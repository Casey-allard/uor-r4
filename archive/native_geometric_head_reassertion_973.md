# Live-head same-value reassertion: the head contract — #973

The second independent review of the [reassertion-versus-truncation repair](native_geometric_reassertion_chain_repair_973.md) confirmed a disclosed, inherited gap: a resident sequence such as `vemqi in moss harbor. vemqi now in pearl meadow. vemqi in pearl meadow.` answered `Unknown.` for an initial or previous request on `90ebd843`, `e44a9ae4` and `e3a906c8`, while the current request answered correctly. Repeating the current fact made the retained history unreadable because the frozen immediate-previous reader takes its first hop only below a revised head, so an assertion head had no historical read at all. This cycle extends the versioned chain contract with a **head contract**, refits the version-intent witness from frozen parent `f0901dad`, and retains **`fc479376`**; `90ebd843` stays preserved as the prior accepted comparison baseline.

## Semantics, defined explicitly

Record-hop semantics are unchanged. The **previous** version of a live head is the head's immediate previous record, whatever its value; when the head is a same-value reassertion, that record is the one the head repeats, so `What was the previous location of vemqi?` answers `pearl meadow`, not `moss harbor`. The **initial** version is the chain's assertion root reached through validated links; depth counts record links, so the root of the sequence above is two links below the head. A previous-distinct-value reading (the last value that differs from the current one) is a different intent that this cycle neither implements nor claims.

The first hop below a live head is valid under the head contract (`reassertion_heads`) when the head is a resident same-value reassertion: an assertion naming a strictly older, nonconflicting, same-owner predecessor whose exact value payload it repeats, re-proven byte for byte. A conflicting head, a foreign-owner or differing-value predecessor, a head that is not in the live directory and a single-record chain still have no first hop. Deeper links follow the existing versioned contract (revisions and interior same-value reassertions), and a chain is truncated only when the record where the walk stopped names a proven-evicted predecessor, now including a reassertion head whose predecessor slot was overwritten. Candidates reached through the head hop carry their own four chain classes (six to nine), and a truncated head chain its own class (ten), so the learned selector, which the frozen parent cannot help on these heads, learns them apart from revised chains; nothing inspects intent words or answer strings. A previous request on a revised head whose previous record was evicted keeps the parent's answer as before; only the head chain's proven eviction is a learned abstention. The field anchor records the head hop (`reassertion_head`) and restores only under the head contract; a `HistoricalVersionIntentReassertionHeadDisabled` control withholds the hop. Legacy artifacts have no flag on the wire and keep their exact behavior.

## Limitations and next implementation

The head contract reads below a same-value reassertion head; a head whose repeated value differs from its predecessor is a conflict and stays unread, as does a single-record chain. The third independent review found that `fc479376` did not cover every valid chain shape: on the smallest repeated-head chain (two identical assertions) the previous request deferred instead of selecting record 1, because the construction never crossed that chain with the previous intent (no learned codes for chain class seven); the [minimal repeated-head record](native_geometric_minimal_head_973.md) repairs that coverage. The same review recorded eight inherited owner-first current-request formatting failures on head chains, kept separate from factual selection. Previous is the head's immediate previous record by record-hop semantics; a previous-distinct-value intent is neither implemented nor claimed. A previous request on a revised head whose previous record was evicted keeps the parent's answer; only a head chain's proven eviction is a learned abstention. Plain-style requests under two phrasings still receive the inherited owner sentence for the same exact record; exact authored text alone is reported separately. Both reviews' prompts are development evidence; only the fresh draw is held out. These are bounded authored forms with fresh spellings, not temporal language understanding.

Next under #973: intermediate-version intent with exact depth labels, so a request for a specific earlier version selects that exact record or abstains when the chain no longer holds it, while preserving initial, previous and current behavior, reassertions and reassertion heads, competing owners, dependency abstention and causal follow-ups.
