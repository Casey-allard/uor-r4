It freezes the previous lexical block and every inherited parameter. Only new tag-18 feature roots are learned in the existing shared signed-H4 lexical router. Current composition retains tag 17, its dictionary, token choices and parameters.

An admitted historical anchor requires the actual historical reader's selected retained source, matching action and exact endpoints, and a unique immediate-predecessor link from a live, nonconflicting current revision with the same owner. The anchor retains the old record identity and an optional `current_revision` proof. Each field read and state update rechecks the link, with validation charged to the work counters. The optional proof is absent from legacy and current-anchor serialization. The runtime implementation is shared with [field_composition.rs](../crates/uor-r4-core/src/native_geometric/field_composition.rs).

[Snapshot restoration](../crates/uor-r4-core/src/native_geometric/field_composition_snapshot.rs) replays the actual source reader and field selector and compares the reconstructed field state. A serialized proof alone does not grant access. `without_historical_field_composition()` restores the parent artifact; `HistoricalFieldCompositionDisabled` provides the corresponding runtime control. The existing context, geometric-transform and field-read controls remain independently available.

Offline Rust supervision supplies typed Owner/Value pieces and literal byte labels to `fit_historical_field_composition()`. Serving receives prompt tokens only and chooses byte, field-read, defer and stop actions geometrically. The new serving path adds no response template, historical phrase parser, transformer, provider, mathematical matrix product or expert network. Its role is to compose fields after source selection. The existing 32-step response-entry limit remains in force; the evaluation harness stops at 96 output tokens.

## Remaining source-selection question

The longer previous-location owner-first failure precedes field composition. In the observed diagnostic, the historical reader defers and the dependent reader supplies a NoRead decision with dependency `[2, 0]`. [role_read::offer](../crates/uor-r4-core/src/native_geometric/role_read.rs) implements that dispatch order.

A source-based hypothesis is limited exposure of the longer query's temporal cue: [historical_read::features](../crates/uor-r4-core/src/native_geometric/historical_read.rs) emits ordered prime features for only the eight most recent captured query words, while [relation::read_features](../crates/uor-r4-core/src/native_geometric/relation.rs) checks owner matches in that same eight-word range and includes neighboring addresses. Appending the owner-first instruction can change which cues enter that view. This has not yet been established as the measured cause. The next diagnostic should capture the actual query words, exposed primes and historical/dependent candidate scores for the short and long requests before selecting a bounded context-binding repair.
