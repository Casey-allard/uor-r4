# Principal engineering review: one native geometric language and memory path

**Status:** independent architecture proposal, 2026-09-24. **Reviewed tree:** `3101c06061726d9438a22649a25b98558525e8d0` in the isolated `kvar-20260924` worktree. ## Executive judgment

The project has several legitimate ingredients but no single trained artifact that combines natural-language understanding, learned addressing and writes, exact versioned memory, context-dependent geometric selection, useful open-vocabulary generation and bounded sparse serving. The strongest current language predictor is an ordinary 64-dimensional integer RNN. Its 64-token independent training windows and dense output scan leave a short memory horizon and weak generation. KVAR establishes that a gated addressed overwrite store can solve a synthetic long-lag task; it does not solve learning a useful address from raw text. The loaded bridge proves exact memory can reach the same lexical decoder through `Copy`; the newest 72-cell gate nearly reproduces a recent exact-pair cache and fails complete continuations. The missing system is the **trained causal information path** from observed text to typed write/query, admitted source, selected value, changed internal state and uncopied output. [Current state](current-state.md), [KVAR result](kvar-recall-result-2026-09-24.md), [bridge result](addressed-lexical-bridge-result-2026-09-24.md), [sparse-read result](native-sparse-read-result-2026-09-24.md).

I recommend **one trainable native geometric-state + exact-memory model spine**, with finite relative transport, a product-geometric address and bounded discrete energy as architectural mechanisms from the first integrated build. Co-design an ordinary sparse address/action arm inside the *same milestone*, with identical admissible information and parameter-access budget. This prevents the requested geometric route from waiting indefinitely behind component repair, while D4 still governs what can be called a demonstrated geometric predictive contribution. Design every trainable stage for D5 sparse *learned-parameter access* now; retain the present dense D0-b RNN as an explicitly non-D5 quality scaffold/comparator, not the target spine. [Decisions D0-b, D4–D6](DECISIONS.md), [adopted direction](direction-decision-2026-09-24.md).

## Where the system is stuck

1. **Information is lost before the head.** Frozen-state adjudication found only +0.022 bits beyond the servable order-two count prior; a more elaborate readout of the unchanged state did not recover a meaningful long-range signal. The old main-artifact state decays from 97.84% previous-token recovery at lag 1 to 0.60% by lag 4. Training windows are independent. [Direction decision](direction-decision-2026-09-24.md), [Part A result](frozen-state-readout-adjudication-result-2026-09-24.md).
2. **Exact storage has no learned semantic ingress.** KVAR's write/read gate works with explicit `BIND`/`QUERY` markers and one-token keys; the language bridge receives the address, history and write permission from the caller. The latest gate has only an exact BPE pair and five coarse metadata classes. None supplies an address learned from roles, entities, discourse or code identifiers with variable context. [KVAR](kvar-recall-result-2026-09-24.md), [bridge source](../../crates/uor-r4-core/src/native_geometric/learner/addressed_lexical_bridge.rs), [sparse source](../../crates/uor-r4-core/src/native_geometric/learner/sparse_native_read.rs).
3. **Source selection is disconnected from general generation.** A selected exact token can bypass the vocabulary head and be emitted as Copy, which tests wiring. It does not demonstrate learned influence on the next **uncopied** token, useful continuation after a copy, or open-ended dialogue/code. A candidate absent from postings, a BPE identity collision, a stale version or an erased lexical distinction cannot be repaired by a better scalar ranker. [Current-state top](current-state.md), [scoped store](../../crates/uor-r4-core/src/native_geometric/learner/scoped_memory.rs).
4. **Arithmetic and traffic are different constraints.** The newest report counts 602,406 packed-code inspections in the vocabulary map and 9,408 in transition maps per NoRead step: **611,814** scanned slots for **153,052** nonzero terms. Selected Copy avoids the head for that step, yet source indexing/lookup, prompt setup, transition and request validation still cost work. The synthetic KVAR base inspects 8,771 slots/token. D0-b's no-float/no-multiply condition is meaningful; D5 also requires that most learned rows remain untouched per token. Neither a 2-bit dense scan nor compiling only nonzero coefficients establishes D5. [Sparse-read result](native-sparse-read-result-2026-09-24.md), [D5](DECISIONS.md).
5. **An evaluation loop can conceal the architecture gap.** Many retained component tests repair exact behavior on authored worlds; that discipline is valuable for regressions. It cannot replace one loaded model that learns from varied raw source, reads/writes causally, generates complete answers and beats a matched ordinary method. The most recent negative already says not to tune the 72-cell gate on its exposed Dev files. [Current state](current-state.md), [project track](project-track.md).
6. **An older public API can misstate the product.** `crates/uor-r4-api/src/native_capability_api.rs:457–477` still labels geometric prose and `>40,000 tokens/sec on Apple Silicon M1` as `QUALIFIED`, although present evidence does not warrant those broad claims. Its temperature sampler at `:1113–1141` uses `f64`, divide and `libm::exp`, violating D0-b when that route is exercised. Repair the selected public API/metadata/sampler boundary as part of wiring the unified model, and prevent the old `.rgm` prose service from silently standing in for the new artifact; this is a truth and serving-contract gate, not a reason for a disconnected wording-only microtask.

## Proposed single model spine and interfaces

This is a **proposed architecture**, not an implemented union of modules. It has one causal training/export/load/serve forward. Keep exact source and version authority outside the low-dimensional latent state, while learning when, where and how to use it.

```text
raw bytes -> pinned tokenizer -> exact causal event tape (source, span, occurrence)
          -> shared low-bit product-geometric state h_t + typed observation
          -> learned {NoWrite, Write, Revise} and semantic key proposal
          -> typed/versioned record ledger + bounded exact and geometric postings
          -> learned product-geometric query -> K admitted records (or NoRead)
          -> exact scope/version/owner eligibility -> degree-2 lane energy
          -> selected source -> finite relative transport + selected operator rows
          -> shared h_(t+1) = sparse state action + gated residual
          -> full-support tree Generate(token) | Copy(owned span) | Stop
          -> actual emitted token + event fed back to the SAME state/ledger
```

**Two distinct write levels.** First, a causal event tape records every observed/emitted token, its immutable source identity, byte/BPE span and occurrence order, subject to a declared retention limit. This capture is deterministic; it is not a successful semantic memory write. Second, the learned controller proposes `NoWrite`, `Write` or `Revise` for a typed proposition/version and a content-geometric code. A semantic record must link back to exact tape occurrence(s), have an injective `(scope, entity, relation)` key, distinct exact lexical value and token payload, commit/predecessor, and explicit valid/absent/no-history/evicted/conflict status. Store only after observing the responsible source span or a committed emitted action. `scoped_memory.rs:1201–1265,1312–1415` is the correctness source; its *semantic* write policy is not proven for raw open text. A hash/prime/geometric code selects a page, then exact identity and version checks verify any hit before copy/update. KVAR's one-hot row can be compacted for synthetic overwrite only; a general span/version event needs ownership and retention accounting.

**Learned ingress and index.** Train a contextual binder and key/query proposer on source spans with role reversal, repeated names, same token in content and cue roles, changed-source and read-disabled controls. It must use observed identity, state and discourse rather than request-provided `BIND`/`QUERY` labels. A proposed product key can combine a learned content code with typed role/relation/scope and finite orientation; exact identity remains in the ledger, not the learned code. Maintain bounded inverted postings for mandatory exact typed keys and a small number `L` of learned geometric buckets per record. Probe only budgeted pages, merge/deduplicate source IDs, then apply scope/version/retention veto and keep at most `K` candidates. This is **not** an all-pairs record graph or a scan over all historical keys. A `NoRead`, miss, forbidden scope and verified eviction remain different model-visible outcomes. Measure correct-record `Recall@K` before energy ranking and confirm the emitted-token action feeds the next state.

**Finite geometry, energy and state.** A product state of small four-coordinate banks carries content, role and signed local orientation. Learned events select finite Q8/2I/H4 actions; serving composes/inverts action IDs by tables and transports only selected vectors by signed permutation/index operations. For each of the at-most-`K` admitted records, form typed relative lane codes `rᵢₗ=(qₗ aₗ)⁻¹gᵢₗ`, where `aₗ` is a causal local frame. A degree-2 discrete energy can sum one-lane terms `wₗ[rᵢₗ]` and a **sparse fixed graph of lane-pair** terms `Jₗₘ[rᵢₗ,rᵢₘ]`, plus typed/status bias. “Degree two” refers to factors over at most two discrete lane variables, **not** a quadratic polynomial in real quaternion coordinates or all-pairs interactions between records. Evaluate only admitted records, a bounded number of lanes and selected factor rows; no `W²` event graph or `K²` candidate-edge scan belongs in this first model. The selected event transports a typed value into a few shared low-bit operator rows updating the **same** state used by ordinary language generation. This is deterministic sparse parameter routing from learned codes and a shared operator bank, not an MoE expert gate or a per-record expert network. A finite group element itself is not continuous Hamiltonian flow or semantic metric. `hamilton_transport.rs` supplies Q8 action; `group_table.rs` supplies a larger finite table. Ordinary sparse bucket/action and finite-sign controls are developed concurrently at equal information, capacity, candidate set and parameter accesses; D4 governs eventual claim promotion. A common rotation of query and keys alone preserves inner products, so relative/task-conditioned action needs causal evidence.

**Output and D5.** A full 4,098-row linear readout forces an all-vocabulary parameter scan on NoRead steps. Train a hierarchical **full-support** distribution over legal modes `Generate`, `Copy` and `Stop`; within `Generate`, score root groups and then leaves or deeper branches. For `V=4,096`, width 64 and a balanced 64×64 factorization, scoring all 64 roots and all 64 leaves *in the sampled root* touches `64·64 + 64·64 = 8,192` low-bit coefficient positions versus the present flat head's `4,098·147 = 602,406` positions. A tree of bounded branching can touch fewer rows. These are **access calculations**, not measured speed, energy or quality. Exact teacher-forced `log P(v)` sums the legal mode, true-token root and true-token leaf conditional log probabilities, with each scored sibling set normalized; every vocabulary token needs nonzero support. Exact ancestral generation samples the mode, then a root, then a leaf from those normalized conditionals. Greedy root then greedy leaf is not generally the global MAP token; exact MAP would compare all root/leaf products and lose the sparse head benefit, while a declared bounded beam is approximate and charged. `Copy` must normalize over eligible owned occurrences and map its token/path probability without double counting when comparing lexical likelihood. The hierarchy must be co-trained; a top-`K` shortlist without outside mass is not comparable NLL. Selected shared operator rows must similarly replace dense always-scanned recurrence in the target path. Instrument learned router, embedding, state action, candidate, output and external-memory reads separately.

**Fit/export/load/serve as one model.** The Rust trainer must run the entire hard causal forward on episodes: tokenize, deterministic event capture, learned semantic write/key, bounded hard index admission, degree-2 energy, selected shared operator transition, and exact tree/mode likelihood. Use offline float/matmul and surrogates or contrastive credit for hard routing, but train with joint next-token/Copy/Stop losses and source-grounded write/read targets; maintain hard-forward validation during fit. Training-only positive-source insertion or wider retrieval may diagnose missed admission but never enters serving acceptance. Gradients/credit must reach binder, product key/query, energy, operator selector, state and tree; a frozen RNN with a side cache would not test this model. The control arms share splits and losses and differ only in registered ordinary/geometric modules.

One versioned native bundle should bind tokenizer, training-data split digests, source/format, low-bit parameter and codebook bytes, finite geometry table identity, typed key/version schema, output tree, scales, limits and an operation-access manifest. A single `fit -> export -> reload -> generate` entry point must explicitly select this bundle; an old `.rgm` or lexical artifact must fail model-kind dispatch rather than silently satisfy the new command/API. Export/reload and separate-process parity compare state, writes, postings, candidate IDs, read statuses, token probabilities/actions and emitted bytes. Construction may allocate; steady serving uses caller-owned scratch and bounded retention. Audit the actual selected serving symbols, including API sampling, for float, divide and multiply under D0-b. The `tl_execution.rs` scratch/low-bit compiler and graph-format/replayer patterns are donors, not a ready compiler for this spine.

**Code ownership and migration seam.** Reuse `native_geometric/learner/scoped_memory.rs` as the exact typed/version semantic authority, `memory_runtime.rs` for ring/provenance invariants, `transferable_lexical.rs` for shared legal actions and feedback, `tl_execution.rs` for caller-owned scratch/parity, `hamilton_transport.rs` and `group_table.rs` for finite actions, `geometric_attention.rs` for ordered-address lessons, `jepa_trainer.rs` for Rust tokenizer/data/export plumbing, and dormant `graph-runtime/src/route_attention.rs` for bounded top-M/census patterns. Implement new event-tape/retention and stable occurrence-ID format, learned binder and product key/query, bounded dual-posting index, degree-2 energy scorer, sparse selected-row transition, full-support tree/mode head, joint Rust training/export format and explicit API model-kind/sampler dispatch. `sparse_native_read.rs` is a negative diagnostic/control, not the new controller. Each replacement module needs a clear versioned interface; importing the old generator, scalar gate, prime ID distance or float delta cell wholesale would recreate known gaps.

**Prospective access and memory ledger.** Define `P` as all learned parameter bytes, `N` retained raw events, `W` retained semantic records, `L` bounded learned postings per record, `K` admitted records, `F` active single-lane and lane-pair factors, `B` four-coordinate state banks and `V` vocabulary. Per token, record *actual bytes read*, not only arithmetic: `A_learned = A_embed + A_write/query + A_page_codes + K·F·A_factor_cell + A_selected_state_rows + A_mode + A_tree_path`; separately report `A_data = A_event_append + A_index_probe + K·A_record_header + A_selected_payload + A_copy`. A degree-2 *lane* graph costs `O(KF)` selected factor accesses, while query/key computation, posting traversal and overflow checks are charged separately. Working state minimum is `4·B·s` bytes for `s` bytes/coordinate, plus selected-row/candidate/tree scratch and source-cursor metadata; real peak RSS includes allocator/index/tokenizer overhead. A bounded raw tape with average `m_e` metadata and `p_e` owned payload bytes costs `N(m_e+p_e)`; semantic record headers cost `Wm_s`, learned posting IDs at least `O(WL)` bytes, and exact typed/version indexes plus hash-table slack add more. This is a capacity *formula*, not an upper RSS bound. A raw tape can preserve exact data but does not guarantee constant-cost arbitrary retrieval: a bounded learned index can miss, exact postings require a known typed key, and page overflow must either spend additional bounded probes, evict with a visible status, or return `unavailable`. A full scan restores findability for retained records only at `O(N)` access and would break the sparse serving budget. On artifact/codebook update, product keys drift: keep sessions pinned to the old model/index or rebuild every learned posting from the exact tape/semantic records under the new codebook, with versioned index digest and atomic switch. Do not reinterpret old bucket IDs under new weights.

For an initial **engineering envelope**, investigate `B=16–32`, `K=16` in a small pilot and at least a measured `K=64` stress condition, `L≤4` learned postings per semantic record, and a `V≈4,096` tree. At two bytes/coordinate, the raw state for `B=16–32` is `128–256` bytes; at four bytes it is `256–512` bytes. A larger illustrative case with `N=65,536` and a 192-byte *header/retention allowance* costs `12 MiB` before raw payload, exact and learned indexes, table slack, sessions and snapshots. If `K=64`, 16 one-lane terms and 16 sparse lane-pair terms each require two selected cell reads, the energy stage alone reaches `64·(16+16)·2 = 4,096` cell reads/token before router/state/head or cache effects. The proposed 64×64 output head inspects 8,192 coefficients per Generate step. Plan one active session at `N≤8,192` for the first fit/load loop, then a declared `N=65,536` retention stress; a provisional host target is ≤512 MiB peak process RSS and ≤100 ms median decode/token at pilot capacity, with the exact machine, prompt length, quality and power recorded. This target is a planning limit, not an observed capability or scaling extrapolation; failure prompts capacity/index redesign, not a false speed claim. Set D5 design caps for each module in absolute bytes and fraction of `P` before fit; tune the numerical caps from a pilot trace and the quality needed for a useful model, then freeze them before held-out evaluation. Reserve cumulative local time/storage from the live ledger. These figures are targets/illustrations, **not** throughput or power claims.

**Cross-review against the mathematics and CS proposals.** The [mathematics construction](principal-attention-mathematics-2026-09-24.md) defines degree two over active relative-code *lanes* inside each candidate; the [CS review](principal-attention-computer-science-2026-09-24.md) requires the learned address to precede scalar rank and the output to remain normalized. Those constraints are compatible with this engineering spine. Three implementation traps remain. First, "append-only" means immutable records **within the configured retained window**; a bounded M1 store must expose eviction and cannot promise all-history access. At 32 active sessions, the illustrative 12 MiB header allowance alone would be 384 MiB before payload and indexes, so actual concurrency/capacity must be set from machine RSS rather than copied from today's API `max_sessions=32`. Second, semantic write decisions are model outputs, while raw source capture is deterministic: replaying the tape after an artifact update may produce different semantic assertions or versions. Treat that as a versioned migration with an audited diff or keep the prior session/artifact pinned; merely recomputing geometric bucket codes does not preserve meaning. Third, fixed-cap posting lists can silently erase a live relevant source. Overflow must be observable and its choice—extra bounded probe, verified eviction, or explicit unavailable—must be trained/evaluated; exact typed identity checking after retrieval protects soundness, not `Recall@K` completeness. Rebuild/migration costs are `O(N)` or greater and belong in startup/update accounting, even if decode touches only sparse rows.

## Falsifiable integrated milestone, then scale

**M1: one learned raw-text geometric memory-language artifact.** Build ordinary and geometric sparse modules in the same integrated train/export/serve milestone; test both end-to-end at the same information and parameter-access budget. Freeze source-disjoint prose and Rust/code-identifier episodes requiring distant rebinding or role-dependent lookup at lags 32–512, and verify a tuned order-two count control is at chance where claimed. Include natural-text companions, negative/missing/conflict/scope/version cases and exact spans across BPE boundaries. Compare NoRead, recent exact cache, equal-work stateful n-gram, ordinary learned sparse router/action, finite-sign geometric control and product-geometric relative energy/transport; the existing dense D0-b RNN remains a quality scaffold clearly outside terminal D5. Evaluate full-support teacher-forced loss and actual loaded complete prose, memory and code outputs from **one artifact**. Source-only edits should change the right answer and at least one later uncopied token while fixed-flags NoRead does not. Judge grounded meaning with legitimate alternative phrasings and independent source facts; do not make exact next-eight-token match the whole-program prose metric. The latest `0/8` is a valid narrow retained negative, not a general semantic score. A Rust code claim needs held-out parse/compile/execution tests. Predeclare effect/uncertainty thresholds before a fresh draw, and retain earlier memory/lexical controls. [D6](DECISIONS.md), [latest negative](native-sparse-read-result-2026-09-24.md).

**Convergence rules:** Component diagnostics are allowed only to unblock the shared artifact. Low candidate recall points to observed-role/key/admission training; correct admission with wrong selected source points to energy; an oracle read that leaves later uncopied language unchanged points to state/output credit; a source-edit effect only under teacher forcing points to rollout/export mismatch. Stop the integration branch and revise data/objective/architecture if both ordinary and geometric arms fail source-disjoint complete tasks despite sufficient source admission. If geometry ties a useful ordinary arm at matched cost, retain the ordinary result and withhold a *geometry advantage* claim at this scope; it does not ban further geometric development. Do not make a new local fixture or larger H4/S7/E8/harmonic bank the next milestone without an integrated failure diagnosis. Preserve all negative candidates.

**M2: capability expansion.** Once M1 passes as a whole path, train broader diversified dialogue, document memory and Rust coding on the same spine with cross-window state and exact source provenance. Track long-range retrieval, factual correction, source interventions, abstention, general prose loss/coherence, completed interactions and executed code alongside held-out loss. Do not promote a model on unique reference strings where multiple correct answers exist. The historic locally served models have limited data/context/capacity; frontier replacement is a later scale question, not a property of a finite group. A prior [geometric-core architecture](geometric-core-architecture-2026-09-19.md) estimate put chat-scale learning at far more tokens/compute than one M1 run; measure this spine's fit throughput and scaling curve before setting capacity or promising frontier parity.

**M3: hardware and replacement qualification.** D5 has constrained the architecture and traces since M1; this stage asks whether it works well enough on hardware and against useful baselines, not whether to retrofit sparsity. Measure on the named M1-class host: resident model/index/tokenizer and peak/steady RSS; prefill versus decode; tokenization, admission, read, state update, output and session costs; cold/warm cache; bounded source capacity; long actual-generation traces and complete useful tasks; physically measured package power and joules/task. Compare quality on matching tasks or chart the gap against current [llama.cpp benchmark tooling](https://github.com/ggml-org/llama.cpp/blob/master/tools/llama-bench/README.md), [bitnet.cpp](https://github.com/microsoft/BitNet) and [T-MAC](https://github.com/microsoft/T-MAC). Their reported speed elsewhere is not UOR-R4's M1 result. [Product Keys](https://arxiv.org/abs/1907.05242) is sparse-access precedent, not proof of a no-transformer implementation. The current tiny artifact may fit cache while being far too weak for a capability comparison; a future sparse model's latency depends on index misses and touched bytes as well as total parameter size.

## Decision status and uncertainty

This report's architecture is **proposed**, not owner-adopted or experimentally supported end to end. The adopted [canonical milestones](project-track.md) and D0-b/D4–D6 remain authority. The KVAR memory result, exact scoped-store semantics, loaded bridge and newest failed gate are distinct verified components.
