## Design and independently testable deliverables
1. `language_transport.rs`: learn an integer text-feature-to-Q8-operation map from selected-key supervision, not relation IDs at inference. Operate on supplied typed query/key vectors; filter owner IDs exactly and reject ambiguous/absent sources. Compare equivalent explicit signed-permutation execution, disabled transport and shuffled text. The test is bounded typed language retrieval, not universal natural-language interpretation or geometric superiority.
2. `tl_execution.rs`: compile all four native ternary maps once, precompute request-dependent event offsets and use caller-owned state/scratch/output arrays. Prepare evidence and typed facts without allocating; preserve every score, action, payload token and final state across native/compiled paths. Trace allocations around complete pretokenized preparation plus generation. Do not silently change legacy defaults.
3. A runner integrates learned source selection and native Generate/Copy/Stop on new values/spans. Train response syntax, not a renderer: all output tokens must be emitted by the loaded model or copied from selected owned payloads. Rust evaluation compiles the exact generated bytes, runs safe bounded programs only, and compares actual stdout. No wrapper or repair counts as success.
4. Mixed fitting reuses pinned repository/broader-source data with new finite instruction and span-intervention supervision. Fit values and templates, exposed validation values and fresh final values are distinct. Keep historical grounding/feedback regression panels, multi-token crossed controls and all failed candidates. New exposure does not become a general-language claim.
5. Define a new checkpoint-bound optimization phase. Compare continuing old moments with resetting moments from the identical served parent, at equal data/schedule; serialize cursor, data/source identity and validation state. Reproduce an actual interrupted run across a fresh process. Preserve old exact replay semantics and source bindings.

## Experimental constraints
Rust implements preparation/model/fitting/inference; Python/shell only orchestration, independent analysis and compiler checks. Two threads, 2GiB model RAM, 4GiB compiler RAM, 2GiB new storage and 90-minute complete-session projection recorded before use. Existing isolated worktree reused; target about50GB physical free. No paid external compute or destructive unique-data cleanup.

Training: predeclare a bounded mixed schedule before fitting; current parent is the retained causal artifact, with optimizer continuation from its verified final checkpoint. Candidate choice uses finite exposed instruction validation plus historical preservation, never final-source results. New geometry selects exact payloads but does not supply expected response words. Broad source prediction and open-ended generation remain separate measurements.

Review risks: absent owner must not fall back to another payload; equal-distance source ambiguity is an error; no checkpoint may silently reset moments or schedule; Stop terminates before state update; disabled Copy must remain illegal; signed central quaternion orientation is retained; invalid buffers/overflow return errors; serving speed requires exact output parity. Local tests, source/manifest hashes, generated failures and owner-file preservation precede protected delivery.

## Research basis
Parcollet et al., *Quaternion Recurrent Neural Networks* (arXiv:1806.04418), supports structured Hamilton parameter sharing, not an integer-serving guarantee. Yang et al., *Gated Delta Networks* (arXiv:2412.06464), distinguishes targeted memory updates and adaptive erasure; its dense/GPU implementation is not adopted. Here the proposed use is learned relative addressing of separately retained payloads, with categorical-equivalent controls and no imported capability claims.
