## Main finding

The repository already has most of the *types of primitive* needed for geometric attention: exact occurrence identity, ordered prime routes, fixed zeta coordinates, exact finite H4 transport, orientation-sensitive observations, hard geometric retrieval, payload leases, compositional operators, and learned finite decision tables. It does not yet establish a trainable complete route from language context through these primitives to useful generated prose. Adding more mathematical names, coordinates, or expert labels will not by itself complete that route.

The strongest immediate architecture synthesis is exact addressed memory plus finite geometric transport plus a context-sufficient learned nonlinear operator. “Context-sufficient” is concrete here: each decision must be able to use the distinctions required by its target, either directly or through an explicitly adequate shared state. Current Hamming-policy wiring guarantees coverage across the union of outputs, but provides each token score with only a small fixed subset of the packed inputs. That is a mechanism worth analyzing before scaling the same training recipe. The result is a limitation of this circuit layout, not a disproof of Hamming geometry or geometric language models.

A coherent implementation has four separate obligations:

1. **Identity and memory:** preserve the exact ordered record and its version/occurrence; never substitute a prime or content hash distance for semantic relatedness.
2. **Geometric computation:** transform query, retained state, and record keys with typed finite operations whose invariants are known.
3. **Learned use:** train query/key/state/operation/emission decisions so the actual selected record changes later prediction usefully.
4. **Credit and qualification:** give changed hard selections credit for their causal downstream effect, then test deterministic generated behavior and retained controls. A finite table that can represent a function is not evidence that a given training process learned it.

## Current policy: what is actually geometric, and what is restrictive

The actual Hamming metric is over artifact-bound hemisphere predicates of 120 H4 roots. Root distance is XOR/popcount over the two words of a 120-bit signature; two-lane distance adds the two root distances. This is geometry-derived Hamming distance, not distance between cryptographic addresses. The code explicitly says the two contextual lanes are not a paired-H4 lift. [Metric implementation](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_refinement/metric.rs#L1)

The current-state record reports 120 distinct signatures and exhaustive agreement with signed angular *single-root* ranking over 856,800 query/candidate-pair comparisons. It explicitly does not establish equivalence of sums over two lanes, softmax attention, or learned semantic similarity. Those are different propositions. The same state record reports that initialized full-path conformance passed while language remains unqualified: 0/24 authored answers, 1/460 teacher-forced symbols, no EOS in the sampled 64-symbol generations, and all 1,536 Full generation steps had a maximum-score tie. These are archived reports, not runs performed for this review. [Current state](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/docs/integration/current-state.md#L5)

Hard retrieval scans up to 256 occurrences and eight results, plus Null, per hop. It compares keys before gathering payload. Strict improvement over Null is required; ties retain the earlier winner. Selected exact identities and payload leases remain distinct from geometric keys. Two records with identical keys are therefore distinguishable by identity in storage but not by their metric score at that query. The lexical payload is available after selection; a later query can use it, but the first read cannot score an unread payload by magic. [Selection loop](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_refinement/runtime.rs#L210)

The shared Boolean policy has 4,096 input ports, layer widths 1,024 → 256 → 1,796, 3,076 LUT4 gates, and 49,216 truth-table bits. Its inputs include current/initial H4 signatures, selected and previous lease roots, two 64-byte payloads, presence masks, keys, phase, position, zeta bins, and active-output state. Exact occurrence addresses are deliberately excluded from learned score inputs. [Parameters and topology](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy.rs#L11), [packing](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy.rs#L245)

**Derived receptive-field result:** the first two layers partition their inputs; final-layer wiring selects four second-layer outputs. Consequently one final output bit sees at most 4³ = 64 of the 4,096 input ports in one invocation. Four adjacent bits form one token score, so that score sees at most 256 ports. Final wiring repeats every 64 output gates; token scores 16 indices apart have the same 256-port structural input set, with different learned truth tables. Comparing two scores can involve the union of their subsets, at most 512 ports. The whole 257-score vector and the geometric outputs can collectively depend on all ports. Recurrence, hard retrieval, and root quantization can mediate information between invocations. Therefore this is a structural locality restriction, not a proof of total model incapacity. [Exact wiring](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy.rs#L81), [score assembly](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy.rs#L418)

The coverage test checks the union of reachable inputs across the geometric-output range and across the emission-output range. It does not check full context access for every symbol score, required symbol-pair comparison, or operation decision. Those are materially different guarantees. [Coverage test](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy_tests.rs#L42)

Each emission, extent, and control score is an unsigned four-bit integer, 0–15. Argmax uses strict improvement and therefore picks the lowest legal index on a tie; EOS is index 256. The current initialized EOS failure has this specific structural context, although a trained table could learn an EOS margin. Root outputs are snapped to one of 120 valid signatures. Four roots have at most log₂(120⁴) ≈ 27.63 bits of state identity, not 480 independent bits because their signatures occupy 480 ports. Redundant signature bits can ease Boolean computation but do not add state cardinality. [Decision and argmax](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy.rs#L164), [root snapping](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/policy.rs#L418)

The present credit helper evaluates finite parameter contrasts. Its header explicitly does not claim a derivative, unbiased gradient, or fitted optimizer. It computes offline softmax cross entropy of the integer scores; serving selects hard argmax. Thus the absence of runtime softmax does not prevent a probabilistic training objective, and the existence of that objective does not solve credit assignment to every hard internal decision. [Credit helper](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/credit.rs#L1)

The session carries genuine state and exact acknowledgments, but this integration refreshes its object snapshot through serialization/import after observed bytes. It is bounded code, not yet an allocation-free production kernel. Keep these claims separate from the stricter frozen R4G1 runtime. [Session update](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/session.rs#L220), [snapshot refresh](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/hamming_policy/session.rs#L157)

### Prime order, factors, and semiprimes

`OrderedPrimeRoute` retains both the ordered sequence and factor multiset. The tests distinguish reordered n-lets by their ordered κ even when factors are identical, and preserve a factor vector when a diagnostic product overflows. This is the correct separation: arithmetic product/factor overlap supports unordered structural questions, while order requires its own representation. [Route source](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/prime_route_attention.rs#L266), [test assertions](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/tests/prime_route_attention_958.rs#L289)

`SemiprimeExpert` sorts two validated factors, computes their u64 product, and finds a unique prime handoff by gcd. Equal experts and disjoint experts return no unique prime handoff. This is a precise routing combinator; the type does not contain a trained expert model. Six primes yield 15 distinct unordered non-self pairs. With m primes the distinct-pair count grows as m(m−1)/2; permitting self-pairs adds m. Directed operations need a separate direction tag or ordered pair because multiplication commutes. [Semiprime implementation](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/prime_route_attention.rs#L225)

More primes can expand the registry and reduce overloaded identity assignments. They do not automatically create discriminative keys or useful specialist behavior. A proposal to use semiprime experts must specify each expert's actual shared operator parameters, legal input/output type, routing cost, and training credit. Expert gates remain a conditional future option under the canonical policy, not a free consequence of the prime vocabulary.

### Zeta channels and state transport

The canonical native geometry compiles eight phase channels from prime identities and fixed zeros. The current addressed/Hamming route uses four phase bins in the packed policy state. BOS/EOS occupy reserved token identities; bytes must use the existing byte offset rather than redefining a 256-entry registry. The 512-zero constant table and its bitwise binding are a coordinate convention independent of proving classical RH. [Native geometry preparation](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/training.rs#L108), [fixed-grid identity and phase deltas](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/prime_route_attention.rs#L885)

The inspected phase test checks exact fixed-grid identity, rejects channel 512, bounds quantized forward/reverse phase error, and demonstrates that distinct antipodal S3 states can have equal Hopf observations. A common fiber rotation preserves the observation in the authored example. Retaining the full S3 or explicit fiber prevents pretending that S2 contains the missing information. [Zeta/Hopf test](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/tests/prime_route_attention_958.rs#L415), [SpinTorsionState](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/prime_route_attention.rs#L633)

**Architecture deduction:** adding Q phase channels costs O(PQ) preparation/storage for P registered atoms and at least O(Q) state/observation work when all channels are used. Wrapped additive phase accumulation is commutative; additional channels do not by themselves preserve sequence order. Exact occurrences, ordered n-lets, or noncommuting transport must carry order. More channels may help distinguish a demonstrated collision, but no inspected test shows that more zeros produce useful prose or solve the current output tie/locality problem.

### Exact H4, paired coordinates, polarity

The canonical compiler and native anchors bind exact Z[φ] root coefficients, product tables, Galois/companion maps, and inverse witnesses. Z[φ] multiplication uses φ²=φ+1; Galois conjugation maps a+bφ to (a+b)−bφ. The paired construction is the project's specific golden-coupled H4⊕φH4 shorthand, not an arbitrary pair of independent learned roots. [Exact coefficient operations](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/prime_route_attention.rs#L381), [paired profile](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/canonical_lexical_ingestion.rs#L2533), [native anchors](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/anchors.rs#L1)

Therefore a proposed learned radial magnitude requires an actual additional state variable and bounded operations, not a reinterpretation of a constant root norm. [Anchor tests](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/native_geometric/anchors.rs#L183)

### The owner's √2 / 2i / [0,2] bridge

The repository gives a typed interpretation, not a literal numeric equality. ADR-0003 states

`d_chord = 2 sin(d_geodesic / 2)`.

For the unit sphere, geodesic distance lies in [0,π] and normalized chord distance in [0,2]. Orthogonal unit points have chord length √2. The complex difference i−(−i)=2i is oriented and has norm 2; it corresponds to antipodal, not orthogonal, separation in that common normalization. The expression [0,2] is an interval/range in the cited distance metadata, not necessarily a vector with coordinates (0,2). A vector (0,2) is another valid representation of 2i in R² only after declaring that different type. [ADR-0003 bridge](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/docs/adr/0003-fixed-zeta-prime-route-attention.md#L228)

ADR-0004 requires chart identifiers, units, orientation, quantization error, and tie rules. The compiler metadata repeats the √2/2i/[0,2] anchors and a normalized chord interpretation. These facts support a conversion contract, but do not prove every proposed discrete/continuous adapter has been implemented or is information-preserving. [ADR-0004](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/docs/adr/0004-geometric-intelligence-route-hierarchy.md#L142), [compiler profile](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/canonical_lexical_ingestion.rs#L2075)

A useful implementation route is to precompute the finite chart conversions between already bounded states, preserve orientation/fiber separately, and test round trips against the declared quotient and quantization. A scalar chord distance cannot recover orientation, source identity, or a Hopf fiber. Domain conversion cannot restore information that its input representation has discarded.

## Cayley-Dickson and Clifford: discriminate between implementations

The small `cayley_dickson.rs` module hashes a token into 16 coordinates and uses cyclic offset arithmetic for named Lie and Jordan operations. Those formulas are not a full Cayley-Dickson multiplication table or a demonstrated Clifford product. Its zero vector called `identity` is not the multiplicative identity of those advertised unital algebras. This module may be a deterministic feature prototype; its names should not serve as evidence of algebraic completeness. [Entire small module](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/cayley_dickson.rs#L1)

The older transformerless `cd_space` actually implements octonion Fano multiplication, quaternion Hamilton multiplication, and complex multiplication in floating coordinates. Its 16-component storage is a direct collection of 8+4+2+1+1 components, not automatically the 16-dimensional Cayley-Dickson algebra. `endomorphism` executes floating M16 matrix products and matrix-vector application, which cannot be carried into no-matmul serving unchanged. [Domains](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/transformerless/cd_space.rs#L1), [matrix path](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/transformerless/endomorphism.rs#L1)

**Derived correctness problem:** the legacy `left_octonion` embeds the active 8×8 left action and appends an identity spectator block on the lower eight dimensions. `clifford_generator` then calls this embedding. On the spectator block, γᵢ²=+I rather than −I and γᵢγⱼ+γⱼγᵢ=2I rather than zero for i≠j. Thus the advertised full 16-dimensional Cl(0,6) generator relation is false for that embedding; the valid active eight-dimensional action must be treated separately. Its volume element is hardcoded as the seventh left action, rather than deriving the full embedded six-generator product. This is a mathematical deduction from source, not a newly executed test failure. [Embedding](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/transformerless/endomorphism.rs#L133), [generator/volume](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/transformerless/endomorphism.rs#L205)

The legacy Lie/Jordan continuous implementation does real transpose-based symmetric/skew decomposition and matrix multiplication. Its discrete branch uses bitwise formulas. No inspected witness proves these two products conjugate under a declared domain map. The Bott/Fock module is a bounded saturating, decaying rotate/XOR recurrence; its suggestive name does not establish Bott periodicity or a faithful Fock-space tensor computation. [Lie/Jordan](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/transformerless/lie_jordan.rs#L1), [recurrence](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/transformerless/bott_fock.rs#L1)

The newer `spiralcore_operator` is a much stronger finite building block: exact eight-dimensional signed permutations, the specified Fano orientation, six left/right generators, fifteen bivectors, and a 64-state group lowered to composition and inverse tables. Its inspected tests check the relevant anti-commutators, orientation/volume signs, bivector order, and malformed prime bindings. Runtime group composition can be one bounded lookup after compilation; it does not require executing the source matrix arithmetic. The implementation itself marks semantic advantage pending and cross-chart transport not established. [Finite operator](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/spiralcore_operator.rs#L1), [lowering](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/spiralcore_operator.rs#L379), [exact algebra assertions](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/tests/spiralcore_operator_958.rs#L38)

This operator is reusable for a defined finite noncommuting action, not an immediate replacement language model. Before combining it with H4, specify the action on actual model state and memory keys, whether the map is injective or a quotient, its inverse/ambiguities, and what training signal makes that action useful. The latest supplied SpiralCore material is reviewed by the parent separately; this section concerns pinned repository source.

## Spectral, harmonic, calculus, and topological material

`zeta_projection` builds floating complex windows, orthogonalizes them, projects state through matrix/vector contractions, computes coefficient covariance/eigenvalues, and chooses a window by a biased score. Its projected output uses coefficient magnitudes, discarding phase/sign there. These are inspectable offline reference calculations, not operations already compatible with geometric-only serving. A finite action learned or selected offline could be compiled, but a lookup implementation of the same dense contraction remains outside the serving boundary. [Projection](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/zeta_projection.rs#L104), [contractions](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/zeta_projection.rs#L196), [window output](https://github.com/UOR-Foundation/uor-r4/blob/b267cfd2d958a76099cc8792e11c777c031895a0/crates/uor-r4-core/src/zeta_projection.rs#L329)

## UOR, Prism, NEMESIS, and W33

The inspected `uor-addr` G2 canonicalizer sorts two complete digest byte strings; F4 identifies a digest with its bitwise complement; E6 partitions by the first byte modulo nine. These are explicit identity quotients/partitions. They do not, merely through their algebraic names, implement ordered semantic composition or exceptional Lie-group dynamics. ## All-pairs relational state and practical synthesis

For group states g₁…gₙ, relative elements rᵢⱼ=gᵢ⁻¹gⱼ can be computed with the existing inverse/product tables. This is permitted finite algebra, not a vector-weighted contraction.
