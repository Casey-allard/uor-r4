* **The training loop does not exist.** `LowBitCore::float_forward_ste` gives the forward shape, but
  the backward pass, straight-through estimator, BPTT and Adam are **not written**. Until they are,
  the core computes but cannot learn — it will emit meaningless logits from random ternary weights.

## 6. Traps that cost this session the most time

**On measurement**
* **A source-level count of multiplying operators is not evidence about multiplier circuits.** Four
  instruments disagreed — raw grep 82, `forbidden_arith` 43, token classifier 216, static binary
  3,100 instructions. Only the last was called authoritative and it was wrong too: a static count is
  not an executed count. Use `scripts/serving_multiplier_check.py`, a **per-function zero-check** —
  "no multiply mnemonic in this function's address range" is a *sufficient* condition and is
  indifferent to dead code, inlining and compiler strength reduction.
* **The scanner's arithmetic scan covers a named sublist, not the kernel region.** `hopf_metric.rs`
  held 82 raw `*` while a test asserted only that certain function names appear once. Extend the
  coverage rather than trusting the existing pass.
* **Apple Silicon has no architectural multiply event.** A hardware multiply count does not exist;
  `xctrace` is not installed and `frida` is not present. Do not propose a dynamic counter again
  without checking first.
* `powermetrics` on this machine reports `CPU Power: 0 mW` under load while the CPU is demonstrably
  busy, so `Combined Power` is GPU-only. Any J/token from it is ~1000× too low.

**On process**
* **Never use an anchor as replacement text — insert *before* it.** This destroyed a section heading
  twice (`D1` in `DECISIONS.md`, and a `EVIDENCE.md` table row twice).
* **Verify before claiming.** Three bugs shipped into a 180-line script (`--command` vs `--`;
  a token regex requiring `]` after "tokens"; mixed power fields), each caught by running the thing
  rather than by reading it. Testing the failure path is what found them.
* **Do not upgrade a number's meaning.** "17× faster" from the incumbent comparison is at
  **unequal quality** and must carry that clause. Energy at unequal quality is not evidence for the
  project's premise.
* **Beware my own summaries.** The statement that the VSA layer was "29 % of serving multiplies"
  came from a static instruction count and was wrong as a claim about serving — those multiplies are
  on an on-demand path the materialised codebook never takes. Prefer the receipts and the
  reproducible commands over any prose in these documents, including this one.
