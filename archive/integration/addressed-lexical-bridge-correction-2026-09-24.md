# Addressed lexical bridge — prospective correction after first exposed run

The original [pre-registration](addressed-lexical-bridge-plan-2026-09-24.md) and its two value pairs remain frozen. `final1` and its independent `replay1` are sealed and preserved. Their loaded rows show copied value changes and exact child replay, but the original **parent receipt incorrectly set `independent_reload_equal=true` before replay ran**. More importantly, absent, evicted and read-disabled addressed requests let the ordinary lexical model continue with no source, producing ungrounded strings. That is an unacceptable grounded-answer interface even though Copy was illegal. Neither defect changes a fitted parameter or the observed positive copied rows.

The corrected attempt uses the **same artifact, tokenizer, writes, addresses, pair values and eight-step bound**. The bridge now returns a typed `Disabled`, `Absent`, `NoHistory` or `Evicted` with **no grounded tokens or actions** unless an exact record was found; ordinary prose continuation remains a separately measured path. Native/compiled parity is checked only for actual `Found` generation. The parent corrected receipt marks independent replay `null` and decision `PENDING_INDEPENDENT_REPLAY`; a separate-process replay over the sealed parent panel may mark equality true and qualify the final gate. The corrected run/replay use new exclusive roots `final2`/`replay2`. The first roots remain visible as an instrument/safety negative, not retroactively relabeled.

No new value pair, learner fit or threshold is selected after seeing `final1`. Passing would establish explicit-address copied-source causality and safe typed abstention on this familiar-token panel only. Raw request parsing, learned writer/reader policy, content-dependent uncopied words, general prose and energy remain untested.

**Additional interface controls before the authoritative rerun.** `final2` and `replay2` are sealed and exact on their 20 rows. They verify absent and evicted abstention but do not directly exercise the `NoHistory` branch or an identical entity under a different scope. The authoritative `final3`/`replay3` adds only those two typed negative rows per case (24 total), records the exact query scope/entity in every row, and requires both to return no record and no grounded output. The values, source substitutions, model, tokenizer, learner weights and positive decision criterion stay fixed. All prior roots remain retained.

**Serialization-use correction before final4.** The `final3`/`replay3` 24-row controls agree, but review found that `Memory::from_bytes` was checked and its returned value discarded before `evaluate`; generation used the in-memory panel object (which the child loaded from sealed JSON). That supports a JSON panel reload claim but not the stronger claim that actual generation consumes the memory binary round-trip. The runner now decodes each case's five `Memory::to_bytes` images with `Memory::from_bytes` and passes those decoded stores into every row. The 24-row panel, pairs, flags, model, tokenizer, weights, thresholds and bridge are fixed. `final4`/`replay4` will be the authoritative sealed pair; all previous roots remain preserved.
