## Mechanism and matched conditions

Each Source segment receives a cue only from its immediately preceding nonempty Context segment. The query is encoded alone from identity. Both observed endpoints must be present. The directed table addresses `inverse(query) * cue` in signed H4; the capacity-matched control addresses the cue root alone, while executing the same relative calculation and using the same carrier information, presence masks, learned capacity and access. Each has 960 quarter-nat Q4 coefficients, 480 packed bytes and 3,840 expanded table bytes. Carrier encoding still reads the existing context tables: the small cue payload does not make the complete model equally small or cheap. Radius, raw roots and retained latent states remain in the sidecar but are unused by this version.

The bonus is added to every occurrence of a Source before the existing global Copy/Period/Stop alias normalization. It is uniform within that Source and stable across generated prefixes. No metadata-role selection, answer slot, target-based candidate filter, record normalization, controller suppression or query reset is introduced. Uncued single-source controls have exactly zero cue contribution. Source labels remain outside native inputs and enter only the final ordinary token loss and membership scorer.

Both arms train 64 balanced B8 updates on the unchanged 128 development cases: four singles plus four bank episodes per update, preserving two intact bank query pairs and four visits per episode. The selector uses all 1,204 canonical targets, mean token CE within each episode, equal episode weighting, the baseline included and earliest ties. Checkpoints are 0/16/32/48/64.
