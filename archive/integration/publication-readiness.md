## Current official arXiv requirements

Checked against primary pages on 2026-09-03 UTC; refresh again before an actual submission.

- **Scholarly content:** arXiv expects self-contained research of archival interest, with appropriate sections, figures, references and professional tone. It can decline work lacking substantive/original research or needing major revision. Moderation is not peer review; earlier journal acceptance does not guarantee arXiv acceptance. Significant generative-AI use should be disclosed consistently with disciplinary methodology standards; humans remain responsible, and AI tools are not authors. [Content moderation policy](https://info.arxiv.org/help/moderation/index.html)
- **Endorsement:** first submission or a new category can require endorsement. Current guidance links a January 2026 policy update. Institutional-email and prior claimed-paper conditions apply to that route; personal endorsement remains an alternative. Check the account's actual category-specific state and obtain an eligible subject-area endorser when required. Endorsement does not certify correctness. [Official endorsement guidance](https://info.arxiv.org/help/endorsement.html)
- **Category:** select according to the manuscript's actual contribution. `cs.LG` fits machine-learning research; `cs.PF` fits performance evaluation; `cs.LO` includes program verification. A browser workbench description alone does not establish a learning-method contribution. Category selection is an editorial judgment, not a way to bypass a decline. [Official category taxonomy](https://arxiv.org/category_taxonomy)
- **Metadata:** title/author/abstract must agree with the paper; accurately state affiliation and author consent. The abstract limit remains 1,920 characters. Current help specifies ASCII metadata with supported TeX representations, so validate the literal form values rather than copying rich PDF text. [Metadata guidance](https://info.arxiv.org/help/prep.html)
- **Source and bibliography:** submit the TeX source when available. Current processing can run BibTeX/Biber from supplied BIB inputs; a matching precompiled BBL is also supported and takes precedence. Include necessary figures/styles and exclude irrelevant backups/output files. Inspect arXiv's generated PDF before completion. [TeX submission instructions](https://info.arxiv.org/help/submit_tex.html), [Why source is required](https://info.arxiv.org/help/faq/whytex.html)
- **Compiler compatibility:** arXiv currently offers TeX Live 2023 and 2025, with 2025 the default, and explicitly lists `pdflatex` and `xelatex`. Tectonic is useful locally but is not the same build environment. For biblatex, match BBL/backend versions; current guidance lists BBL 3.3 for TeX Live 2025. [Current arXiv TeX environment](https://info.arxiv.org/help/faq/texlive.html)
- **Appeal:** first read the actual notice. An author appeal through the support portal should include submission IDs, prior correspondence, the PDF, a research-content explanation, category fit and a specific reconsideration rationale. Repeated requests without new information are not considered. arXiv does not promise detailed feedback; denied appeals are final, apart from possible procedural review channels. Do not contact moderators directly. [Official appeal process](https://info.arxiv.org/help/moderation/appeals.html)

These rules explain review stages and preparation obligations. They cannot diagnose the user's two past rejections without the notices, and no workflow can guarantee acceptance.

## Scholarly workflow to add to the project plan

1. **Recover decisions and freeze a candidate.** Save each notice and exact submitted archive privately, hash them, and distinguish technical, metadata, endorsement, moderation, and appeal states. Freeze the manuscript, repo commit, model/data versions and relevant results. Choose one paper scope and one primary contribution; write a short contribution paragraph that can be supported now.
2. **Create a claim ledger.** For every abstract/result/table/theorem claim, record claim ID, exact statement, class, assumptions, source artifact, immutable revision, validation command, measured domain, limitations and status. Reuse [formal_vocabulary.md](/Users/casey.allard/uor-r4/docs/formal_vocabulary.md:24), [proof-model status matrix documentation](/Users/casey.allard/uor-r4/crates/uor-r4-proof-model/README.md:21), and [check_claim_wording.py](/Users/casey.allard/uor-r4/scripts/check_claim_wording.py). Do not treat source-wording scans as proof verification.
3. **Establish original contribution and related work.** Build a versioned reading ledger from primary papers, official repositories and standards. Each entry needs authors/title/DOI or arXiv version, exact theorem or experimental locator, code revision, hypotheses, notation translation and how it supports or differs from this paper. Use search tools for discovery, then read the primary text. Classify novelty as known, translated, corollary, new proof, adjacent, or apparently new within an explicitly recorded search scope. Do not claim global novelty from failed searches.
4. **Audit mathematics independently.** Use the Mathbox proof-audit claim card and dependency graph. Give each implication `proved`, `conditional`, `finite-range checked`, `incomplete`, or `refuted` status under the exact domain. Record theorem-to-Lean declaration-to-Rust/WASM correspondence, toolchain and trusted assumptions. Where the implementation differs from the mathematical model, state the bridge obligation. A proof of finite state width does not prove context preservation, accuracy, or arbitrary-session stability.
5. **Qualify empirical claims.** Pin model revision, tokenizer, prompt set/splits, hardware/OS/browser/backend and complete commands. Save per-trial logs, outputs and raw samples; define TTFT and generation timing, cold/warm cache conditions, synchronization, memory measurement, failures and uncertainty. Match baselines fairly. Keep actual browser behavior, native microbenchmarks and geometry diagnostics separate. Include quality/causal controls alongside speed when the mechanism purports to replace attention. Run only the smallest evaluation that changes a named decision; protect sealed data and frozen evidence.
6. **Generate figures and tables from admitted data.** No handwritten measurement arrays in the publishing path. Each plotted value must resolve to a logged run and script revision; machine-generated files should carry provenance and units. Distinguish theoretical bounds, source-reported measurements, reproduced results and illustrative diagrams. Ensure the paper, README and research summary carry the same status.
7. **Write for the research community.** Use a neutral abstract with a precise problem, method, supported contribution, actual result and limitation. Keep product vision and untested extensions in clearly labeled future work. Separate sole authorship, collaborators, acknowledgments, funding and AI-tool disclosure; verify names/identities rather than guessing. Have a technically qualified independent reader review the claim ledger and manuscript before submission.
8. **Build reproducibly.** Use the existing Tectonic for local drafts with retained logs and bibliography intermediates, an isolated output directory, pinned resource bundle/cache, and an offline second build when practical. Then verify using the selected arXiv-compatible TeX Live environment. A successful PDF does not establish scientific correctness. Resolve undefined citations/references, missing assets/glyphs, rendering defects and source dependencies; visually inspect every final page with bundled Poppler.
9. **Package and verify the package itself.** Build a manifest of allowlisted TeX/BIB/BBL/style/figure files and hashes. Regenerate BBL after final citation changes. Build again from a fresh extraction of that exact archive; never assume the working directory PDF proves the archive works. Keep scripts/data/code in the repository or appropriate ancillary/reproducibility deposit with stable revision links. Preserve old evidence; exclude AppleDouble, local notes, unused images and secrets from the new archive.
10. **Perform a final editorial/status gate.** Check category, endorsement, author metadata, license selection, abstract characters, source/PDF consistency, artifact access and claim ledger. Complete arXiv processing and inspect its PDF separately from submission completion, moderation and public announcement. Record actual receipt/decision/identifier. If declined, apply the stated notice and official appeal policy to a concrete author-reviewed response; do not submit guesses or repeat unchanged material.
11. **Connect dissemination after announcement.** Use the installed Hugging Face paper skill to link a real arXiv identifier to model/dataset cards and authorship metadata when appropriate. Its paper manager assists indexing/linking; it does not submit to arXiv, provide peer review, or decide acceptance. Preserve manuscript and artifact versions together when issuing corrections.

Suggested durable outputs: `paper/claims.json`, `paper/literature.jsonl`, `paper/reproducibility.md`, a generated tables/figures manifest, a pinned bibliography, `paper/build-manifest.json`, a source-package manifest, and a private submission-decision log. These are proposed next artifacts; they were not created in the product repository during this audit.
