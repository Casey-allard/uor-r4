Its code search accepts only strict increases of exact fitted joint-hypothesis count, and starts at 96/96. Thus zero accepted moves over 5,880 evaluations is forced by the saturated criterion. Revisit learned representation when an objective has remaining signal: unfamiliar-entity or structural transfer, a declared margin, compactness at matched accuracy, or complete inference cost. Ordered 2I products can share interval preparation, but the group is finite and cannot provide arbitrary injective memory. Exact occurrence/version records must own payloads separately. A semantic correction is generally noninvertible; forcing replacement into a pure reversible group action would confuse transport with revision.

## Why scope/version memory is the next obstruction

`ObservedTextRuntime::step_inner` presently selects among matching subject/goal clauses using the highest joint parse score. The fixture's oracle rejects duplicate matching facts, so this policy has not been tested as correction handling. A syntactically confident stale assertion could defeat a later correction.

A parse score is not a version policy. Adding an input-dependent constant c(x) to every parse score leaves the within-clause argmax unchanged, but can reverse ranking between clauses x and x'. Therefore parse likelihood/score alone cannot define which fact is current. Introduce exact eligibility by scope, relation and committed version before ranking admissible sources.

A useful proposed record layout is:

`key = (scope, lexical entity identity, learned relation type)`

`record = (key, record ID, predecessor ID, source/version, owned payload, learned update intent)`

Use typed/length-delimited field encoding, not ambiguous slash concatenation. Version order and byte equality can be deterministic infrastructure; the language model still has to infer arguments, relation, assertion/correction intent and requested temporal view from observed text. Explicit authenticated scope metadata is a legitimate API boundary; gold semantic intent is not.

Pin one committed read view through a dependent answer. A correction arriving between hops must not splice old and new records into an answer that existed in neither view. Captured payload ownership and origin liveness remain distinct. A record deleted from the current directory is not automatically unavailable to a pinned read; explicit eviction/capacity failure must remain visible.

Define previous assertion versus previous distinct value before fitting. Cover initial/previous/current requests together with same-value reassertions, conflicting bare assertions and valid explicit corrections. Reuse historical pitfalls rather than rediscovering them. Scope noninterference holds within the declared retained capacity; cross-scope eviction under shared capacity is not a proof of unlimited isolation.
