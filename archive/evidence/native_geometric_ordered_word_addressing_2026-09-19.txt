Verbatim tool output; every number is reproducible from the commands shown.

## 1. What changed and why

`GeometricAttention` previously addressed memory by **one token**. The controlled experiment in the
[previous receipt](native_geometric_geometric_attention_2026-09-19.txt) §10 showed that costs 3×
accuracy when a token repeats with two different successors (`clean 0.44` vs `duplicated 0.14`), and
identified the fix: the address must be an **ordered word** over the context, not a set or a
commutative hash.

This change makes the word length `order` explicit. `order = 2` addresses by the ordered pair of the
last two tokens over the 120 elements of `2I`, giving **120² = 14,400 ordered addresses**, with
`(a,b) ≠ (b,a)` by construction. Address is a positional radix composition of 2I elements — tabled
reads and index arithmetic, no multiplier.

This is the project's own formalism, not an import: the ordered n-let of group elements, and the
directed relative element `r(i,j) = inverse(g_i)·g_j` of the September-13 attention synthesis
(`docs/integration/geometric-attention-research-2026-09/README.md`). The order principle is the one
W33 supplies in exact finite form (`PLPL = LPLP`, `Ω = LP − PL`, `ker(Ω)` order-insensitive).

## 5. A defect found and corrected during this change

The first run of the refactor produced 0.00 everywhere, including at `order = 1` where 0.86 had been
measured. Cause: `tail_word` was off by one, reading index `len` instead of `len − 1`, so
`forward_i32` — and therefore the accuracy metric — read the wrong bucket. **Training was correct and
the measurement was not.** Corrected; all results above are post-fix. Recorded because the failure
mode (a measurement bug that looks like a mechanism failure) is exactly the class of error this
project has already been burned by.

## 9. Honest limits

* Still **not a language model**. This is a from-scratch synthetic task at `dv = 32`, one layer.
* The task is now **saturated** at 1.00, so it can no longer discriminate. The next measurement needs a
  harder task (larger alphabet, longer runs, or a real corpus) or the mechanism will look perfect while
  hiding its real limits.
* Addresses are still **fixed**, not learned. `order = 2` needs ~14,400 buckets and the dense state is
  `n_addr × dv`; `order ≥ 3` (1.7M+ addresses) requires a sparse addressed store.
* No serving-multiplier claim: the construction is multiplier-free and the integer path is verified
  equal to an `f64` reference, but `scripts/serving_multiplier_check.py` has not been run on it.
* Energy per token remains **UNAVAILABLE** on this machine.

## 11. Closing the saturation caveat: a discriminating curve

§9 flagged that the copy task saturates at `order = 2` for a 32-token alphabet, so it can no longer
discriminate. Difficulty is now raised by shrinking the alphabet until ordered *pairs* repeat with
different successors. Context 16, 900 steps, deterministic seeds, `dv = 64`:

```
alphabet= 4 context=16 order1=0.34 order2=0.62
alphabet= 8 context=16 order1=0.25 order2=0.84
alphabet=16 context=16 order1=0.42 order2=0.97
alphabet=32 context=16 order1=0.55 order2=1.00
```

**The ordered-pair address wins at every difficulty, and the margin grows as words become unique**
(+0.28, +0.59, +0.55, +0.45). At alphabet 4 — only 16 possible ordered pairs for a 16-token run — both
saturate-limit cases are gone and `order = 2` still doubles `order = 1`. The measurement now
discriminates. Pinned as `ordered_words_win_at_every_difficulty`.

(Counter-intuitive but consistent: `order = 1` also improves with a larger alphabet, 0.34 → 0.55,
because single tokens then repeat less often. The two effects are different collisions and the
data shows both.)
