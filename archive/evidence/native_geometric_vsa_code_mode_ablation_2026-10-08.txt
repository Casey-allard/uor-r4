Date: 2026-10-08. Executed by: DeepSeek session, local M1 checkout.
References #820.

WHY THIS WAS RUN
  `learner/vsa_codes.rs` documents a defect and its repair. The defect: the serving
  path built its VSA codebook from `splitmix64(vsa_seed, token_id)`, a fixed random
  function of the token id, so `E[d_H] = D/2` and "the only recoverable signal is
  `a == b`". The repair: derive each token's code from the LEARNED 120-root
  assignment by locality-sensitive hashing of the canonical icosian root
  quaternions, so `E[d_H] = D*theta/pi`, monotone in the angle between roots.
  The Card P7 ablation had measured the VSA term as HARMFUL under the fixed
  codebook. Question: does the repaired codebook change that verdict in the
  full-vocabulary discrete scorer?

WHAT THIS ESTABLISHES
  * Switching the codebook from the fixed token-id hash to the learned-root LSH
    construction does NOT make the VSA term contribute to the full-vocabulary
    discrete scorer. The band is NEGLIGIBLE (epsilon = 0.01 BPB) in all four runs,
    and the delta is slightly NEGATIVE in every one (ablating VSA marginally helps,
    by 0.0010 to 0.0020 BPB), replicated on two disjoint held-out slices.
  * Top-1 accuracy is unchanged by the mode (within 0.12 pp, both directions).
  * This is the aliasing ceiling that `vsa_codes.rs` itself states: codes are a
    function of the root, so a 4,096-token vocabulary collapses onto at most 120
    distinct codes and two distinct tokens in the same root have `d_H = 0` —
    indistinguishable to every head. The module's own words: escaping that requires
    codes at finer resolution derived from the CONTINUOUS learned embedding, which
    the exported artifact does not carry (it stores `token_to_root` only); that is
    Stage 3 of `native-core-transition-plan.md`.

SCOPE AND LIMITS — read before reusing these numbers
  * This measures the VSA term's contribution to THIS artifact's full-vocabulary
    discrete scorer. It is not a verdict on the 120-root representation, on the
    JEPA learner, or on routing: the September wiring record measured the root
    codebook improving `shortlist-recall` on two disjoint slices (recall 8.4-8.8 %
    -> 10.7-11.2 %; shortlist BPB 2.72-2.83 -> 2.67-2.78). The repair is real; its
    effect does not reach this scorer's VSA term.
  * `ablate-prose` prints a static wiring note for the `vsa` row ("MIS-WIRED: heads
    bind a fixed random codebook..."). That string is not mode-aware, so it is stale
    for the root runs here; the mode switch is confirmed by the header line
    ("root (120 distinct code vectors)" against "fixed (0 distinct code vectors)").
  * Debug build, one artifact, one corpus, two 8,256-token slices, temperature 1.0.
    No training, no fitting, no serving change was made.
  * The absolute BPB differs from the Card P7 record (vsa row 1.8048) because that
    record evaluated the stripped `_nocoarse` artifact (963,950 bytes); this one
    evaluates the 2,691,950-byte artifact whose sha256 is quoted above.

NEXT ACTION THIS POINTS AT
  Stage 3 of `native-core-transition-plan.md`: codes derived from the continuous
  learned embedding at finer resolution than 120 buckets. Until the artifact carries
  that embedding, no codebook at root resolution can make this term informative, and
  this sweep cannot be used to retire the mechanism.
