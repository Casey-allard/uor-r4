WHAT THE INVESTIGATION FOUND INSTEAD — THE VIOLATION IS WIDER, AND THE GUARD IS NARROWER
  The multiplier-free invariant is enforced by `scan_for_forbidden_arith_and_floats`
  (`transformerless/source_scan.rs`) over `NATIVE_GEOMETRIC_INTEGER_KERNEL_BEGIN/END` regions.
  For `hopf_metric.rs` the test at `tests/native_geometric_allocations.rs:526`:
    * checks the whole kernel region for the STRING "f32"/"f64" (floats only), and
    * loops over a list of function names — including `mul_q30`, `norm_q30`, `dot_q30` — and
      asserts only that each name appears EXACTLY ONCE (`matches(function).count() == 1`).
  It does NOT arithmetic-scan that region. Measured: the region from line 477 to 1033 contains
  **82 raw `*` occurrences**, in `mul_q30` (a 16-multiply Hamilton product), `norm_q30` and
  `normalize`.

  That matters because `mul_q30` is on the SERVING hot path. `context_hopf_fiber_q30` accumulates
  `s3 = s3.mul_q30(root)` over the context window — up to 64 calls per token — so the Q30
  quaternion algebra contributes on the order of 1,000 multiplies per token, roughly 40x the
  JEPA projection I originally named. The "zero matrix multiplications" metadata was therefore
  accurate about GEMM but silent about a much larger folded multiplier site.

THE CORRECT FIX FOR THE LARGER SITE IS NOT SHIFT-ADD
  `mul_q30` multiplies by one of the 120 canonical root quaternions, and 2I is closed under
  multiplication, so the accumulated state is always a GROUP ELEMENT and the accumulation is
  exact group composition. That is what this project already claims as its mechanism — "exact
  group composition by lookup". The right implementation is therefore a **120x120 product table**:
  120 element coordinates (120 x 4 i32, ~1.9 KB) plus a 120x120 index table (14,400 u8), giving
  O(1) table reads, ZERO multiplies, and EXACT products instead of Q30 rounding that currently
  needs `normalize` every 8 steps to control drift.

  That is strictly better than shift-add on every axis — correctness, multiplier count and
  speed — and it does not hide the multiply behind a helper, it removes the need for one. It
  requires the accumulated state to be carried as an index rather than a quaternion, which is a
  real change to `context_hopf_fiber_q30` / `context_fiber_from_ring` and their consumers.
