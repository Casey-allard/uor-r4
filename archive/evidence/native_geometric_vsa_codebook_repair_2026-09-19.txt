  Implemented the "correctly wired" version of the VSA codebook and measured it against the
  current wiring, as DECISIONS.md D2 requires for an `enabler` whose delta is NEGLIGIBLE.

  * `Codebook::from_vectors(seed, table)` — a codebook built from explicit per-token vectors.
  * `learner/vsa_codes.rs` — builds those vectors by locality-sensitive hashing of the canonical
    icosian root quaternions, so each token's code follows the model's LEARNED 120-root
    assignment (`token_to_root`) instead of `splitmix64(vsa_seed, token_id)`.
        for bit b:  w_b ~ Z^4, random 31-bit integers   (deterministic from the seed)
                    code[r][b] = 1  iff  <w_b, q_r> > 0
                    E(t) = code[ token_to_root[t] ]
    Asserted properties (unit tests, both pass):
        - identical roots -> d_H = 0
        - antipodal class mean 4096, coincident class mean <= 200, span >= 3000
        - class-mean distance monotone non-increasing in cos(theta)
        - >= 8 conjugate-class angles; > 9 distinct distance levels (graded, not a 9-level collapse)
        - <= 120 distinct codes for a 4096-token vocabulary (the aliasing ceiling)
  * `ablate-prose --vsa-code-mode <fixed|root>` selects the codebook at evaluation time.

WHY RANDOM INTEGERS, NOT {+1,-1} SIGNS
  Signs make `dot == 0` ties reachable on the highly symmetric icosian roots, which broke the
  LSH estimate (an observed antipodal spread of 2519..4096 instead of a constant complement).
  Random magnitudes make exact cancellation measure-zero, so `code(-q)` is the exact bitwise
  complement of `code(q)`.

RESULT — THE REPAIR DOES NOT MAKE THE MECHANISM CONTRIBUTE
  Wiring the codebook to the learned representation does not help. The ablation delta stays
  NEGLIGIBLE and mildly negative (-0.0009 -> -0.0013), the baseline BPB is unchanged
  (1.7989 -> 1.7993, +0.0004), and the decision-flip rate rises from 0.7 % to 1.2 %: the layer
  moves the model about twice as often, still in the slightly wrong direction.

  This is a NEGATIVE for the repair, not a retirement of the mechanism. Three distinct causes
  are now separable, and only the first was addressed:

  1. WIRING (fixed here). The codebook was a fixed random hash of the token id, disconnected
     from the learned assignment. Now it is derived from the learned assignment. Established
     by unit test rather than assumed.
  2. ALIASING (binding, not fixed). 4,096 tokens collapse onto at most 120 codes, so distinct
     tokens in the same root have d_H = 0 and are indistinguishable to every head. The heads had
     been doing exact-identity induction correctly after the query/key inversion fix; the
     root-derived codebook TRADES that away for coarse graded similarity, and the trade is
     net-negative. Removing the aliasing requires codes at finer resolution than 120 buckets,
     i.e. derived from the CONTINUOUS learned embedding, which the exported artifact does not
     carry (it stores `token_to_root` only, not `weights_base`).
  3. DESIGN CEILING (not addressed, and structural). All four heads reduce matching to a single
     scalar Hamming distance over a single codebook. One scalar cannot simultaneously express
     exact identity, graded semantic similarity, and role-specific matching. Even with a finer
     codebook this tension remains: a finer code improves similarity while making identity
     discrimination harder, because both are read off the same number. The required change is a
     richer read — separate identity and similarity channels per head, or a per-head codebook —
     not a better single codebook.

  Conclusion for the plan: the VSA layer is an `enabler` whose value cannot be realised at root
  resolution or through one scalar distance. The next step is not retirement and not a different
  hash; it is a finer, representation-derived code PLUS a richer per-head read, which is Stage 3
  work and requires an artifact section for the continuous embeddings plus a re-export.

LIMITATION THAT MATTERS
  `ablate-prose` scores the FULL vocabulary and therefore does not exercise the 64-candidate
  shortlist routing. The VSA vector also feeds `route_shortlist_q30_with_memory` as a routing
  query, so the ROUTING effect of a codebook change is NOT measured by this experiment. A
  shortlist-level measurement (or an end-to-end serve comparison) is required before any
  conclusion about the routing role.
