SCOPE
-----
#973 asks for one bounded task: qualify the core's short-prefix arithmetic and declared mean-loss
STE, repair the count instrument, MEASURE real-text causal route coverage, then measure complete
training-step cost, and admit a small pilot only if those results make it informative.

RESULT IN ONE LINE
------------------
**Do not train this configuration.** On real text at V=4096, order=2, 64-token windows, 93.8% of
scored positions read a bucket that has never been written in that window. An empty route is the zero
vector, the default readout has no bias, and its loss is exactly log2(4096) = 12 bits/token, so the
default path's mean loss is at least **11.26 bits/token** — worse than the unigram baseline (9.22)
and far worse than the best static backoff baseline (6.33). The cold-route floor alone exceeds the
frozen development target, which is the frozen failure branch. The missing piece is a learned
cold-context prior, not more steps.

================================================================================
1. CORRECTNESS: TWO SOURCE DEFECTS CONFIRMED AND FIXED
================================================================================

1a. Short-prefix unsigned underflow (review finding 1) — CONFIRMED, FIXED.
    `tail_word` computed `len + k - order` and `word_at`/`sequence_loss` computed `i + k + 1 - order`
    on `usize`. For `order = 2` these underflow whenever the prefix is shorter than the word, which
    panicked under overflow checks and silently wrapped in release (where `Vec::get` then returned
    `None`, so padding happened by accident, not by design).

    Fix: one definition of the padding contract, `PAD_TOKEN`, `word_ending_at` and `tail_word_of`,
    using checked arithmetic, shared by the served path, `sequence_loss` and the trainer.

    Verified by `short_prefixes_pad_instead_of_wrapping` (exact table for order 1 and 2, empty,
    1-token and 2-token prefixes) and `short_prefix_paths_do_not_panic_under_overflow_checks`
    (`forward_i32`, `sequence_loss`, `train_batch` and `final_token_correct` at lengths 0..=3 for
    order 1 and 2, in a debug build with overflow checks on).

1b. Value and kernel gradients divided by the sequence length twice (review finding 2) — CONFIRMED,
    FIXED. `g = p * inv` at the readout already converts the summed loss to the mean; `gkernel +=
    acc * inv` and `gwv += dscratch * inv` applied `inv` a second time, scaling the value and kernel
    gradients by 1/(n-1) relative to the readout (63x at n=64).

    Fix: the two extra `inv` factors are removed; `inv` is now documented as applied exactly once.

    Verified by two INDEPENDENT analytic references that never call the trainer's backward pass and
    never finite-difference the quantised step function:
      * `reference_order2` derives d(mean loss)/d(theta) by the chain rule for the order-2 exact
        read, with the value gradient as an explicit suffix sum over later reads at the same address;
      * `reference_order1_kernel` derives the kernel gradient for the order-1 group convolution.
    Tests: `the_mean_loss_ste_matches_an_independent_analytic_reference` (two lengths, output and
    value groups, both required non-vacuous) and
    `the_kernel_gradient_matches_an_independent_reference_at_order_one` (two active classes,
    repeated writes, non-zero read credit). Both pass.

    NOTE: the first version of the order-1 reference stored the write under the VALUE token's
    element instead of the context token's, and the first order-2 fixture was vacuous because
    `norm_bits = 0` renormalises to zero bits. Both were caught by the non-vacuity assertions in the
    tests themselves.

    BEHAVIOURAL EFFECT, MEASURED — the review asked for this explicitly. Fixing the factor changes
    two pre-existing synthetic filter results at their recorded seeds and budgets:
      * `corruption_in_the_objective_changes_the_filter` failed after the fix (corrupted 0.13 -> 0.10);
      * `a_general_filter_is_at_least_as_good_as_a_class_filter` failed after the fix (class 0.27 ->
        general 0.09).
    Both pass again only after re-tuning the fixture learning rate (0.05 -> 0.15 and 0.05 -> 0.5
    respectively), because the fix changed the per-group gradient scale the rates were tuned under.
    At the re-tuned rates the general-filter margin is 0.11 vs 0.09 against a 0.02 tolerance, i.e. a
    tie rather than the previously recorded "does not lose". **The earlier filter accuracies are
    therefore superseded at their recorded scope, and the general-filter capacity claim is not
    validated at this budget.** This is a corrected measurement, not an improvement.

1c. Causality and reset fixtures added (all pass):
    * `same_query_tail_with_a_changed_prefix_is_distinguishable` — the review's counterexample
      `[0,1,2,0,1]` vs `[0,1,3,0,1]`: identical query address, different accumulated bucket, different
      logits. This is why the earlier "context is the residue pair" claim is wrong.
    * `cold_routes_are_uniform_on_a_non_repeating_sequence` — a non-repeating order-2 sequence has no
      live route at all and costs exactly ln(V); the same tokens with a repeated pair do have one.
    * `a_batched_read_matches_an_incremental_observe_predict_trace` — the batch teacher-forced read
      equals an independent step-by-step `observe`/`logits` trace, elementwise, for order 1 and 2.
    * `a_future_token_cannot_change_an_earlier_prediction` — no position depends on later tokens.
    * `sequence_state_is_reset_between_documents` — a prior sequence does not leak into the next.
    * `an_empty_bucket_predicts_uniformly_and_costs_log_v` — the cold-route loss is exactly ln(V).

1d. Float-training versus integer-serving rounding: made explicit in the references. The trainer
    floors `num_raw * 2^-shift`; the served path computes `num_raw >> shift`. For integer-valued
    `num_raw` these agree (arithmetic right shift is floor division, including for negatives), and the
    `order`-2 test compares the trainer's accumulated gradients against the closed form directly.

2. COUNT INSTRUMENT REPAIRED WITHOUT ERASING PRIOR OUTPUT (review finding 3)
================================================================================
The previous receipt text and all prior numbers are PRESERVED. The tool's framing is corrected:

* **Relabelled.** The tool now prints "STATIC BACKOFF COMPARISON on real text (NOT an
  information-theoretic ceiling)". The earlier "achievable ceiling / entire context is the residue
  pair" framing is withdrawn: the residues select the bucket, but the bucket holds prefix-accumulated
  values, which the counterexample in 1c demonstrates. The measured quantity is the best predictor
  that sees only the address. The binary name is unchanged.
* **Cross-entropy and top-1 now come from the same interpolated distribution**
  (`blended_argmax`), so a `lambda = 0` fixture reproduces the unigram *probability and argmax*
  exactly — new test `lambda_zero_is_exactly_the_unigram_model`, which also checks the interpolated
  distribution normalises over the vocabulary.
* **Accuracy cost moved out of the tuning sweep.** Computing the argmax inside `evaluate` made the
  tool hang (the tuning sweep paid a per-candidate argmax 100x per family); accuracy is now computed
  once per scored position at the final weights, exactly as the task requires.
* **Protocol stated explicitly.** Counts are fit on the fit split only (80% of non-held documents);
  interpolation weights are tuned on the disjoint validation split (every fifth remaining document)
  by target-probability cross-entropy; held-out figures use those counts and weights. **There is no
  refit on the full training split** — the earlier claim of a full-training refit is corrected here.
* Scored positions are the same range for every family (`i >= 2`); bits/byte uses the held documents
  that produced the scored positions; documents are tokenised separately so no context crosses a
  document boundary. Tokenizer, corpus and split counts are printed, and the corpus is pinned by
  sha256.

3. CAUSAL ROUTE COVERAGE MEASURED ON REAL TEXT (the decisive instrument)
================================================================================
Tool: `crates/uor-r4-core/src/bin/geometric-realtext-coverage.rs`.
Method: replay exactly what the trainer does. At step i the write stores value(t_i) at the address of
(t_{i-2}, t_{i-1}); the read addresses (t_{i-1}, t_i), left-padded on a short prefix. A read is
"empty" when no write in the same window touched that address. State resets per window; windows are
non-overlapping chunks of the document.

VECTOR CANCELLATION (named, seeded initialisation; NOT learned behaviour)
  dv=128 seed=20260919, 64 windows: 0 of 388 written routes had an exactly-zero value vector.
  Scope: one seeded initialisation of the value table. It bounds cancellation attributable to that
  table, not a learned or trained behaviour. Token-only counting cannot see cancellation; this is the
  named substitute, and it is explicitly not a trained result.

READING
* Empty routes dominate (85-94%), and widening the window helps only slowly (0.938 -> 0.846 from 64
  to 256 tokens) because a route is live only where the same ordered residue pair recurred earlier.
* The first eight positions of every window are cold with probability ~0.994, which is structural.
* The addresses that ARE written are almost always unique within a window (distinct exact contexts
  per address ~1.004, distinct successors ~1.002-1.083), so the live routes carry almost no repeated
  structure to average over.
* Information regimes are labelled, not merged: the global count baselines in section 2 are fit on
  global counts and contain corpus priors that an empty per-window bucket cannot contain; the
  per-window cold routes here are a different regime. They must not be read as one comparison.

CORROBORATION (independent). The untrained trainer's held-out loss at this configuration was
8.5064 nats = 12.27 bits/token, close to log2(4096) = 12, exactly as a mostly-cold untrained model
predicts. Measured loss and the coverage floor agree in magnitude.

================================================================================
Tool: `crates/uor-r4-core/src/bin/geometric-realtext-train-probe.rs`.
A step is one `train_batch`, which covers both full-table quantizations (wv and wo, each vocab x dv),

================================================================================
5. DECISION (frozen branch, applied)
================================================================================
The task's failure branch was: *if the cold-route loss floor already exceeds the frozen development
target, or useful reads are too rare to train the intended function, stop scaling this configuration.*

Both conditions hold, on both corpora:
  floor (docs, 64-token)  11.2575 bits/token  >  best static backoff baseline 6.3310 bits/token
  floor (docs, 64-token)  11.2575 bits/token  >  unigram baseline            9.2223 bits/token
  live routes             6.19% of scored positions (docs), 14.51% (crates)

**Decision: do not train this configuration at V=4096, dv=128, order=2 with fixed element(token) =
token % 120 and per-window state reset.**

MISSING PATH, named. The absent channel is a **learned cold-context prior**: the reset state contains
no corpus statistics at all, so a cold route cannot fall back to anything, whereas the count baselines
in section 2 carry global priors the empty bucket does not. Also unchanged and untested here: the
`order`-2 radix read does not exercise group multiplication, zeta phases or chirality, and a bijective
renaming of the 120 labels preserves its behaviour, so this baseline is not evidence about the
distinctive geometry.

SMALLEST GEOMETRIC INTERVENTION (proposal, with matched controls — NOT executed here).
  1. Supply a learned cold-context prediction through the same discrete path, with an explicit
     fallback marker, and compare against (a) the same model with the prior ablated and (b) the
     global count baseline labelled as a different information regime. This is what the review's
     "learned geometric prior/state plus selected causal memory" asks for, and it must be shown that
     BOTH channels matter.
  2. Only then revisit capacity. Do not increase dv or steps: an injective map from 4,096 tokens to
     120 single roots is impossible, and learned remapping cannot inject identities it does not have.
  3. Widen the causal state only with a mechanism that raises live-route frequency; window widening
     alone moves p_empty 0.938 -> 0.846 over 64 -> 256 tokens, which is not enough.

LIMITS
------
* No model was trained to convergence; no pilot was run. The timing probe trains 6 steps to measure
  cost, not quality.
* Coverage is token-only. Cancellation is measured under one named seeded initialisation and is not a
  trained result. Weights were never learned, so nothing here is a statement about learned behaviour.
* The mechanism as configured only (fixed `element(token) = token % 120`, `order <= 2`, per-window
  reset). This is not a verdict on the geometric architecture; the group-composition path is separate
  and unmeasured on real text.
* Corpora are internal repository source and Markdown, pinned by sha256. They are development data and
  are not an instruction corpus or a final holdout.
* Energy/token remains UNAVAILABLE. No serving-multiplier claim is made for the new modules, and
  `serving_multiplier_check.py` was not run on them.
* Storage: text only plus two binaries in the shared existing `target/`; no model artifact. 128 MiB
  stop margin untouched. No deletion, no cleanup, no paid or external compute.
