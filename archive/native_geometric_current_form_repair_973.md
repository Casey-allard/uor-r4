## Diagnosis: the first divergent decision

Example: `Record: amber quay holds pemru. Record: amber quay holds pemru. Where is pemru? Explain in a sentence. Name the owner first. Answer:` (required ` pemru is in amber quay.` from live head record 2, with EOS).

1. **Writer binding** is intact on every artifact: both records are committed with owner `pemru`, span `amber quay`, record 2 the live head (`final_relations` identical across candidates).
2. **Current selection** is where the artifacts diverge. The handoff trace on `4568679d` shows `candidate: None` for every request that carries both instructions, in every layout (`handoff-trace-1/context-trace.json`), while the same records with the owner-first instruction alone or the explanatory instruction alone offer record 2 through the committed relation source 33. The frozen persistent relation reader (`relation::read_choice_with_recent`) scores each record from `read_features`, whose owner scan covers only the eight most recent request words. The request `Where is pemru? Explain in a sentence. Name the owner first. Answer:` has twelve words and the owner sits at reverse index 9, so no owner feature is produced, no record scores above zero, and no relation candidate exists. This is the first decision that differs from the eight-word requests.
3. **Exact source and span.** Without a relation candidate the parent dispatch falls back to a copy of a query occurrence (word index 14, `quay` in the second record) and the frozen extent operator extends it forward through `holds pemru` (span words 2). In the forward layouts the same fallback happens to reproduce the record span (`amber quay`, one extension), which is why forward both-instruction requests already read correctly, from the occurrence rather than the committed record.
4. **Field composition** then cannot anchor: `field_composition::initial_anchor` requires the copy candidate's span to equal the record's stored span, so the owner-first composer never fires on the reverse layout and the copy path emits the mis-spanned words followed by learned continuation text without a terminating decision.
5. `fc479376` answered these prompts through its historical selector instead (anchor on record 1, the root, with a historical proof to head 2, past tense); `4568679d` correctly defers there and thereby exposes the broken frozen current path.

## The change

The smallest causal change is at the divergent decision: the frozen persistent relation reader's own owner scan. A **reader-request-window contract** (`reader_request_window` on the historical-version witness, absent in legacy artifacts) lets `relation::read_choice_with_recent` scan the request words after the latest committed fact, up to the sixteen-word view, for the named owner instead of the eight most recent words of any kind. The scan is bounded by `relation::committed_cutoff`, the byte end of the last committed owner, value or span terminal, so an owner spelled inside an earlier record is never taken for the requested owner. The change is versioned and ablatable: `Control::HistoricalVersionIntentReaderWindowDisabled` withholds it, and removing the witness (`HistoricalVersionIntentDisabled`) reproduces the frozen parent exactly, which the actual-artifact test asserts on every new sequence.

What is deliberately unchanged: `relation::read_features`, the inherited eight-word feature base of every later learner (dependent reads, the current-query handoff, historical read, historical version intent), keeps its exact frames through a new `read_features_window(…, 8, None)` wrapper; the role reader's eight-word context, the word-copy hints, the extent operator, field composition, the emitters, all learned codes, dictionaries and receipts of `4568679d` are untouched. The retained artifact is therefore a **promotion** of `4568679d` (`native_historical_version promote-window`): the same learned witness with the contract flag set and the identity it binds, no refit. No prompt keyword, owner/value list, response template, source-index answer, oracle call or evaluation-ID lookup enters serving; the reader still decides from its learned owner-hint features, and the field composer still decides owner-first composition from its own learned request-word codes, as the forward layouts already showed.

Why this is the operator repair the review asked for rather than a historical-selector patch: the historical witness is right to defer on a current request; the defect was that the shared reader below it could not see the owner. With the owner visible, the existing dispatch order (historical, handoff, dependency, persistent read) selects the committed live head through source 33 and the owner-first composer anchors on the stored span `amber quay` (span words 0), which the earlier occurrence copy could never satisfy on the reverse layout.
