## What and why

`tests::the_transformer_control_is_parameter_matched_to_the_geometric_arm` in `crates/uor-r4-training/examples/mqar-bench.rs` first compiled after #2224 and failed at its tolerance assert. I looked for a merged change to the geometric stack's parameter count and found none:

- `git log -S parameter_count -- crates/uor-r4-training/src/geometric_stack.rs` finds two commits. a5f8313 (#2174) introduced this test and froze 1,370,008. ca5bdc6 (#2193) added quaternion-valued maps, which are opt-in (`quaternion_weights=none` by default) and do not change the default shapes.
- `StackConfig::shapes()` has not changed since #2174. I summed it by hand for `rrarra`, width 128, 4 heads, MLP 384, context 512, vocab 512, L2 read with rotation: **1,370,008**, so the frozen count is still correct.

The real cause is the tolerance. The test allowed a residual of `3 * width` = 384. But one hidden unit of the control MLP costs `3 * width * layers` = 2,304 parameters, so rounding to the nearest width can leave up to 1,152. The solved control has `mlp_hidden` 395 and 1,370,496 parameters, which is +488 over the arm and fails the old bound. The test has carried this since it was written; it went unnoticed because the test target did not compile.

**Change:** the bound is now half a unit (`3 * width * layers / 2`). The control's solved width (395) and count (1,370,496) are frozen. The doc comment is corrected. There is also a short entry in `current-state.md`.

**Proposal for the owner (not done here):** the [3 October direction](https://github.com/UOR-Foundation/uor-r4/issues/820#issuecomment-5971681179) says no transformer baselines. On that basis the `arm=transformer` control and this test could be retired. I kept them because they reproduce earlier recorded control results, and removing them is the owner's call.

## Result

Test-only fix; no model change. Decision: KEEP the frozen geometric count.
