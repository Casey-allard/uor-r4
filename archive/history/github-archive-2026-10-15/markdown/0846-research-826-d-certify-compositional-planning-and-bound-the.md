## Body

Parent tracker: #826

## Context

A learned transition/planner implementation and any optional geometric arm require one untouched, production-path verdict across generalization axes, horizons, controls, and resource limits.

## Problem

A headline average can hide entity/template memorization, short-horizon success, invalid intermediate steps, oracle leakage, or a reference-only path. “General reasoning” is broader than any planned benchmark.

## Goal

Run the frozen benchmark without retuning, verify every production plan witness, choose the strongest eligible mechanism, and publish a precise promoted, limited, or negative claim.

## Scope

- [ ] Freeze the exact candidate implementations and identities before opening the untouched partitions.
- [ ] Run entity-, vocabulary-, topology-, composition-, template-, relabeling-, counterfactual-, and horizon-held-out slices.
- [ ] Report exact terminal success, valid intermediate transitions, constraint satisfaction, evidence support, decline, first-failure step, expansions, latency, and bytes.
- [ ] Run retrieval/direct/memorized/shuffled/trivial controls and any promoted geometry under exact equal budgets.
- [ ] Verify plan witnesses independently from model outputs and reject paths containing invalid transitions even if the final text matches.
- [ ] Test prompt-state and selective-decision integration, including unsupported/no-plan decline.
- [ ] Repeat on a second task family/domain and declare multiple-comparison handling.
- [ ] Publish a task/horizon capability table, falsifiers reached, resource envelope, and open limits.
- [ ] Issue `PROMOTE TYPED PLANNING`, `LIMITED CAPABILITY`, or `REASONING NOT ESTABLISHED`.

## Non-goals

- Use fitting/calibration partitions for the final verdict.
- Aggregate away failed generalization axes.
- Call the bounded task suite universal or general intelligence.

## Dependencies and entry gate

Requires sibling A and B final candidates; sibling C may be NOT TRIGGERED or negative. Requires promoted S1/S2/S3 integration and the normative production path.

## Acceptance criteria

- [ ] All thresholds, identities, candidates, and partitions were frozen before final access.
- [ ] Every claimed successful plan has a valid replayed witness and terminal verifier result.
- [ ] Performance clears the frozen lower-bound gate on every required generalization axis and horizon, or the limitation is explicit.
- [ ] The selected mechanism beats all non-degenerate controls under equal budgets.
- [ ] Public docs and conformance state the exact tasks/horizons/scope rather than an unqualified reasoning claim.

## Verification

- [ ] Untouched-partition access/audit log and CID verification.
- [ ] Independent witness/verifier replay and planted invalid-intermediate-path negative.
- [ ] Equal-budget/resource audit and independent statistics recomputation.
- [ ] Actual production R4Engine/CLI/server route test; reference-only results listed separately.
- [ ] Regression replay for prompt causality, selective risk, free-running sequence, deterministic bytes, P-4, and allocation.

## Run contract

- **Metric/current value:** Frozen exact valid-plan/generalization lower bound across required split axes and horizons, with witness validity and resource budgets mandatory; current value is set by sibling B before final access.
- **Reachability ceiling:** Representational coverage × within-horizon reachability from sibling B, stratified by task/split; publish the maximum achievable success before launch.
- **Pinned identities:** Untouched benchmark partitions, verifiers, all candidate artifacts, normative scorer/binaries, state/selective configs, seeds, hardware, raw traces/witnesses, and reports.
- **Nulls/falsifier:** Retrieval/direct/memorized/shuffled/trivial controls, strongest non-geometric baseline, any eligible geometry, second domain/task family.
- **Binding cheap instrument:** CID/access audit, control non-degeneracy, witness verifier, production reachability, and ceiling above the effect floor all pass on non-final fixtures.
- **Exit rule:** Promote only if every mandatory generalization/horizon lower bound, witness-validity rule, non-regression gate, and resource envelope passes without retuning.
- **If positive:** Freeze the measured typed-planning capability for instruction/release work and publish its exact boundary.
- **If negative:** Publish LIMITED CAPABILITY or REASONING NOT ESTABLISHED, retire failing mechanisms, and do not broaden the claim downstream.
- **Cost estimate:** Post wall time, hardware, repetitions, judge/verifier cost, storage, and blocked release resources.

Post exact values and pass the cheap instrument before a full run. Controls must be non-degenerate; unavailable observations are `UNAVAILABLE`/`null`.

## Compatibility and migration

Certification changes no artifact semantics. The capability record is versioned and binds exact artifacts/binaries; older bundles remain outside the claim.

## Repository conformance

- **Execution scope:** Untouched offline certification of the normative deployed R4Engine planning path; “reasoning” in public claims is limited to the exact typed state-transition/planning tasks measured.
- Preserve applicable P-4, zero-allocation steady state, deterministic bytes/reductions, fixed capacities, bounded work, typed decline/errors, no_std, and replayable witnesses.
- Normative math uses the formal vocabulary; empirical criteria name split axes, horizons, n, uncertainty, identities, and status.
- **Conformance mapping:** RF-01, RF-08, RF-12, RF-13, RF-27, RF-28 plus any built planning/geometry capability.. Existing reference IDs are not deployed-planning evidence.
- Built capability order: IDs TOML → tagged Gherkin → failing marker/behavior test → implementation → regenerated conformance.
- Unselected geometry/planner arms remain reference/open or are retired with explicit gates; generated conformance is never hand-edited.
- Claim-changing results append evidence and reconcile all current summaries.
- Formal or empirical wording must use the exact typed transition/planning scope and horizon.
