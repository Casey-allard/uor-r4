## What changed and what was learned

The previous pending byte query accumulates XOR and therefore loses order. The new typed query retains forward and reverse signed H4 products at every prefix occurrence. Each actual emitted byte updates that pending geometric history; a subsequent Read commits it. Canonical prime token identities remain alongside their exact positions, separately from geometric comparison. Two product channels are not a paired-H4/icosian lift. Byte leaves can alias; prefix history is not a globally injective byte encoding.

The learner evaluates the 16 combinations of Hold, Right-compose, Left-compose and Replace for two shared channels. It minimizes actual generated token mismatches, length discrepancy and exhaustion over 256 training examples. Only `[Right, Left]` attains 256/256 complete training answers. This is discrete empirical-risk selection against fixed canonical key encoding, not joint gradient training, learned semantic geometry or a scalable general optimizer. No expected source path or development answer enters fitting.

The existing learned action policy, byte/EOS writer and advance operator remain frozen. The recurrent transition is generalized over query type; the old byte-query adapter retains its original learned reader, while the new prefix-query adapter uses fixed hemisphere-signature Hamming comparison against all four supplied keys. A unique zero-distance key offers a payload. This is strict structural compatibility, not a learned relevance kernel or proof of absence. Canonical identities are not used as semantic distances or answer selectors.

The same read/emit/stop transition implements both adapters. New inference uses bounded group-table reads, XOR/popcount, integer accumulation/comparison and the retained writer/actions; it has no transformer, mathematical matrix product or provider response. Geometry construction is host work. Bounds are four source reads, 128 prefix occurrences, 128 output bytes and 160 transitions, with exhaustion reported as failure. This diagnostic implementation allocates bounded vectors/traces and recomputes supplied key geometry; no allocation-free kernel, complete-path speed or energy claim follows.
