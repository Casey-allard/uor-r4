### P2 — Empty matching StraightThrough tensors still reach division by zero

The public `straight_through` entry checks F32 and matching shape but permits a shape such as `(0, 4)` (`geometric_stack.rs:2082–2091`). The Metal implementation also checks shape, dtype and layout, but passes `elem_count() == 0` onward (`2042–2063`). `call_straight_through` then calls `linear_split` with that zero length (`metal_stack_kernels.rs:587–603`). `linear_split` calculates `width = min(max_threads, 0) = 0`, then `0.div_ceil(0)` (`23–26`), which panics instead of returning the promised error result.

This is not protected by an assumed earlier zero-size allocation failure: the inspected Candle 0.9.2 `MetalDevice::new_buffer` forwards the byte size to its allocator, which either reuses an adequate buffer or maps zero to a nonzero allocation via `size.saturating_sub(1).next_power_of_two()`. Local dependency source: `/Users/casey.allard/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/candle-core-0.9.2/src/metal_backend/device.rs:172–179,228–243,269–270`.

**Source-derived trigger, not executed:** create two matching empty F32 tensors on Metal and pass them to `straight_through`. The current CPU rejection fixture already constructs an empty F32 tensor for SwiGLU, but tests StraightThrough only for wrong dtype (`metal_stack_ops_parity.rs:815–839`).

**Minimal repair:** explicitly reject empty inputs at the public boundary and retain the guard at the raw Metal dispatch boundary, or deliberately implement an empty-output path that performs no dispatch. Add the corresponding focused regression. If rejection is the chosen contract, its public-boundary regression can be CPU-only; any Metal check still requires normal admission after the hold. No broad suite or new kernel implementation is requested.

The implementation remains **partial operation acceleration**, not a qualified complete GPU training path:

- `StackModel::attention` requests `rope=true` (`geometric_stack.rs:700–709`), while its geometric read requests null and age features (`751–760`). These modes correctly fail closed in the current Metal FusedRead implementation. The report already discloses the supported Dot/no-null/no-age/no-RoPE mode at lines 66–72. Implementing the other modes is not a prerequisite imposed by this review; project planning must simply not assume these full stack routes are now available on Metal.
- Recurrence forward still reads parameters to the host to prepare `log_a` (`3104–3112`), and recurrence backward runs its host-vector path (`3143–3146`). FusedRead backward also reads host vectors (`3887–3890`). CrossEntropy forward retrieves row losses for a host reduction (`4684–4696`). These boundaries do not invalidate scoped kernel correctness, but they prevent describing the entire training path as GPU resident or transferring operation timings directly to end-to-end speedup.
- The report's opening claim of parity across all forward/backward tests is at most a historical small-fixture claim pending its underlying receipt. It is not current exact-head validation, general gradient qualification, language capability, serving performance or whole-path energy evidence.
