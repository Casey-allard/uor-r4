# ML/attention specialist: compact reconstruction instructions as a native read substrate

Source pin: `88c413599b805373b307035ee722ae8cdd1efea3`. Read-only source review and mathematical derivation, 14 October 2026. No model execution, training, new CUDA qualification, or implementation benchmark was performed for this memo. The supplied attention note is assessed as a proposal, as the owner requested. Existing recorded measurements are named as such. All paths below are relative to this worktree.

## Finding first

The user's architectural idea is coherent: a compact instruction/reference can be the object attention selects, provided that its interpretation is fixed and the information needed for the query is either in the descriptor or accessible through exact backing objects. The receiver need not expand every object merely to decide which object to inspect. This is a useful systems proposal even when the compact instruction is short because both sides already possess the same dictionary or geometric operator tables.

There are already two unusually concrete bridges in UOR's current implementation: every persistent 8-coordinate model block belongs to a 16-member root alphabet, and the current Flock selector compares only one of those 16 frame roots plus exact ordering metadata. Those restrictions permit exact compact state encodings and, for the existing Flock comparison law, exact sufficient candidate indexes. They are more immediate connections to the owner's idea than an entirely new oscillator head. A phase/synchronization read is also a coherent candidate, but it would be a distinct learnable read law whose utility remains unmeasured. There is no reason to make adopting it a prerequisite for investigating the compact representation.

## What the current vectors actually represent

`discrete_encode` copies a token's learned codebook row into device vectors; it does not construct a reversible byte codec (`src/discrete.cu:268–270`). `CarriedBatch` deliberately retains device token IDs, full token/occurrence/record/version identities, valid lengths, model binding, and codebook epoch alongside those vectors (`src/device.rs:177–188,761–817`; `src/lib.rs:116–124`). Vectors from an old learned epoch are refused (`src/device.rs:690–694`). Thus the exact object identity is present in the combined carrier, but it is not generally recoverable from the geometry alone.

This is observable in existing evidence, not a hypothetical objection. The original V4096/B4 initializer has only sixteen full-vector patterns, each shared by 256 token identities; the retained pilot diagnosis derives the partition from the initializer and corroborates it with recorded GPU snapshots (`docs/labs/a2-pilot-diagnosis-2026-10-14/README.md:63–84`). A newer standalone constructor reports distinct vectors, but even an initially injective codebook is not automatically kept injective by learning. The existing diagnosis explicitly distinguishes initial uniqueness from a permanent no-merging constraint (`:95–101`).

The ternary metadata retains all leaf indices and all ordered child links. Its validation walks the forest and proves coverage/order of the retained atoms; it is not merely a final snapped geometric root (`src/metadata.rs:26–70,103–176`). In Flock, the geometric parent payload is a transported sum snapped back to one of sixteen roots (`src/discrete.cu:139–154`). That geometric parent is a lossy read summary, while the retained children can still support exact reconstruction or finer inspection. These are compatible roles and should be documented separately.

Answer to “are we already compressing our tokens into vectors?”: **we encode tokens into learned geometric states and retain exact identities separately. We do not currently implement the supplied reversible byte-compression scheme as that encoding. However, the geometric states themselves admit a much smaller exact encoding than the current expanded coordinate storage.**

## Immediate exact representation opportunity

The build constructs precisely sixteen roots in the anchor's orbit under the 64-state signed-axis group, and validates that every compiled transport stays in that orbit (`build.rs:179–238,256–282`). The model loader validates every codebook block against those roots (`src/discrete.cu:346–350`). Route output is an action applied to an admitted root, Flock output is snapped to an admitted root, and codebook updates apply a group action (`src/discrete.cu:64–71,196–198,341–343`). Therefore every persistent block can be represented exactly by a four-bit root index under the pinned root ordering.

For V4096/B4, the current codebook geometric payload is `4096 × 4 × 8 × 4 = 524,288` bytes of i32 coordinates. Four root labels per token require `4096 × 4 × 4 / 8 = 8,192` bytes, a 64-fold reduction of **that geometric payload only**. A B4 carried vector is 128 bytes as expanded coordinates versus two bytes as packed root labels. This excludes token/occurrence/version identity, schemas, codebook/geometry versions, indexes, buffers, and decoder tables. It is a derived representation size, not an implemented artifact size or measured speed/energy saving. A token ID is already only twelve information bits at V4096; replacing that ID with a sixteen-bit geometric tuple would not itself compress token identity.

The corresponding exact operations need not decompress all vectors:

* Transport: `apply_root[action_id][root_id]`, a 64×16 finite action table derived from the existing signed-axis action. This is a lookup of a geometric group action, not evaluation of a learned dense coefficient map.
* Distances: fixed 16×16 L1/Hamming tables derived from the actual root coordinates. Per-token distance remains the sum of block distances, preserving existing tie rules.
* Flock combination: decode the handful of selected roots into eight bounded integer coordinates, add/subtract as presently specified, and snap using the present exact law. No table covering all possible large histories is implied.
* Writer: endpoint root labels identify its 256 cells directly; full-vector ranking uses the same per-block distance law. The existing writer contract and learned state can remain semantically unchanged.

Required proof/qualification is an operation-preserving diagram, not a tolerance: decode after packed transport equals existing transport after decode, and the writer/read/proposal decisions coincide for the same state, epoch and exact identities. Small primitive action-table correspondence can be reviewed exhaustively; model-path parity remains GPU qualification under its own FIT sheet. Packing changes memory transactions and adds unpacking/index costs; no throughput outcome follows from the payload arithmetic alone.

## How the existing heads and writer work

The “weight sets” in this model are not necessarily large dense coefficient arrays. The learned parameters currently include token-block root choices, Route's per-block/per-stage action choices, or Flock's per-block/per-level ternary gates (`src/lib.rs:125–131`; `src/training.rs:224–242`).

Route takes the last valid token as query. Learned frames transform that query to choose fixed geometric ports down the retained ternary forest; the composed BFS action transports one reached leaf payload per block (`src/discrete.cu:41–76`). Port selection is based on query geometry and port geometry, not on comparing every leaf's semantic content. That makes Route a concrete geometrically controlled access law, with expressivity to be assessed on its own merits.

Flock builds frame/payload summaries for real nodes, then selects K earlier candidates independently at each tree level. It ranks by frame L1, frame Hamming, recency descending, and node ID ascending; it transports selected payloads into the query frame, snaps their sum, and uses learned ternary gates to add, ignore or subtract each level's consensus (`src/discrete.cu:106–198`). Current Flock uses the actual BFS transport but does not use BFS path length as an additional ranking factor in this implementation. The query token and any node containing it are excluded from the candidates by the causal eligibility condition at lines 165–168.

The shared writer admits the nearest occupied endpoint-root cells, then ranks every token identity within those cells by full-vector distance. It does not insert the answer into admission (`src/discrete.cu:208–252`). A better read cannot recover a correct output token which its final writer does not admit. The pilot's recorded admitted targets fell from 5,680 to 2,180 of 14,287 while top-8 hits increased; this is why a new attention evaluation must report admission and ranking separately (`docs/labs/a2-pilot-diagnosis-2026-10-14/README.md:32–47`). That measured observation neither rules out Flock nor selects a replacement: the pilot arm was Route and did not test this proposed phase law.

Learning currently tries exact finite parameter alternatives through the same read/writer, keeps the unchanged state on ties, and applies only a strictly lower objective with the expected model epoch (`src/discrete.cu:280–345`). A new head can reuse that protocol. It would need an explicit new parameter kind and candidate law; it does not require reinstating gradients, Adam, cross-entropy, or floating-point instruments.

## Interface A: exact compact Flock, followed by selective reconstruction

This is the least speculative native interface. Retain exact DAG/occurrence identities, store geometric payloads as root labels, and maintain a candidate index sufficient for the existing Flock law. The math specialist supplied an exact compression of the candidate search: for each payload block, tree level, causal cut and codebook epoch, retain the first K eligible nodes for each of the sixteen frame roots under `(recency descending, node ID ascending)`. The union has at most 16K candidates. It contains the original global top K for every query frame: any omitted node has K nodes of its same frame ahead of it under every query's first two equal distance keys. This is a derived exact result, not a measured implementation result.

The selected candidates carry root payloads, occurrence/span metadata and exact backing references. Transport and combine use the existing law; the writer and learning objective can stay fixed. This makes a compact descriptor genuinely sufficient for the current query operation, rather than assuming that a short arbitrary summary preserves everything. A bounded retained candidate cache does not make the backing exact history disappear.

For incremental inference at a fixed learned epoch, the index can be updated with new eligible atoms/ternary parents. For training, a token-block proposal may affect every occurrence of that token and their ancestor summaries. Cache invalidation or exact counterfactual recomputation must be included in the qualified law and measured cost; this is not automatically O(log N) per learned codebook update. Identical content in different positions remains separate occurrences, since recency, causality and multiplicity matter.

The more ambitious extension is hierarchical descriptor selection followed by lazy expansion of only promising child subtrees. That is a legitimate new read. Exact equality to a full leaf selector requires certified subtree bounds or a proven query-sufficient summary; Flock's present snapped consensus alone is not such a certificate. It is also acceptable to define the hierarchical read as a new bounded access law and test its language/task behavior fairly. It must not be advertised as identical to full search without the proof.

## Interface B: discrete relational synchronization over descriptors

The proposal's valuable new idea is an interaction law: attention can emerge from a query-conditioned network of coupled states rather than independent scalar ranking of every memory item. Compression/transport supplies identities, compact states and lawful transitions; synchronization supplies a potentially different selection/composition rule. One does not establish the other, but they can be composed.

A D32-compatible candidate can keep a finite geometric state at each selected descriptor, pin the query state as an anchor, and use a bounded sparse graph: query-to-frontier links and retained FBS parent/child links, with explicitly bounded additional relation links. Learned edge-type/head/level parameters select ternary couplings or a finite geometric action. They should be shared by declared structural roles, rather than silently introducing one learned unconstrained coefficient for every pair of context positions.

An illustrative exact energy is a sum of source-bound integer unary and edge costs. A unary term ties each mutable state to its descriptor's input frame; another relates candidates to the anchored query. A pair term measures exact geometric displacement after the two declared finite actions, with a ternary relation coefficient implemented by sign/zero. The state updates try a declared finite set of geometric moves and accept only strict energy descent, using a fixed traversal and tie rule. Finite integer state/energy plus strict descent prevents a state cycle; it does not prove a global optimum, relevance, or acceptable settling time. A declared sweep/move bound makes execution bounded even when local settling is slow.

This is a finite geometric synchronization head inspired by the note. It is not an assertion that a 64-state noncommutative action group is identical to continuous Kuramoto phases on S1. If literal phase angles or 120-degree triads are material to the hypothesis, the phase alphabet, exact cost table, orientation map into SpiralCore actions, and frustration behavior must be specified and reviewed. Replacing sin/cos by an arbitrary table while retaining the continuous theorem would not establish the intended mechanism.

After settling (or the explicit bounded stopping point), the head emits an ordered list of selected descriptor identities and declared transport actions. Their payloads are fetched or locally reconstructed, transported through the existing SpiralCore action, combined through a defined integer law, and passed to the current shared writer. A conservative first implementation can use synchronization only to rerank a pinned candidate set, keeping the existing payload transport, combination and writer. A later experiment could let it control admission; those are different causal changes and should be distinguishable in receipts.

Critical constructive questions are whether the input anchors prevent trivial all-aligned collapse, whether different query/content inputs change selected descriptors, whether signed relations distinguish agreement from conflict, and whether the new interaction adds information beyond the existing frame metric. These require designed controls, not a universal PAS threshold. Phase agreement alone is not a grounding oracle: identically represented incompatible claims can agree in phase. Retained exact provenance lets the model retrieve the evidence needed to distinguish them; it does not automatically make their relation learned correctly.

Multi-head composition can reuse the current B-block representation: each head has its own declared read/coupling controls and contributes root payloads through ternary gates and an exact combine law. Alternatively heads can feed distinct typed block families, with an explicit bridge to the existing writer. Geometry may impose useful separation, but hard-coding seven roots/families as “grammar” and eight as “semantics” is a hypothesis requiring task evidence. A full 240-root/fifteen-orbit extension is additional representation work, since the present read/writer operates in one sixteen-root orbit. It should not be silently folded into the first phase-head experiment.

## Compression before tokenization

For transport/storage, yes: encode the original bytes into the Showcase-style exact instruction DAG, send the descriptor and any receiver-missing dependencies, reconstruct the exact bytes, and apply the unchanged tokenizer. If reconstruction returns exactly x, then tokenizing the reconstruction returns the same tokens as tokenizing x, assuming the same deterministic tokenizer/configuration. This achieves a compatibility loop with the present language model; it does not by itself change its attention complexity or semantic quality.

For native compressed-domain attention, there are two distinct input contracts:

1. Preserve token semantics while storing the source compressed. Retain a reliable mapping from token/occurrence spans to byte ranges or DAG objects; read compact geometric descriptors and decode selected content only when needed. Token boundaries can cross byte-chunk boundaries, so incremental tokenization or boundary metadata must reproduce the pinned tokenizer exactly. Model/geometry summaries are versioned derived data alongside immutable exact objects.
2. Make reconstruction operations themselves the learned input alphabet, such as typed reference, literal, concatenate, transform or repeat descriptors. This is a genuine new model representation. The system can still emit ordinary tokens through the existing writer, but the read must learn a mapping from instruction structure to useful output states. Compressor choices, chunking, and shared dictionary versions become model-input semantics; identical decoded text can have multiple instruction forms. Canonicalization or an explicit invariance target is therefore necessary for any claim that the model is reasoning about the same content independently of incidental encoding.

Neither requires the impossible assumption that a fixed tiny instruction reconstructs every arbitrary source with no shared state. A useful shared decoder and dictionary are a valid part of the architecture. What must be measured is the complete conditional cost: descriptor bytes plus missing dictionary/object bytes, decoded working set, index maintenance, read/update computation and output quality. Repeated/shared structure can make that a favorable trade; the current evidence does not determine the task-level trade yet.

Learning compact geometric token states and learning an exact compression program are also different optimization problems. The current learner changes a finite codebook to improve writer/read objectives; it does not search for short exact programs that reconstruct arbitrary training bytes. If program induction is desired, its exact decoder and lossless acceptance condition must be separately specified. No such change is required merely to use an already exact codec as storage or transport.

## Evidence and a fair staged assessment

The source-derived packed-root and candidate-index bridges should first have exact construction controls: root/schema identity, action and distance equivalence, stable ties, occurrence multiplicity, causal cutoff, writer admission equality, stale-epoch refusal and deterministic missing-dependency behavior. Exact parity here is meaningful because the claim is unchanged computation, not approximate language quality. A speedup or resource saving then needs measurements including table/index/decode overhead at real shapes.

A new relational synchronization read needs construction controls for query sensitivity, nontrivial selection, signed-edge behavior, bounded termination, deterministic ties, causal isolation, exact transport, and invariance to descriptor repackaging where that invariance is claimed. A finite fixture proves these defined behaviors, not grounded conversation.

Language assessment then needs a trained-in configuration and the standing independent FIT/owner release gates. Preserve the same data/response masks, writer and evaluation lineage wherever the causal question permits. Report target admission, conditional ranking, exact loss components, useful-reply/grounding results and fresh transfer, with measured full learning/evaluation cost. Use an unchanged-read packed implementation as a representation/control path; use the current Flock read as the geometric candidate comparison if it is the relevant arm. Do not require a prohibited transformer/softmax baseline. A failure should localize representation, admission, interaction, optimization or infrastructure, rather than declaring the whole geometric mechanism invalid.

The supplied SIOPL draft provides a good telemetry vocabulary for this work: source IDs, selected versus rejected candidates, actual actions, missing dependencies, model/decoder versions and direct observations. The “lawful but unselected” outline likewise supports distinguishing a lawful implementable head, a reachable implementation, a functional measured head and an actually deployed configuration. Neither conceptual document substitutes for the missing task evidence, and neither needs to be dismissed for not claiming such evidence.

## Cross-specialist discussion recorded

The math specialist supplied the exact sixteen-frame shortlist argument and required either query-sufficient summaries or sound pruning bounds for full-search equality. The networking specialist agreed that descriptor-native selection is implementable and specified decoder/basis/operator schema binding, immutable object IDs, separate occurrence/span/version identity, model-epoch summaries, and typed missing-dependency fetch/retry. These are compatible with the ML proposal. The shared store is an architectural asset, while receiver misses and stale learned summaries are explicit state transitions rather than model negatives.

Open question for physics and systems integration: what property of continuous phase synchronization is essential to the proposed advantage, and can that property be realized by the exact finite geometric head without merely renaming the current metric ranking? That is a constructive design question. Current evidence supports investigating the compact native substrate; it does not yet select the oscillator law over Flock or show that Flock is inadequate.
