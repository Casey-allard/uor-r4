# ML adversarial cross-review of the integrated native-descriptor proposal

Reviewed source: `88c413599b805373b307035ee722ae8cdd1efea3`. Reviewed documents: `local/swarm/integrator.md`, `parent-challenges.md`, `physics.md`, and `docs/labs/spiralcore-native-attention-review-2026-10-14/README.md` as present during this pass. No model/reference execution or qualification was performed. This is a constructive source/design review, not a TEST FITNESS verdict.

**Assessment: the basic architecture is coherent.** Exact objects and reconstruction instructions can remain compressed while a model reads compact geometric annotations and selects the portions to materialize. An exact implementation of today's read and an interaction-based new read are distinct viable designs. The integrated report correctly keeps their evidence separate. A complete finite design card is the next meaningful artifact; there is no basis here to adopt or reject a replacement attention law.

## 1. The novelty claim needs to be about selection, not all interaction

The report is right that current Flock independently ranks each candidate using its frame distance, coordinate Hamming, recency and node ID. But current Flock is not devoid of candidate interaction: it transports and combines three children into parent payloads, and combines selected payloads into a level consensus. A change to another candidate can therefore change output even with unchanged ranking. Calling every output change proof of a novel relational head would be a false discriminator. [Current parent aggregation](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L139), [current selection and selected-payload combination](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L165).

The proposed novelty should be stated narrowly: **candidate-candidate relations can change which immutable evidence references are selected, while their existing query-distance/tie keys stay fixed.** This distinguishes new relational selection from the present payload aggregation. It does not imply the existing learned representations cannot already solve useful relational tasks.

Use two separately labeled construction controls:

* A synthetic edge-on/edge-off control fixes the candidate pool, order, query, per-candidate frame/payload and readout law. Only a declared pair relation changes. Verify the exact selection effect predicted by the chosen finite law. This proves implementation sensitivity to interaction, not that the relationship can be discovered from language.
* An end-to-end causal-input control supplies paired prefixes whose explicit, observable relation structure differs and whose independent Flock ranking keys remain the same. The actual graph-construction path must derive the changed relation. Compare selected exact references, not only final output. If the relation is manually injected using the answer, the result remains a synthetic controller fixture and cannot be called learned relational understanding.

An irrelevant relation, a missing relation, opposed relevant evidence and an unchanged-relation repeat should accompany the positive case. These are causal discriminators rather than arbitrary numerical thresholds. A later task assessment must establish whether the relation-generation mechanism generalizes.

## 2. Inner settling, readout, and outer learning are three contracts

The physics review correctly separates synchronization energy from the task objective. The finite design card must also separate the settled state from the selection/readout. A controller can decrease its energy, and still leave every selected reference unchanged; alternatively it can select different references while worsening writer admission or task loss. None of those observations is interchangeable.

Before FIT, specify:

1. The finite state alphabet, unary/pair energy, input/query anchors, sparse graph, update schedule, tie policy, stopping rule and bounded-work receipt.
2. The deterministic mapping from controller states and immutable evidence to ordered references and transport actions. In particular, state when opposed evidence is retrieved rather than rejected. Avoid using universal phase agreement as the desired answer.
3. The learned parameter inventory and its outer objective through the actual shared writer. Specify exact virtual alternatives, learning eligibility, baseline conditions, invalidation and acceptance rules. The existing learner evaluates virtual changes through the complete read/writer and accepts strict improvement at the expected epoch. [Counterfactual path](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L280), [choose/apply](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L308).

The learning schedule matters materially. Today vector coordinates are scheduled before Route or Gate coordinates. Adding a coupling parameter type without a dose/schedule that attempts those slots would not test a trained-in head. Report attempted, sensitive and accepted proposals by parameter family. [Current coordinate schedule](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/training.rs#L224).

Keep candidate-pool admission, relational ranking, payload combination and writer admission separately observable. The existing writer admits cells before ranking tokens inside them; improving relation energy cannot create an absent candidate or an unadmitted token. [Writer](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L229).

## 3. The relation graph and compressed backing store need a causal access contract

“No target argument to the controller” is necessary but insufficient. A compressed object may contain the complete document, including future tokens. A descriptor's learned summary, object length, dictionary construction, relation links, version lookup or cached controller state could expose information from outside the declared prefix even if the selected payload itself is earlier. Content addressing does not by itself make access causal.

For unchanged model semantics, build the read-visible candidate graph and summaries only from the exact permitted prefix and pinned pre-existing artifacts. Whole-object storage can still retain future bytes, but the access/annotation interface must enforce the span boundary. If any extra metadata is intentionally visible, it belongs in the declared model input contract rather than an implicit exception. Model-specific learned dictionaries or annotation statistics must bind their training/source scope; DEV answers or future suffixes cannot determine relation weights or candidate eligibility.

The construction control should hold the visible prefix and permitted artifacts fixed, alter the suffix and withheld target independently, and verify identical candidates, graph, controller trace, selected references and predictions. Loss values may change when the target changes, because the target legitimately enters the objective; the read and prediction may not. Also test an otherwise valid backing node whose span crosses the causal boundary. [Current caller-bounded prefixes](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/device.rs#L708), [current Flock exclusion](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L165).

Sparse output degree alone is also not a resource guarantee. The graph generator must name how it finds the bounded edges; an all-pairs search followed by truncation still incurs all-pairs construction work. An explicit typed relation from the input format is a lawful feature. A hidden parser/oracle that supplies the answer relation is a different model component with its own provenance, restrictions and measured cost.

## 4. Exact byte storage and the current token BinderPlan must stay distinct

The exact-index proposal depends on the current token ordering, node grouping and level eligibility. A 32-byte Showcase storage leaf is not a token, and a deduplicated storage node is not a unique occurrence. Replacing the model's BinderPlan with storage chunk groupings would change current Flock's candidate set, parent summaries and tie IDs. That would be a new read/representation, not a parity-preserving storage optimization. [Token BinderPlan construction and ordered coverage](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/metadata.rs#L26).

Use a binding between token/occurrence spans and backing byte-DAG objects. Keep canonical model node IDs for the existing comparison law. The byte DAG may deduplicate and rechunk independently, while the model retains its canonical token grouping. If a later instruction-native model intentionally attends to program structure, register that as a new input contract.

For content-only behavior, test two equivalent reconstruction programs with different chunk boundaries, dictionary IDs, reference sharing and cache warmth. Their decoded token/occurrence sequence and model-visible descriptors should be identical, or the explicitly promised output should be invariant. Fetch counts and latency may differ. Raw storage hashes must not accidentally become semantic distances or tie keys. If reconstruction-program structure is intentionally informative input, exact content invariance is not automatically promised; instead state that choice and assess transfer across encodings.

## 5. The exact Flock cache is conditional on virtual proposals and complete observables

The sixteen-frame top-K proof preserves selected references under the present comparator. To claim complete trace parity, also retain the total eligible-node count per block/level; a short retained list does not itself recover that count. Preserve the original tie order and actual kept count, including levels with fewer than K candidates. [Flock trace fields](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L112), [eligible count and trace write](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L167).

The committed epoch alone is not a sufficient cache key during learning. `input_block` and `table_block` apply candidate-specific virtual actions before commitment; several different hypothetical states share the same epoch. A VectorBlock proposal can change every occurrence of one token, ancestor payloads, frame-based selections in other blocks, and writer-cell occupancy when an endpoint block changes. [Virtual input/codebook overlay](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L24), [frame pairing](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L106), [virtual writer cells](https://github.com/UOR-Foundation/uor-r4/blob/88c413599b805373b307035ee722ae8cdd1efea3/crates/uor-r4-discrete/src/discrete.cu#L220).

Bind caches to source/model/geometry identity, the actual BinderPlan/window, causal cut and the exact virtual proposal overlay, or prove a narrower dependency-specific invalidation rule. Gate-only proposals can reuse selection and node payloads because the current gate changes their combination, but the final read/writer result still changes. Endpoint-root proposals also require correct writer occupancy/admission, even if a read cache itself is valid. Missing or stale dependencies need repair/refusal rather than silent fallback values.

These conditions do not defeat compact-native computation. They identify what must remain exact for it to represent the current computation faithfully, and which costs a performance measurement must include.

## Required additions before a finite FIT review

The integrated report is appropriately a feasibility review. The next card must choose the state law; pin causal candidate and graph construction; define decoder/occurrence/token bindings; specify readout and actual learning slots; enumerate complete cache/proposal dependencies; distinguish inner settling from outer acceptance; set bounded execution and missing-state behavior; and name the constructive and adversarial controls above. C6 versus G64, byte storage versus token grouping, and exact parity versus a new approximate read are genuine design choices to expose, not technicalities on which to dismiss the idea.

I recommend adding the selection-novelty qualification, suffix/target isolation control, explicit learning-slot exposure, byte-DAG/token-BinderPlan distinction and eligible-count/cache requirements to the synthesis. With those boundaries, the architecture remains a credible candidate for a small, falsifiable design card. The review supplies no language improvement, throughput result, replacement decision or training authorization.
