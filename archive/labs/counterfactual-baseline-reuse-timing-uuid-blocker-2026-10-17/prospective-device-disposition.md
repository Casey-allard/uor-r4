# Prospective physical-device scope assessment

This is a separate design assessment after the closed timing2 setup refusal. It changes no consumed packet/release and authorizes no rental or dose.

**A future explicitly reviewed packet may reasonably admit a different physical UUID within the same declared RTX5090/sm120/exact595.71.05 class, while retaining strict own-AOT admission and all original paired controls. Exact physical UUID is not intrinsically necessary for the causal U-versus-R comparison.** This is a proposed prospective disposition, not an approval of an unprepared packet or a claim that an unobserved GPU is finite-qualified.

The physical serial identity does not enter the model or kernel math. Both U and R in the proposed timing comparison run on the same newly recorded actual device, context/runtime and input set; no old-host timing value is the comparator. The accepted finite fixtures support the unchanged implementation at its recorded environment, not a theorem about every other GPU. A newly admitted UUID must be described as the prospective subject of the fixed timing comparison, never as retrospectively the finite3 device.

Real risks are device/board power and clock policy, memory/PCIe/CPU behavior, thermal throttling/contention and runtime-library variation; these can change absolute wall times or favor one allocation/access pattern. Different hardware may also expose faults or scheduling behavior that the previous physical GPU did not. A UUID match alone would not eliminate these risks because clocks/load/libraries can change between leases on the same device. Conversely, a new UUID alone is not evidence of a different kernel result. Record identity and environment, rather than infer performance from the serial number.

Minimum decisive safeguards for a written successor packet:

1. Prospectively pin one RTX5090/sm120, exact driver595.71.05, unchanged source/binary/cubins/report identities and the chosen declared memory/library/image constraints. Record actual UUID/offer/machine/host/VRAM, device capability, nvidia-smi environment and loader mappings; retain actual library hashes and the known missing historical library/image digest limitation. No broad driver-family or architecture expansion.
2. Require both U and R to run on that same actual device/runtime under the one admitted runner lease. Preserve exact original checkpoint/config/bridge and same-policy/window targets. No historical-host timing comparison or resource substitution.
3. Preserve pre-proposal own-AOT resources, static U0/R512, dynamic0, zero spills and block16 launchability; fail closed. Keep exact all16 loss/status/five-word parity for every warmup and measured pair, audit masks/state/epoch/apply checks, partial-fault receipts and unchanged accounting. Do not add a CPU model oracle or tune after observing a failure.
4. Keep the original32 proposal dose/order,12 measured pairs/four cells, all signed differences and strict gap-versus-spread/event/wall/whole bars. No selecting only favorable cells, warmups, devices or repetitions. A rejected/faulted/noisy result is preserved at that actual scope with no opportunistic extra dose. Any benefit remains only a scoped engineering observation on the new recorded environment.
5. Repair the archive-copy omission before rental and check that every frozen manifest member can be reproduced in the archived local-operator tree. Preserve exact guards, renewed live/unknown state, disk/caps/ownership, complete SHA/full-cloud MD5 before down and peer isolation. Finish protected blocked-result delivery/cleanup/hygiene, then get independent sealed readiness and a distinct execution release.

No extra finite model-dose programme is intrinsically required solely because a physical UUID differs if that prospective scope and all existing runtime/parity gates are retained. New implementation, GPU architecture, driver version or weakened predicates would be a different disposition. This assessment supplies no current execution approval and does not imply general correctness, library equivalence, training permission or mechanism-wide speedup.
