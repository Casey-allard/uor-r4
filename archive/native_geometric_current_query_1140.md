## Mechanism and implementation

No serving code, feature representation, parser, admission gate, arithmetic implementation or emission template changes. Literal/derived flags, literal recency, lineage and lexical provenance already distinguish the relevant alternatives. Training changes the shared geometric code roots and a bias; it does not add an answer-family head.

All prefixes are generated by native inference and checked against expected responses before their actual committed write IDs become supervision. Expected response text is never ingested as a supplied intermediate. Independent questions require nonderived operand occurrences introduced in the current query, including when their values equal old literals or computed results. Dependent questions require the actual original generated result; adding extra coins additionally requires the exact new query occurrence. These conditions are offline labels and evaluation checks, not runtime selection rules.
