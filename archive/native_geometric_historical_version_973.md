## Mechanism and boundaries

The witness binds the complete `f0901dad` parent. Serving considers only live directory heads whose exact owner the request names, and walks each such head's immutable `previous` chain through validated links only: explicit revision action, strictly decreasing identity, an existing exact record, matching nonconflicting owner, at most fifteen links. A candidate is a root only when its chain reaches a genuine assertion (`previous == 0`, assertion action), not merely the oldest surviving slot; when later facts overwrite the root slot, no root candidate exists. Every validated ancestor is offered with its exact depth and one of four structural classes (previous, previous root, deeper ancestor, deeper root). The shared signed-H4 selector scores each representable candidate against deferral; deferral leaves the entire parent dispatch, including the frozen immediate-previous reader, unchanged. This is bounded source arbitration over exact records, not an expert network and not a runtime keyword rule.

The selector's lexical view is the request after the latest committed owner/value endpoint, as in the current-record handoff. Its dictionary is built from those request views of the construction prompts, capped at 128 entries, and a word receives a prime identity only when it occurs in at least two distinct construction views; a spelling confined to one prompt, however often repeated there, stays at zero, like a fresh word. Query words matching the candidate chain's owner enter as a fixed role sentinel, and words matching a competing live head's owner as a second non-prime sentinel, so owner role rather than spelling reaches the geometry. Features are the inherited owner-context features, ordered request context over sixteen words, request words paired with the candidate class, and the candidate's depth and view length by class. Training labels contain prompts and exact ancestor record identities or explicit deferral; they contain no response strings. Only new outer code roots are learned. Serving uses bounded transport, integer scores and table lookup, with no matrix product, transformer, provider or response template.

The field anchor gains an optional `ancestor_depth`. A one-link proof keeps the legacy wire form; explicit depths start at two. Each dependent owner/value read and every checkpoint restore revalidates the complete path from the live head to the selected record, so a broken, overwritten, cross-owner or shortened path rejects continuation. Owner-first and plain answers read the same selected record.

## Limitations and next implementation

When later facts evict a chain's root, no root candidate exists; the selector defers and the parent's immediate-previous answer is emitted. Explicit abstention for an unrecoverable initial version is not implemented. Intent between the initial and an intermediate version (for example the second of four) is not labeled or claimed. The committed request boundary is not general request segmentation, and these are bounded authored forms with fresh spellings, not temporal language understanding.

Next under #973, learn a NoRead deferral for historical requests whose validated chain cannot supply the requested version, so a truncated history abstains instead of answering with the wrong version, and extend the same selector to intermediate-version requests with exact depth labels. Preserve exact spans, competing owners, revisions, dependency abstention and causal follow-ups.
