# UOR research publication workflow

The research paper is an evidence product. Begin with the repository's normative claim vocabulary and a ledger linking each substantial assertion to a theorem, experiment, source or explicit assumption. Use `docs/integration/claim-ledger.json` and the publication-readiness report when present, then refresh any changing submission rules from official arXiv sources.

1. Select one defensible contribution and intended audience. Record what is original relative to the nearest primary literature, what the algorithm actually computes, and what remains conjectural. The full frontier-product aspiration is not automatically the paper's contribution.
2. Write definitions, domains, quantifiers, assumptions and operator ordering before proof prose. An independent reviewer should reconstruct the central argument and look for counterexamples. For Lean, inspect the actual proposition and assumptions/axioms; constant definitions, dimension parameters or a no-sorry scan do not prove runtime memory, scientific interpretation or implementation correspondence.
3. Bind empirical tables to exact artifact/model/dataset IDs, commands, environment, measured outputs and declared controls. A benchmark generator containing hardcoded browser values cannot establish new browser measurements. Distinguish core throughput from end-to-end token latency, and logical dimension from physical resident memory.
4. Maintain primary-source reading notes with DOI/arXiv version and supporting pages/equations. Use citation-audit tools for claim/entry matching, then verify the referenced work and metadata. Do not invent references or infer support from an abstract keyword match.
5. Write a coherent manuscript: problem and prior art; contribution; construction/theorems; algorithm; controlled results; limitations and negative findings; reproducibility. Check notation, figures, units, uncertainty and consistency between abstract/conclusion and actual results. Keep authorship, acknowledgments and AI assistance accurate.
6. Rebuild the exact source package and inspect its PDF, bibliography and metadata. A stale uploaded .bbl may override the .bib, so reconcile all citation keys. Exclude OS metadata/build debris. Validate the current accepted arXiv TeX/source rules, category and endorsement where applicable. Tool discovery or successful local compilation does not establish submission acceptance.
7. Review actual previous rejection notices and exact submitted versions. Distinguish file-processing defects, moderation, category/endorsement, preview and public announcement. Never guess rejection reasons from missing records. Use the official appeal process if its criteria apply; do not try to route around a rejection through alternate accounts/categories or cosmetic resubmission.

No tool can guarantee arXiv acceptance; arXiv moderation is not journal peer review. Mathematical review, reproducible evidence and faithful claims improve the research itself. Submit only after the user's explicit submission decision; installing this skill grants no such authority.
