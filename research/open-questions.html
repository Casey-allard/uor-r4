UOR-R4

What is still open

The project has built and tested many of the parts of a language model. The few it has trained together (the discrete writer, the reads and the ranking loss) have not yet beaten a simple count table, and a full trunk of lawful parts has never been trained. The biggest open question is simple to state: can a model that uses no softmax learn to rank the right word above the wrong ones? Nobody knows yet. Beside it sits a list of tests that were never run, or that failed only because the test was set up badly. Most of them are cheap, and the cheapest decisive one is FIT-reviewed and queued, not yet released.

Terms follow the glossary. Claims are labelled proof, measurement or hypothesis as in formal_vocabulary.md. Dollar figures are the chief architect's estimates, not recorded costs.

How the output head works, in two lines

The model first picks a shortlist of candidate cells, the nearest K of 256 by address. A row counts as admitted if the right token survives that cut. It then ranks the shortlist and takes the nearest token. So a model can fail at admission, at ranking, or at both. Source: docs/labs/repo-renormalization-2026-10-19/audit/synthesis.md section 1 and K16 outcome.

The central unknown

Can a softmax-free read learn ranking? This is a hypothesis, and the biggest one. Every float read that learned had softmax helping it somewhere in training. The best read without softmax, arm W, is a recorded REJECT. It was worse by 0.0172 BPB (bits per byte) and ran 15% slower, and its gradient came from a softmax-shaped surrogate. The starling read reached recall 0.329 where softmax reached 0.999. Both verdicts close those configurations only (decision D22), not the idea. See findings for the numbers and flock read for the discrete read that replaces them.

What we know today: the best trained discrete model scored top-1 of 65 and 463 of 14,287 development rows, below a unigram count table (1,226) and a context-free successor table (6,300) (measurement, K16 outcome). The cause is open. The record rules out one suspect: aliasing did not explain the ranking failure. It leaves ranking capacity, the read, the address key and the training schedule.

FIT-reviewed and queued

These are the closest to a decision. A FIT review is not an owner release: spending waits for the owner (charter §5.1).

  1. W2, the read-code capacity capture (about $0.91, already reviewed as FIT, same lease). It decides whether the wall is the representation (H_rep: the stored code cannot separate the answers) or the learning law (H_law: the code could, but the update rule does not find it). It also adds the count-table arms that the headline bars lacked. Source: architect review section 6, docs/labs/course-correction-2026-10-18/audits/d37-reactivation-architect.md.
  2. The admission-preserving rerun of A8. Pre-registered and reviewed FIT, never run. Its controller and a separate finite qualification producer are merged. The qualification is NOT_RUN. Source: admission-anchor controller.

Every step that trains also needs an owner release (charter §5.1), and training stays HELD until the owner releases it.

Never tested, moderate cost

  • Ranking with admission intact. No run has had admission intact and then failed or succeeded at ranking (admission).
  • A rank objective that keeps cells occupied. The registered route after the K16-R run collapsed to 19 or 20 occupied cells (rank margin).
  • Full-epoch and frequent-token revisit schedules. One pass sees 43.3% of the training targets (proof, by arithmetic, model training).
  • The finite relational head. K16-A reached its 16,404 batches and can satisfy the prerequisite for the next stage (architect review §5; relation read).
  • Discrete Hamming binding (VSA) on the current writer (VSA).

Never tested, expensive or blocked

  • A trunk built only from lawful parts. Train it with float in a new scanned module, then export. The 24-kernel extract has passed finite controls only (geometric stack). No exporter exists for it.
  • The forced-copy oracle for the pointer. The cheapest decisive pointer test. It needs a lawful pointer first, because running it on the old softmax pointer would execute a banned model (pointer key).

Not yet buildable

The map of lawful parts still has gaps that no test can fill until someone builds them (docs/labs/repo-renormalization-2026-10-19/audit/synthesis.md section 1).

  • Position. No mechanism is assigned. The only related result is about recurrent state, and it is confounded (see findings).
  • Normalization. None is designed.
  • Address as the read. Never built, and nothing yet consumes the object store.
  • A lawful exporter for any trained trunk, so the export gap is unmeasured.
  • A faster writer. The writer scans the whole vocabulary, about 5 million comparisons per row, which breaks the per-token sparsity goal at larger vocabularies (proof, by count, architect review §3.5).

What counts as success for the first milestone

The charter sets the M1 closing bar: integer top-1 through the D11 export beats both count tables on the same development panel, on each of two seeds, with tokens per second reported. A bits-per-byte bar returns later, once a lawful likelihood exists (charter §4.8). That settles the old open question about scoring a model with no likelihood, for M1 only. A lawful likelihood is still unbuilt. A conversation bar (M2) is further off, and a float student would need a new owner decision (docs/labs/repo-renormalization-2026-10-19/audit/synthesis.md section 4, stage 5).
