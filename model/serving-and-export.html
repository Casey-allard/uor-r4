UOR-R4

Serving and export

A finished model must leave the lab and run as an integer artifact on an ordinary device. D11 bans floating-point and transcendental arithmetic and excludes dense matmul; D80 and D81 allow the hardware integer multiply and divide. The saved discrete M1 pair and a separate FBS trunk have now been exported and served. That is not useful-chat qualification or an M4/M7 product release.

Training may use float offline. The integer artifact and its measured export gap are the serving boundary.

Labels: proof, measurement, hypothesis. See docs/formal_vocabulary.md and the glossary.

Two halves with one hard border

Offline training runs on GPUs. The discrete path is integer end to end. D37 permits float only in a separately scanned offline module, with no softmax/squashing or dense matmul and a mandatory export-gap measurement.

Serving runs on the user's device. Its five D11 rules are:

RulePlain meaning
R1No floating point or maths library
R2Integer arithmetic; hardware integer multiply and divide are allowed since D80/D81
R3Reading every stored weight per token is an interim stage, not the D5 end state
R4No transformer backbone
R5Energy is claimed only when measured

Serving an exported artifact on a client device, including browser WebAssembly, is the product and is allowed (charter, section 3.6).

The M1 integer export

The M1 closing model is a 19-table uor-r4.lut-discrete-trunk/1 artifact saved at two seeds. d11_export.rs and trunk.rs build it, and discrete_d11.rs evaluates it in integer arithmetic. It reproduces the reference on all 14,287 DEV rows and passes the planted-fault B4 control.

On p-f, 62.5% of the reference replies are verbatim TRAIN replies: reference-data overlap, not a generated-copy rate or useful-chat qualification (M1 close, Fresh V2, bar-f report).

The separate FBS export

The float-trained FBS trunk exports under lut-stack/5, which keeps rotations exact and puts the export gap inside its bar on both seeds at DEV scope. Earlier lut-stack/4 snapped variants missed that bar; /5 is the passing contract at its measured scope (claude-181, claude-182). /6 carries additional Hamming-read hooks; the joined served session remains open.

The FBS native rates are different measurements from the M1 pair's: 4,217–4,320 tok/s under /5 (claude-182), then 4,491/4,504 after the integer square root (claude-186); and 4,829 snapped under claude-177. Do not substitute them for the M1 pair's 10,876/10,566.

Container and computation

UORLUT01 starts with an 8-byte magic string and JSON header, then aligned integer data sections. The reader validates offsets and lengths and computes SHA-256 as it loads. Table-native schemas include lut-discrete/1 and lut-discrete-trunk/1. The separate FBS lut-stack/5 is a 4-bit float-to-integer stack with exact rotations, not a table-native discrete schema. Older dense lut-stack/1, /2 and /3 families are historical and do not describe the M1 artifact (format.rs).

Exact geometry can be tables: the 120-element icosian Cayley table, Lorentz arcosh values and Q30 Hopf observations. native_geometry.rs supplies typed H4 geometry and checked integer arithmetic; discrete_d11.rs loads table-native discrete artifacts with zero 4-bit matrix sections. Session state uses UR4SESS1 for byte-identical save/restore. uor-chat --discrete also offers a raw-token finite serving path, not text chat or discrete session persistence.

The serving audit

The audit disassembles serving functions and counts multiply, divide, float, vector and matrix instructions. Since claude-175, the FBS stack's audit allows scalar integer multiply and divide and reports their counts, while still refusing float and dense/vector/matrix forms. Other engines keep their declared audit contracts.

  • Native: 44 symbol ranges pass; the stack's step uses the allowed integer operations with no float.
  • WebAssembly: 7 of 7 serving functions pass, with integer operations reported rather than mistaken for decimal instructions.
  • Planted faults and parity checks test that the audit can fail and that the integer computation matches its reference.

The audit proves absence of refused instructions, not model quality. The WebAssembly SIMD kernels remain unintegrated fixtures; the serving path uses scalar table kernels.

Export gaps, old and current

The export gap is the served score minus the float score on the same evaluator and positions. Today's discrete M1 export has zero row gap on the 14,287-row DEV panel at both seeds; the FBS /5 gap is inside its registered band at DEV. These are different contracts and should not be averaged.

Older float geometric stacks had larger gaps. Matched 512-window measurements were about 0.009 BPB, mostly from weight rounding, and three 29M artifacts served at 1.20–1.24 BPB against a 0.90 bar. The older 0.877 float / 0.933 served pair used 512 and 64 windows respectively, so it is not a like-for-like comparison; the separate 19.9M reading of 0.886838 at 512 windows used a different protocol. Those results are historical and do not negate the M1 export or the FBS /5 result. A dense model streamed through tables is still dense, which is why D5 asks for selected addressed reads rather than assuming table lookup implies sparsity.

What remains open

  • M4: select the accepted model and qualify the full quality, CLI, session and audit path. A lawful likelihood (PRLL) is built and registered, but GPU held-out scoring remains open.
  • Joined FBS serving: memory, readout and text/chat distribution are not all in one integer session.
  • M5: full-path memory traffic and energy on the accepted model.
  • M7: library/CLI/browser token and session parity on the accepted model, not only the synthetic stand-in.
  • Addressed/product-key memory: the older exporter refuses it. The real point-key export and p-x run happened, but claude-229 was row 0's instrument fault, not a usable bar result. Claude-231 built the nearest readout on native and browser paths; claude-232 missed greedy parity in every cell, so the p-x rerun waits on localizing the mismatch.

The web client is connected to the current integer worker. DeepSeek's #3442/#3444 rebuilt and published the Studio; #3445 then wired the publicly released M1 trunk for top-8 next-token prediction, and #3446 served /7 integer turn memory on synthetic fixtures; trained-artifact parity and memory-session restore remain open. The M1 model is a language base, not a chat assistant; accepted-model parity remains open. The mdBook workflow publishes preview on main and production only by manual dispatch. This documentation unit publishes neither.
