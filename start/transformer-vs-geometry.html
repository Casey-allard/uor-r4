UOR-R4

Transformer parts and their geometric replacements

In one paragraph. A transformer is built from a handful of standard parts: a tokenizer, an embedding table, a position signal, attention, feed-forward layers, normalization, an output layer, a loss and an optimizer. UOR-R4 tries to replace each part with a geometric or exact mechanism that avoids softmax and matrix multiplication. This page puts each transformer part beside the project's replacement and says how far that replacement has got. The short version: most parts have a candidate, and several candidates are built and tested. Two parts have no candidate at all: position and normalization. No two replacements have yet been trained together into a model that beats simple word-count tables (audit synthesis, section 1).

Each transformer part beside its replacement. Colour gives the status. The two dashed boxes are the gaps.

Terms are in the glossary. Labels follow docs/formal_vocabulary.md: proof, measurement or hypothesis.

How to read the status

Every mechanism has exactly one of three statuses, set on the mechanism board:

  • ACTIVE: on the current model path, crates/uor-r4-discrete.
  • READY: built and tested, but never trained into a model.
  • PARKED: the forms tried so far failed or broke a rule. The mechanism stays open, and its page lists what would reopen it.

There is no "retired" or "dead" status. A failed run closes one configuration, never a mechanism (charter, section 4.1). Today the board has 10 ACTIVE, 4 READY and 13 PARKED mechanisms.

A passing test shows that code does what it claims. It is not a trained capability, and a test marked NOT_RUN is not a pass.

The two gaps

Gap 1: position. A transformer adds a signal that says where each token sits in the sequence. No UOR-R4 mechanism is assigned to this job, and no lawful evidence exists for one. The current model keeps the most recent tokens in order at the leaves of a small tree, so order is present in its layout, but nothing is learned about it (the model page). The nearest result is about carrying a running state by quaternion rotation. It beat no rotation by 0.071 and 0.077 nats (a nat is a unit of prediction error; lower is better), but in a model that still used softmax attention, a sigmoid gate and dense layers, with 332,928 fewer parameters in the comparison arm (transport record). So "rotation can carry order" is a hypothesis.

Gap 2: normalization. A transformer rescales its signals between layers so they stay in a workable range. UOR-R4 has no designed mechanism for this. Snapping each block back to one of its fixed lattice points might play that role, but no record says so or tests it (mechanism board). This is also a hypothesis.

What "replaces" does not mean yet

Having a replacement on paper is not the same as having a working model:

  • No replacement has matched its transformer part on quality. Every attention-style read that learned well in the older decimal experiments had help from softmax during training, and the best softmax-free read was rejected (softmax-free read; audit synthesis (docs/labs/repo-renormalization-2026-10-19/audit/synthesis.md), section 1).
  • No two parts have been trained together except on the current discrete path. That path has no feed-forward layer and no position mechanism, and it scores below a table of word counts (measurement, K16 outcome).
  • Several other things are not built: using an exact address as the read, any consumer of the object store, an exporter that turns a trained model into a D11 file, and an output step that avoids scanning the whole vocabulary (audit synthesis, section 1).

The project does not compare its models against transformers. It compares them against count tables and earlier geometric models, and grades them with fixed, deterministic checks (charter, sections 3.10 and 4.4).
