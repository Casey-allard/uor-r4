UOR-R4

Where UOR-R4 is today

In one paragraph. UOR-R4 is pre-alpha. None of its 8 milestones is complete, and no model built under its rules holds a conversation (STATUS, NOW). Many of the parts work on their own: a whole-number model path on the graphics card, three ways of reading earlier text, one shared word table, a whole-number engine that runs in a browser, and an exact storage system. But the best model trained so far guesses the next piece of text correctly far less often than two very simple tables of word counts. Nobody yet knows why. This page lists what works, what does not, and the measured numbers, each with its source.

Correct first guesses out of 14,287 test positions. The trained model is far below both count tables, and the new M1 bar sits at the higher table.

Terms are in the glossary. Claims are labelled proof, measurement or hypothesis (docs/formal_vocabulary.md). A passing check shows that code does what it says. It is not a trained capability, and NOT_RUN never means passed.

How the model is scored

The test set is 14,287 positions in 400 held-out documents, called the DEV panel (count tables record). At each position the model makes one guess for the next token. A top-1 score counts how many of those guesses are right.

Two plain tables, built from the same training text the model sees, set the floor:

  • The unigram table always guesses the single most common token. It scores 1,226 (measurement).
  • The next-word table (called T2) looks only at the previous token and guesses the token that most often followed it in training. It scores 6,300 (measurement).

Both come from the count tables record. A model that cannot beat them has not yet learned anything a lookup table cannot do. The project compares against these tables, not against transformers (charter, section 3.10).

What does not work yet

No model holds a conversation (STATUS). The detail:

The best trained model is below both count tables. The last full experiment (called K16) trained two variants of the model, each on two random seeds, for 16,404 batches (K16 outcome; all measurement):

VariantSeedCorrect first guessesReach: positions where the right answer was among the candidates openedCells in use (of 256)

Variant A is the one the record selects. Its reach fell below the required 4,894 positions on both seeds. Variant R kept a high reach only by collapsing into 19 or 20 cells, so that each guess was drawn from about 3,400 of the 4,096 tokens, nearly the whole vocabulary; that reach is not real discrimination. The registered verdict was an occupancy collapse (record code OCCUPANCY_COLLAPSE_TRIGGERED), and no run was kept. All four miss the run's own top-1 bar of 1,941 and are far below the next-word table's 6,300. The large gap between seeds (65 against 463) also shows how noisy one run is.

The cause is not established. The first guess was that too few distinct starting vectors were to blame. That is ruled out as the main cause: in variant A, training raised the distinct vectors from 16 to about 275, yet top-1 stayed low (K16 outcome, census section). The candidates still open are:

  • The address key may be too coarse. The key is the distance that orders the drawers. It uses only the first and last block and takes only 5 values (0, 4, 8, 12 or 16) to order up to 256 cells (proof, from the kernel source), so which drawers open is largely decided by their arbitrary numbering (the model page, chief architect's review §3.2). Whether this causes the low score is a hypothesis.
  • The read, the ranking capacity, or the training schedule. One full run sees fewer than half of the training targets: 1,049,856 of 2,425,925 (measurement, audit dossier). These remain hypotheses.

The newest run stopped early. The address-cell run (A8) began with the better reach above, but training eroded it. At its first checkpoint the Relation read held 551 reachable positions, below half its starting 1,351, which triggered the registered stop (the control held 857; measurement, A8 dose). A version that protects the reach is built; its GPU qualification is NOT_RUN (controller record).

No model trained under today's rules has been exported or timed. No exporter turns a trained discrete model into a D11 file (the older float stacks were exported and served in October), and tokens per second for this model have never been measured (lut-serving).

Parts are missing. The current model has no position mechanism, no normalization and no feed-forward layer (transformer vs geometry).

Training is on hold. Each training run needs a reviewed one-page plan and a release typed by the owner personally (charter, section 5).

What about the older models?

Before October, the project trained a decimal-number model called the geometric stack, from 7 million to 214 million parameters. Four 214-million-parameter checkpoints are published on Hugging Face as historical evidence. Their chat versions (which predate today's rules) could rewrite and summarise, while code and arithmetic were wrong (audit dossier, from the model card). That stack used softmax, the SiLU activation (a smooth squashing curve) and matrix multiplication; geometry was about 0.05% of its arithmetic. Served through the integer engine, its best version (19.9 million parameters) reached 0.933 bits per byte and the charted versions 1.20 to 1.24, all missing the old M1 bar of 0.90 (D11 serving record; audit dossier). It breaks today's rules and is PARKED (geometric stack). It shows the project can train a model that writes text. It does not show that the geometric replacements can.

How the project got here

Between 12 and 19 October the owner (project lead Casey Allard) made 19 decisions, several of which rebuilt the model's foundations: no softmax anywhere, no matrix multiplication, GPU-only research compute, whole numbers on the active path. Much of that week went into rebuilding and checking rather than learning. In the week of 12 to 18 October, 34 of 309 records were results; the rest were tooling, plans and reviews, part of it ordered by those decisions. Five training runs on the new discrete path followed, and none produced a kept result (audit synthesis, section 3). The history has the long story.
