UOR-R4

UOR-R4 documentation

Read online (planned; live once the site workflow deploys): https://uor-foundation.github.io/uor-r4/. The earlier Studio web app moves to https://uor-foundation.github.io/uor-r4/studio/.

In one paragraph. This is the map of the UOR-R4 documentation. UOR-R4 is an open research project building a language model that predicts text with geometry and whole-number arithmetic instead of a transformer's large grids of decimal multiplications, so that it can run fast on a laptop or in a browser. It is pre-alpha: 0 of its 8 milestones are complete, and no model built under its rules holds a useful conversation yet (where we are). The pages here explain what the project is, where it stands and where it is going in plain words first, then give the evidence for every claim so an expert can check it. Use the table below to jump to the page that answers your question. The same pages build into a book site, whose table of contents is SUMMARY.md.

How the sections are organised

  • Start (start/): six short pages for newcomers. Each opens in plain words and ends with sources.
  • Products (products/): the three things the project means to ship, and the release format.
  • The model (model/): the current model path, stage by stage, with what is built and what is missing.
  • Mechanisms (mechanisms/): the board and 27 mechanism pages, each with the same template: the idea, how it works, where it stands, and what would reopen it if PARKED.
  • Geometry (geometry/): the mathematics behind the mechanisms, illustrated.
  • Research (research/): how research is done now, findings, open questions, the history, 17 research-line pages and the notebooks.
  • Rules (rules/): the charter explained, where each old decision went, and the change log.

Three directories stay at their old paths because code and tooling read them, and they are not part of the book: integration/ (the live plan NOW.md and the decision index), harness/ (the research harness) and labs/ (governance files and records dated 18 or 19 October 2026). Records dated before 18 October 2026 have moved, unchanged, to archive/.

Conventions used on every page

ConventionMeaning
proofFollows from definitions or code
measurementFrom a recorded run, with its artifact linked
hypothesisAn idea not yet tested
ACTIVE / READY / PARKEDOn the current model path / built and tested but never trained in / the tested forms failed or broke a rule, and the mechanism stays open
NOT_RUNNever run; it is not a pass

The labels follow formal_vocabulary.md, section 2. A passing test shows that code does what it says; it is not a trained capability. There is no "retired" mechanism status: a failed run closes one configuration, never a mechanism (charter §4.1).
