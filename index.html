UOR-R4 documentation

Read online: https://uor-foundation.github.io/uor-r4/. Production publication is by manual dispatch; pushes to main update the preview site. The earlier Studio web app moves to https://uor-foundation.github.io/uor-r4/studio/.

In one paragraph. This is the map of the UOR-R4 documentation. UOR-R4 is an open research project building a language model that predicts text with geometry and whole-number arithmetic instead of a transformer's large grids of decimal multiplications, so that it can run fast on a laptop or in a browser. It is pre-alpha: 1 of its 8 milestones is complete, and no model built under its rules holds a useful conversation yet (where we are). The pages here explain what the project is, where it stands and where it is going in plain words first, then give the evidence for every claim so an expert can check it. How the sections are organised

  • Start (start/): six short pages for newcomers. Each opens in plain words and ends with sources.
  • Products (products/): the three things the project means to ship, and the release format.
  • The model (model/): the current model path, stage by stage, with what is built and what is missing.
  • Mechanisms (mechanisms/): the board and 28 mechanism pages, each with the same template: the idea, how it works, where it stands, and what would reopen it if PARKED.
  • Geometry (geometry/): the mathematics behind the mechanisms, illustrated.
  • Research (research/): how research is done now, findings, open questions, the history, 17 research-line pages and the notebooks.
  • Rules (rules/): the charter explained, where each old decision went, and the change log.

Three directories stay at their old paths because code and tooling read them, and they are not part of the book: integration/ (the one plan PLAN.md and the decision index), harness/ (the research harness) and labs/ (governance files and records dated 18 or 19 October 2026). Records dated before 18 October 2026 have moved, unchanged, to archive/.

Conventions used on every page

ConventionMeaning
proofFollows from definitions or code
measurementFrom a recorded run, with its artifact linked
hypothesisAn idea not yet tested
ACTIVE / READY / PARKEDOn the current model path / built and tested but never trained in / the tested forms failed or broke a rule, and the mechanism stays open
NOT_RUNNever run; it is not a pass

The labels follow formal_vocabulary.md, section 2. A passing test shows that code does what it says; it is not a trained capability. There is no "retired" mechanism status: a failed run closes one configuration, never a mechanism (charter §4.1).

M1 closed 30 Oct; current research through 14 Nov 2026. Pre-alpha, 1 of 8 milestones complete. The saved discrete M1 model scores 7,002 / 7,001 on DEV, 7,215 / 7,228 on Fresh V2 and 7,850 / 7,872 on p-f, at two seeds, and decodes at 10,876 / 10,566 tok/s on an Apple M1. Its limit is that 62.5% of p-f's reference replies are verbatim TRAIN replies: M1 is a language base, not useful chat.

Since then the work has moved to replies in controlled conversations, on the separate FBS trunk. Claude-358's three models state a value told earlier on 314, 320 and 325 of 578 recall questions (claude-358). Served without their exact turn memory, they give 171 to 211 exact replies of 2,218, against 377 to 441 with it, and almost every fact they get right comes from that memory's table (V0, claude-376). Since 13 Nov (D85) the default route is one persistent integer geometric state that training and serving share; the first Q31 vector state has trained on CUDA in a 64-step contract test (codex-5). Carrying the state across training windows (V1) and vector-native reads (V2(a)) are in progress (where we are, PLAN).
