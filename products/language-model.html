UOR-R4

Checked against its sources at abfad0604 (2026-11-14); 34 later commits change its sources.

The language model

The core product is a language model: a program that reads text and predicts what comes next, so it can eventually hold a conversation. UOR-R4 tries to do that with geometry and exact memory rather than a transformer's dense arithmetic. It is meant to ship as one UORLUT01 integer file that an ordinary laptop or browser can run without floating-point arithmetic. M1 is complete, but that product does not ship yet. No model holds a useful conversation and no alpha release exists.

What the model is meant to be

A geometric autoregressive state model with exact addressed memory. Prime addresses, zeta phases, E8/H4/icosian rotations and SpiralCore/FBS routing replace transformer machinery. Exact identity remains separate from geometric address. Conversation with durable memory comes first, then coding and reasoning, on one model.

Fast and local. The lead metric is tokens per second on ordinary hardware, with context and decode reported separately. A small quality gap is acceptable if the model is much cheaper.

Integer at serving. D11 bans floating point and transcendental arithmetic and excludes dense matrix multiplication. Since D80 and D81 it allows the hardware integer multiply and divide. Offline training may use float under D37, but every float candidate must report its export gap and ship as an integer artifact.

The artifact format and serving boundary

UORLUT01 begins with an 8-byte magic string and a JSON header, then aligned integer data sections. The reader checks offsets and lengths and computes the file's SHA-256 as it loads, so a release can pin that identity (format.rs). Table-native schemas include lut-discrete/1 and lut-discrete-trunk/1. The separate FBS lut-stack/5 is a 4-bit float-to-integer stack with exact rotations, not a table-native discrete schema; older dense lut-stack/1, /2 and /3 schemas are not a description of today's M1 artifact.

The serving engine is crates/uor-r4-integer. It serves native and WebAssembly artifacts, with save/restore formats such as UR4SESS1. An engine audit proves the absence of refused instructions, not model quality. M4 still requires the accepted model's full quality, CLI, session and audit path; M7's distribution check is separate.

Historical models and open questions

The four 214M-parameter checkpoints on Hugging Face predate today's rules and used softmax and matrix multiplication. They are historical evidence, not the D11 product. K16's 65 and 463 of 14,287 were also important negative results, but they predate the M1 close.

Open questions now centre on complete generation rather than M1:

  • Can exact memory key a reworded known question so a new phrasing starts the right reply?
  • Can one joined model produce complete correct replies and durable memory, then pass M4's full serving path?
  • What are the full-path latency, memory traffic and energy per token? M5 has not measured them.
  • Can library, CLI and browser produce bit-identical tokens and sessions on the accepted model?
