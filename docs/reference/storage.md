# Storage indexes: where every stored file is

The project keeps its bytes in three places outside git. The indexes in [`archive/storage/`](../../archive/storage/README.md) say what is in each one, so any stored or removed file can be found from the repository; this page says which index to open. Rules for where new files go are in [Workspace, storage and hygiene](../labs/workspace.md).

## The private HF store

`caseyallard/uor-r4-store` is a private HF dataset, so links to it work only when you are signed in to an account with access. The store's own [README](https://huggingface.co/datasets/caseyallard/uor-r4-store/blob/main/README.md) repeats the prefix table below.

[`hf-store-index-2026-10-20.tsv`](../../archive/storage/hf-store-index-2026-10-20.tsv) has one row per file, 3,883 rows in all, sorted by path. Columns: `path`, `bytes`, `hash` (`sha256:<hex>` for LFS files; `git-blob:<sha1>` for small files), `last_commit_utc` and `last_commit_title`. It was taken on 20 Oct 2026 with `hf datasets ls caseyallard/uor-r4-store -R --format json`; re-take it the same way after large uploads.

Download one file or prefix:

```sh
hf download caseyallard/uor-r4-store <path> --repo-type dataset --local-dir <dir>
hf download caseyallard/uor-r4-store --repo-type dataset --include '<prefix>/*' --local-dir <dir>
```

## The laptop workspace backup, 20 Oct 2026

On 20 Oct 2026 the owner approved clearing everything project-related outside the single clone `~/uor-r4`. Each removed folder was packed into one of five tars, uploaded to `local-archive/2026-10-20/`, downloaded back and checked against [`laptop-backup-2026-10-20.sha256`](../../archive/storage/laptop-backup-2026-10-20.sha256) before the originals went to the Trash.

- [`laptop-backup-2026-10-20.tsv`](../../archive/storage/laptop-backup-2026-10-20.tsv) has one row per removed item, 806 rows. Columns: `original_path`, `hf_archive`, `files`, `bytes`. To find where a folder went, search this file for its old path.
- [`laptop-backup-2026-10-20-excluded.tsv`](../../archive/storage/laptop-backup-2026-10-20-excluded.tsv) lists the build caches left out of the tars (folders holding a `CACHEDIR.TAG`). They are regenerated by building.
- The complete member list of each tar is on HF beside it, as `local-archive/2026-10-20/<name>.files.txt` (the uor-r4-local list alone is 25 MB, so it stays out of git).

| Tar | Holds | Paths inside start from | Files | GB |
|---|---|---|---|---|
| `uor-r4-local.tar` | `~/uor-r4-local/`, Codex lab scratch, 3–19 Oct | `~/` | 151,852 | 6.45 |
| `harness-state.tar` | `~/.local/share/uor-r4/{knowledge,research,tooling/serena-smoke}` and per-commit binaries older than 10 Oct | `~/.local/share/uor-r4/` | 3,116 | 2.84 |
| `spiralcore-fbs-review.tar` | `~/spiralcore-fbs-review/`, a review clone with its own git history | `~/` | 15,131 | 1.82 |
| `repo-local-scratch.tar` | `~/uor-r4/local/`, `~/uor-r4/.uor-preserved/`, `~/uor-r4/.uor-cleanup/` | `~/uor-r4/` | 849 | 0.63 |
| `home-loose.tar` | project files and folders that sat loose in `~` | `~/` | 723 | 0.05 |

Restore one folder:

```sh
hf download caseyallard/uor-r4-store local-archive/2026-10-20/<name>.tar --repo-type dataset --local-dir <dir>
tar -xf <dir>/local-archive/2026-10-20/<name>.tar -C <dest> '<path inside the tar>'
```

The path inside the tar is the old path with the tar's root removed, as given in the column above, with no leading `./`. For example, `~/uor-r4-local/a8-census-frozen` is `uor-r4-local/a8-census-frozen` in `uor-r4-local.tar`, `~/uor-r4/local/note-2462.md` is `local/note-2462.md` in `repo-local-scratch.tar`, and `~/.local/share/uor-r4/knowledge/code` is `knowledge/code` in `harness-state.tar`:

```sh
tar -xf <dir>/local-archive/2026-10-20/uor-r4-local.tar -C ~/restore 'uor-r4-local/a8-census-frozen'
```

## The iCloud cold archive

From 20 Oct 2026, the iCloud folder `UOR-R4/results/` is a read-only cold archive; nothing new is added to it. The [iCloud archive README](../../archive/storage/README.md) gives the counts per lab, explains the two gap files and shows how to fetch one object with `cloud-store`.

| File | What it is |
|---|---|
| `icloud-index-2026-10-20.tsv` | The index of the archive: one row per tar, sorted by remote path. Columns: name, bytes, md5, remote path, uploaded UTC, lab. Built on 20 Oct 2026 from the small per-object index files that `cloud-store` kept under `UOR-R4/index/`. |
| `icloud-unindexed-2026-10-20.tsv` | The gaps. Columns: path, bytes, status, note. Status `no-index-row` is a file under `results/` with no valid row in the index (31 files). Status `missing-file` is an index row whose tar is not under `results/` (42 rows). |
