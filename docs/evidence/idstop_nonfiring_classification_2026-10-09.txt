WHY THE 9 DID NOT OPEN (trace channels, counts not impressions)
  Counting, over all 84 cells, where the value's first window id (v0) landed:
    A  v0 never emitted                                        5/84
    B  v0 emitted, pointer's source_held v0, NO run open       71/84   (open available)
    C  v0 emitted, pointer's source held v0, a run ALREADY open 8/84
    D  v0 emitted, pointer held something else, run open        0/84
    E  v0 emitted, pointer held something else, no run open     0/84
  SO THE HYPOTHESISED POPULATION IS EMPTY: in every one of the 79/84 cells that emitted the
  value's first token, the pointer's argmax source at that step held EXACTLY that id
  (matches_source true). There is no cell whose "pointer source is right but the emitted id is
  not the window id at that source". A wider open window cannot add anything, because the strict
  open already succeeded wherever the token existed.
  The argument is not impressionistic: an offline re-implementation of CopyStopRun over each
  record's emitted ids (EOS and short-cycle stops first, the dropped id restored) reproduces the
  recorded fire decision on 84/84 cells and the recorded (window_index, copied) on 23/23 firings.

  The 9 (d) cells, by the same classification:
    4/9 are class A — the value's first token is never emitted at all; the reply is a template
        fragment closed by EOS: " My name is" (natural/n_iyandel), " Sss." (sure/n_therrick),
        " Noted." (noted/n_iyandel, noted/n_therrick). Value text present 0/4. There is nothing
        for any stop rule to stop at.
    5/9 are class C — the value IS emitted (present 5/5) and the reply ends with it:
        " My name is Ithmar." (natural, sure, noted/n_ithmar), " My name is Iyandel." (sure),
        " My name is Orvynn." (sure). In each, a run was ALREADY open when the value's first
        token arrived, opened BEFORE the value on window position 4 or 6 while the value's span
        starts at 7; it covers the template AND the value as one contiguous verbatim copy
        (measured: emitted ids == window[4..11] for the ithmar cells, window[4..11] for iyandel,
        window[6..12] for orvynn), and EOS ends the reply while the run is still extending, so
        the strict rule never reaches a break. The reply does not "run on"; it terminates
        correctly on the value and fails on its PREFIX.
    PRESENT-RATE FOR (d): 5/9 = 0.5556. So the (d) population is NOT dominated by "value never
    emitted" (4/9) and NOT by "right value, wrong termination" (0/9): the 5 present cells are
    "right value, right termination, wrong prefix".

RECOVERABILITY: 0 of 9, and 0 of all 12 non-exact cells
  Any rule that only decides WHERE THE REPLY ENDS produces a text prefix of the reply (the reply
  is a concatenation of id bytes; the probe decodes EOS away). No prefix of any (d) reply
  normalises to the expected value: for the 4 class-A cells the value is absent, and for the 5
  class-C cells the required characters " My name is " come BEFORE the value and no end-truncation
  can remove them. Across all 84 cells, 0 of the 12 non-exact cells becomes exact after any prefix
  truncation (for the 9 no-fire cells the reply is the full unstopped reply, so this is exact;
  for the 3 fired cells it bounds their already-truncated replies).
  Therefore step 3 of the brief was NOT triggered: (d) is not dominated by "pointer source right,
  first emitted id different" — that population is empty — and no open-window relaxation was
  implemented. No relaxation template-firing count exists to report. For context, the STRICT rule's
  own template firing at this floor is 1 of 23 firings: natural/n_therrick fires fully outside the
  value span on " What is" (copied=2).

WHAT REMAINS UNKNOWN
  1. The 5 class-C (d) cells could in principle be repaired by a SPAN-EXTRACTION rule (emit only
     the span the pointer selected, dropping the template prefix), which is a different instrument
     from a copy stop, is not measured here, and would need its own pre-registered test. INFERRED,
     not measured: the ceiling is +5/84 = +6.0 % on this panel.
  2. The 4 class-A cells are a generator/EOS failure at floor 0.5 (the model emits EOS before the
     value); no serving-time stop can touch them.
  3. Not measured: other floors (0.75/1.0), other arms, other panels, non-greedy decoding, any
     integer/D11 port (export still refuses a pointer with an identity term).
