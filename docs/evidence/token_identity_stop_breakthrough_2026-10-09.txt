UOR-R4 — Token-identity copy stop: a NEW BEST 72/84 = 0.8571, and F=1.0 is recovered
Date: 2026-10-09. DeepSeek session. References #820. Tracker #2029 (language base), #2032 (served model).

WHY THIS INSTRUMENT
  The run-length copy stop recovered +40 cells at F=1.0 but added EXACTLY ZERO at F=0.5, and the cause
  was measured: the matched run lay inside the VALUE'S OWN SPAN on only 20 of 79 cells at F=1.0 - the
  rest matched the PROMPT TEMPLATE ("User: My nam..."), because values tokenize to ~5-7 ids and a
  run-length rule lands in the wrong place by coincidence. A stop keyed on TOKEN IDENTITY against the
  span the pointer itself selected cannot fire on the template, so it is the right instrument for the
  failure actually observed.

THE RULE (pointer_copy_stop_identity=1, default 0 = bit-for-bit unchanged; read-out only, no training,
no parameters, nothing serialized)
  At each step the emitted id either (a) OPENS a span at the pointer's own argmax source, when the id
  equals the window id there, or (b) reproduces the span's next window id. The first emitted id that is
  not the span's next id ENDS the reply and is DROPPED, so the reply is exactly the ids the pointer
  reproduced. The essential differences from the run-length rule are the strict open at the selected
  source and DROPPING the id that leaves the span.

THE MECHANISM, MEASURED
  Channels are unmoved by the rule (the floor still sets the mixture; the stop only moves where the
  reply ends). The contrast that matters is at arm-ptr F=0.5: the RUN-LENGTH rule fires on 26 cells with
  only 1 of them exact, while the IDENTITY rule fires on 23 with 20 exact and lands inside the value's
  own span on 21. HONEST LIMIT: at F>=0.75 the rule fires on 61-82 of 84 cells and the fired span is
  fully inside the value's span only about a quarter of the time (it usually starts at the value and
  runs on into the template). So the mechanism is "end the reply at the end of the first span the
  pointer sustains BY TOKEN IDENTITY", not "recognise the value" - the distinction matters for anyone
  extending this.
