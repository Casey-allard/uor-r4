# The web client

The web client is meant to be a language model that lives in a browser tab. You open a web page once, it downloads the model file, and from then on the model can run on your own computer, inside the browser, in a sandboxed form of machine code called WebAssembly. In local WASM mode your prompts and the model's replies stay on the device. An optional user-configured OpenAI-compatible API instead sends prompts to the endpoint the user chooses. The page you would use is the Studio, an editor-and-chat interface already in the repository. The live `/studio/` page now offers the publicly released M1 model as a top-8 next-token predictor after an explicit download click, alongside a clearly labelled synthetic demo and local-file, URL and API model sources. **M1 is complete, but the M1 model is a language base, not a chat assistant; until M7 and M8 pass the web client is a research explorer and demonstration, not a product.**

**5 November 2026 LexLean comparison and exact-tool follow-up (source change; protected delivery is tracked separately):** the public LexLean-R4 repository and live full-pack page were inspected before considering a default-model swap. Repository commit `23436bdcd69e5238fcda51ef2529bbd4a5dc1e73` and deployed tree `563a7549e432fc035bc603504bb3a162eb332212` identify the inspected source. The hosted model computed `17 + 25 = 42` through an exact-arithmetic path, but answered self-description with an unrelated Hunger Games review and the immediate previous-fact question with Fibonacci code. Its older `/8` memory layout, sigmoid tables, heuristic composer and absent OpenAI endpoint make it unsuitable as a drop-in default under the current charter, so no external WASM or second model format is bundled. Instead, the existing UOR `m6_exact_arithmetic` engine now answers a strict bounded decimal `+` or `-` prompt with the numeric result first and an actual geometric place-value trace, explicitly labeled `tool, not model generation`. On the supported stack-backed chat path, the browser worker handles it before tokenization with zero model token IDs and no invented token rate; ordinary prompts retain the prior synthetic/API paths. Exact turns skip session checkpoints because they do not advance model state, including `/7` turn-memory stacks. The M1 discrete artifact remains next-token-prediction-only and is not a new chat mode. The whole exact-tool exchange (its user prompt and answer) remains visible in conversation history but is excluded from subsequent OpenAI message context, so neither a long trace nor a tool-only arithmetic prompt can overflow the model. Both the typed model-source adapter and the live page now reject a worker filename or expected-hash mismatch explicitly instead of hanging in `finalizing`; the live page requires a current numeric load ID and fails closed when it is missing; only the typed model-source adapter separately accepts an identity-valid no-ID response for its single pending operation. Live loads carry monotonically increasing operation IDs, stale numeric responses and stale worker commits are ignored, and a current failure clears old capabilities and disables chat. Every exported page source-load method receives start-time operation metadata, and the panel's bundled click is captured before its legacy handler, so an older source completion cannot override a newer source or API selection. API selection also invalidates an already-posted worker load and clears old capabilities. Unsupported arithmetic-shaped forms, trailing/incomplete subtraction and arithmetic over 160 bytes return explicit errors rather than model generation; signed numeric statements, numbered bullets, number-leading dash prose, ISO punctuation/comma/trailing prose and ordinary dash prose fall through, while date-prefixed arithmetic remains an error. Clock-time ranges with a prose tail fall through only when the tail contains no digits or arithmetic/grouping glyphs; `5 pm - 6 pm + 3` and `2026-11-05T17:25 - 1` remain explicit errors. Recognized no-space date pairs fall through, while other compact or one-sided-space decimal subtraction computes exactly (`50-12`, `50 -12`, and `50- 12` return 38; `17-25` is an explicit underflow). Compact numeric ranges with declared unit prose (`5-10 minutes`, `50-12 minutes`, and `5-10 minutes, 3 times`) and ISO calendar ranges (`2026-11-05 - 2026-11-10`, including `2026-11-05 - 2026-11-10, 3 days`) fall through, as do ordinary ratio counts such as `3/4 of the 20 students passed` and mixed clock/prose forms such as `12:00 - 1, then lunch`; continued arithmetic after them errors. One-sided date-like pairs compute when whitespace separates the hyphen from either numeric group (`11 -05` returns 6 and `2026 -11` returns 2015), while adjacent `11-05` and `2026-11` remain date prose. Signed numeric tails after ISO dates, including comma-adjacent forms such as `2026-11-05,-1`, are explicit arithmetic errors. Declared compact ranges also include `5-10 km`, `5-10 cm`, `5-10 min`, `5-10 students`, and `5-10 dollars`; spaced numeric dates are arithmetic (`2026 - 11` computes 2015), and `2026 - 11 - 05` is an explicit multiple-operator error. Telephone-like prompts fall through only in the explicit 3-3-4 shape: an optional leading `+`, an optional country code `1`, then a parenthesized or bare 3-digit area code, a 3-digit exchange and a 4-digit subscriber, with spaces or single hyphens between groups (`1 (800) 555-0100`, `(800) 555-0100`, `1-800-555-0100`, `+1-800-555-0100`, `+1 800 555 0100`). Dotted 3-3-4 forms such as `+1.800.555.0100` fall through as ordinary prose, while a dotted parenthesized form such as `(800).555.0100` remains an explicit unsupported/grouping error. Unprefixed numeric ranges may end with `?`, `!`, `,` or `.` and fall through as prose (`10 - 20?`, `10 - 20,`, `10 - 20.`), while prefixed underflow questions such as `What is 10 - 20?` remain explicit underflow errors. Exact-tool metrics read `0 model tokens · tool`, with no computed model rate, model stop reason or allocation delta. The no-storage default remains the synthetic demo even when a catalog card is marked primary. No-space trailing or adjacent-minus forms now fail explicitly, while declared ratio prose (`24/7 support`, `1/2 cup`, `3/4 of the students passed`) and multiple separated hyphens in dates, telephone numbers and identifiers fall through; `17/25 of 3` and instruction-suffixed division remain explicit errors. Source selections made while a reply is active preserve the healthy session: model-load and API-use/removal clicks are blocked during generation, while a load started before the reply and a programmatic source selection are retained as the latest pending selection and applied on the existing generation-finished event; programmatic removal of an active API fails closed rather than leaving the deleted endpoint active. Implementation and protected-delivery evidence is tracked in [#3704](https://github.com/UOR-Foundation/uor-r4/issues/3704), not as a new model or milestone capability.

## How it is meant to work

1. **Load the static Studio.** The charter places it at `/studio` on the documentation site.
2. **Download one `UORLUT01` file and verify its SHA-256.** A release pin identifies the model. A
   download-once browser-storage cache is planned, not claimed as delivered.
3. **Start the integer engine in a Web Worker.** The worker loads `pkg/uor_r4_integer.js` and calls
   `init` and `loadStack` on the model bytes.
4. **Generate.** Each token calls `step`. The D11 engine uses integer arithmetic; integer multiply
   and divide are allowed, while floats, transcendentals and dense matmul stay banned. Accepted-model
   cross-browser parity is an M7 measurement, not an assumption.
5. **Save and resume.** `saveSession` emits a `UR4SESS1` snapshot and `restoreSession` loads it.

The real exports are `init`, `tickClock`, `loadStack`, `step`, `saveSession`, `restoreSession`,
`weightsPerToken`, `allocEvents` and `leakedModels`
([`wasm_bindgen_exports.rs`](../../crates/uor-r4-integer/src/wasm_bindgen_exports.rs)). Serving an
exported D11 artifact on a client device is allowed; the GPU-first research-compute rule does not
apply to product serving ([charter](../../CHARTER.md), section 3.6). D84's CPU training program is
development research and does not qualify the browser runtime.

## What is still missing

- **A qualified model bundle for the web product.** M1's native artifacts do not by themselves prove
  browser parity or M7 distribution.
- **The accepted M4 model and its browser export.** Full quality, session and audit bars come before
  M7's accepted-model parity check.
- **A download-once cache and release loader.**
- **Bit-identical tokens and sessions on the real model across library, CLI and browser.** The
  synthetic harness passing is an instrument result, not M7 completion.
- **Automatic build/publish remains owner-only.** DeepSeek's manual production publish is already
  live; this documentation refresh performs no deployment.

## Privacy and integrity

- **Local WASM mode computes locally.** No prompt or reply needs a model server. Native loopback
  uses the `uor-chat` process on this device, with an ephemeral in-memory token. An optional
  user-configured OpenAI-compatible API instead sends prompts to the endpoint the user chooses.
- **Page-load resources are self-hosted.** The static and headless-Chrome checks report zero external
  requests on both Studio pages. Loading the public M1 model from Hugging Face is a separate,
  explicit click that downloads the artifact without sending prompts. User-initiated GitHub features
  are also explicit actions and are refused in Tauri/offline mode.
- **A checksum proves integrity, not secrecy or quality.** The model is public; a hash identifies
  the released bytes, not who made them or whether they answer well.

Until M7 and M8 pass, the page remains a research next-token explorer and synthetic-engine
demonstration, not a working assistant. M1's language-base result and browser prediction are real,
but they do not change that product boundary.

## Open questions

- How large will the accepted model file be, and is a one-time download acceptable on a phone?
- How fast is WebAssembly against native on the same file? The M1 pair's native 10,876/10,566 tok/s
  does not answer that. Older FBS native rates and older evaluation throughput are not browser rates.
- Which remaining served-memory/readout parts are needed for the accepted model's full browser path?
