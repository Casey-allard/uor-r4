# The desktop client

The desktop client is a pre-alpha native shell you install on your laptop. It shows the same interface as the web client, with a host-managed `uor-chat` sidecar and native Rust backend. It opens only user-granted project folders, remembers conversation text locally, and needs no external CDN at page load. The older engine path separately verifies durable object-store snapshots; that is not exact sidecar hidden-state resume. The target machine is an M1-class laptop. **No qualified trained product bundle exists for it to run.** The project is pre-alpha: 1 of 8 milestones is complete, and the `src-tauri/` desktop shell is verified on the 469,252-byte `mk-synthetic-stack` (`seed = 5`) synthetic stand-in artifact ([record](../labs/infra-desktop-client-tauri/README.md)). Nothing ships until the remaining model and client bars pass.

Labels used below: **proof** (derived from definitions or code), **measurement** (a recorded run with its artifact), **hypothesis** (untested). See the [glossary](../start/glossary.md).

*Same interface as the web client; the engine, memory and file access run as native Rust inside the app. The host starts a loopback `uor-chat` sidecar automatically; external MCP connections require an explicit user action and native confirmation. Custom third-party providers and remote model URLs remain browser-only.*

## Goals and non-goals

**Goals.**

1. Run the released `UORLUT01` model natively, under the D11 integer contract, on an M1-class laptop.
2. Share the web client's interface, so there is one interface to maintain.
3. Give the model access to the user's chosen project folders, for coding help.
4. Keep durable conversation memory on disk (the D19 line), so a conversation can be closed and resumed exactly.
5. Work fully offline after install.

**Non-goals.** No cloud model, account, telemetry or remote server is required, and no second model format is introduced. A host-managed loopback `uor-chat` sidecar is part of the local app, not a public server. Training and evaluation stay on GPUs ([charter](../../CHARTER.md), section 3.5).

## Architecture

The app is built with **Tauri**: a small native shell that shows a web page in the system's own webview and runs a Rust backend beside it. The page calls the backend through named commands. Rust is the project's default language ([charter](../../CHARTER.md), section 3.11), so the backend can link the project's crates directly.

## Data flow

1. **Install.** The installer carries the app and, optionally, the model file. If the model is not bundled, the first run downloads it once ([update and download](#update-and-model-download)).
2. **Load.** The model manager reads the file, checks its SHA-256 against the release pin before parsing, and passes the verified bytes to `IntegerStackModel::parse`. The `UORLUT01` reader checks every offset and length and returns an error rather than crashing on a malformed file ([`format.rs`](../../crates/uor-r4-integer/src/stack/format.rs); **proof** by reading the code).
3. **Chat.** The live interface sends an OpenAI-compatible chat request through Tauri IPC to the host-managed `uor-chat` sidecar. The host relays JSON and SSE bytes, exact usage and UOR timing metadata without exposing the sidecar token to the page. The older `native_step_tokens` engine command remains available for focused synthetic-engine tests; it is not the main chat transport. Conversation text persists locally, but exact sidecar hidden-state resume is not claimed. **Exact arithmetic is a separate host tool, not generated by the model.** A strict bounded decimal addition/subtraction uses the shared `m6_exact_arithmetic` engine before starting the sidecar and returns an OpenAI-compatible JSON fallback with zero model usage; unsupported arithmetic-shaped forms and arithmetic over 160 bytes return explicit errors, while ordinary prompts continue through the unchanged sidecar stream. Exact-tool metrics read `0 model tokens · tool`, without a computed model rate, model stop reason or allocation delta. Live model loads carry operation IDs, reject stale responses and clear old capabilities on current identity failures. The whole exact-tool exchange (its user prompt and answer) remains visible in conversation history but is excluded from subsequent OpenAI message context, so neither a long trace nor a tool-only arithmetic prompt can overflow the model. This was added after the LexLean full-pack probe at repository commit `23436bdcd69e5238fcda51ef2529bbd4a5dc1e73` and deployed tree `563a7549e432fc035bc603504bb3a162eb332212` reproduced its correct arithmetic but failed self-description and immediate-fact recall; LexLean itself is not adopted as a second runtime or default model. No-space trailing or adjacent-minus forms fail explicitly, while ratio prose and multiple separated hyphens in dates, telephone numbers and identifiers fall through. Clock-time ranges with a prose tail fall through only when the tail contains no digits or arithmetic/grouping glyphs; `5 pm - 6 pm + 3` and `2026-11-05T17:25 - 1` remain explicit errors. Recognized no-space date pairs fall through, while other compact or one-sided-space decimal subtraction computes exactly (`50-12`, `50 -12`, and `50- 12` return 38; `17-25` is an explicit underflow). Compact numeric ranges with declared unit prose (`5-10 minutes`, `50-12 minutes`, and `5-10 minutes, 3 times`) and ISO calendar ranges (`2026-11-05 - 2026-11-10`, including `2026-11-05 - 2026-11-10, 3 days`) fall through, as do ordinary ratio counts such as `3/4 of the 20 students passed` and mixed clock/prose forms such as `12:00 - 1, then lunch`; continued arithmetic after them errors. One-sided date-like pairs compute when whitespace separates the hyphen from either numeric group (`11 -05` returns 6 and `2026 -11` returns 2015), while adjacent `11-05` and `2026-11` remain date prose. Signed numeric tails after ISO dates, including comma-adjacent forms such as `2026-11-05,-1`, are explicit arithmetic errors. Declared compact ranges also include `5-10 km`, `5-10 cm`, `5-10 min`, `5-10 students`, and `5-10 dollars`; spaced numeric dates are arithmetic (`2026 - 11` computes 2015), and `2026 - 11 - 05` is an explicit multiple-operator error. Telephone-like prompts fall through only in the explicit 3-3-4 shape: an optional leading `+`, an optional country code `1`, then a parenthesized or bare 3-digit area code, a 3-digit exchange and a 4-digit subscriber, with spaces or single hyphens between groups (`1 (800) 555-0100`, `(800) 555-0100`, `1-800-555-0100`, `+1-800-555-0100`, `+1 800 555 0100`). Dotted 3-3-4 forms such as `+1.800.555.0100` fall through as ordinary prose, while a dotted parenthesized form such as `(800).555.0100` remains an explicit unsupported/grouping error. Unprefixed numeric ranges may end with `?`, `!`, `,` or `.` and fall through as prose (`10 - 20?`, `10 - 20,`, `10 - 20.`), while prefixed underflow questions such as `What is 10 - 20?` remain explicit underflow errors. Source selections made while a reply is active preserve the healthy session: model-load and API-use/removal clicks are blocked during generation, while a load started before the reply and a programmatic source selection are retained as the latest pending selection and applied on the existing generation-finished event; programmatic removal of an active API fails closed rather than leaving the deleted endpoint active.
4. **Remember (older engine path).** When that path saves a turn, `native_save_session_durable` snapshots its session state as `UR4SESS1` (`9,782 B` after 32 steps on the synthetic stand-in), wraps the conversation history and snapshot in a `UORMEM01` envelope (`encode_memory_envelope` + `fold_memory_envelope`), and stores the content-addressed records (`446` records on the 32-token self-test, `object_version = bc98ac3d0a8f363ea6e7bcb10dea9acf59bd1a43859d9e6dd4417f0e1d5364ca`) in `uor-r4-object-store::Store` ([record](../labs/infra-desktop-client-tauri/README.md)).
5. **Resume (older engine path).** On reopening, `native_restore_session_durable` reconstructs and verifies the `UORMEM01` envelope from the local store (`verify_memory_envelope`), loads the embedded `UR4SESS1` snapshot back into `LutStackSession::from_session_bytes`, and continues generation token-for-token (`16 + 16 == 32` verified in `durable_memory_object_store_close_and_resume_continues_token_for_token`). That is the M3 restore contract on the synthetic stand-in; M3 itself remains open until a trained model passes the full M3 acceptance panel ([project track](../integration/project-track.md), M3).
6. **Work on files.** When the user launches the host with `--grant <dir>` (or selects a folder through a host-owned dialog), `native_grant_folder` canonicalizes and registers it in `GrantedFolders` (`native_grant_folder` is host-owned and refused over page RPC); `native_read_file`, `native_write_file`, `native_list_directory` and `native_git_status` refuse any path outside granted roots.

## Why native, and how fast

The browser runs the engine as WebAssembly in one worker. A native build can use the processor's vector units (NEON on Apple silicon) and several threads. The project already has native table kernels for NEON and AVX2, though they belong to an older, frozen engine (`crates/uor-r4-simd`). **That native will be faster is a hypothesis.** Nobody has timed WebAssembly against native on the same file. As of 29 Oct 2026 the FBS trunk serves in integers on the M1 laptop at 4,829 tok/s snapped (claude-177) and 4,217–4,504 under `lut-stack/5`, with exact rotations and its DEV export gap inside the bar, ([claude-182](../loop/tasks/d11-exporter-float-trunk/claude-182/REPORT.md), [claude-186](../loop/tasks/fbs-serving-vector-kernel/claude-186/REPORT.md)), natively and without a vector (NEON) kernel; no browser figure exists. Older speeds on record are from older float models served exactly by the integer engine: 68 to 80 tokens per second on 8 threads for a 29M model, which is evaluation throughput over 64 scored windows rather than decode ([D11 serving record](../../archive/labs/d11-serving-2026-10-10/README.md)), and 184.58 tokens per second on one thread for input-driven forward passes, which is not free-running generation either ([lut-serving dossier](../mechanisms/lut-serving.md)). M5 is the milestone that measures laptop cost: ms per token, peak memory, mJ per token and weights read per token ([project track](../integration/project-track.md), M5).

Serving on the user's laptop is allowed. The charter says serving the exported D11 file on client devices, including Apple silicon, is the product, and the research-compute placement rule does not apply ([charter](../../CHARTER.md), section 3.6). D84's CPU training path is separate research and does not make the desktop client a qualification engine.

## Durable memory (D19)

D19 makes grounded conversation and durable memory the first priority ([D19](../integration/DECISIONS.md#d19--grounded-conversation-and-durable-memory-first)). The object store was split out as its own crate for this purpose on 14 October (D34). What it has shown, all on test data (**measurement**):

- 60 tests pass, and a pure-Python client pulled a 256 KiB object byte-identically from the Rust server ([conformance record](../labs/uorobj01-conformance-2026-10-18/README.md)).
- A 23-byte read of a 32,768-byte object touched 8 authenticated nodes, 384 bytes ([object-store dossier](../mechanisms/object-store.md)).
- Repeated content compresses well (7,776 bytes stored in 380), but unique content expands about 2.17 times (32,768 bytes become 70,972) ([D19 store record](../../archive/labs/d19-object-store-2026-10-15/README.md)).
- `src-tauri` folds and restores `UORMEM01` + `UR4SESS1` session state through `uor-r4-object-store::Store` (`446` records for a 32-token synthetic session, `9,782 B` `UR4SESS1` snapshot), and resumes generation token-for-token across process close/reopen ([desktop client record](../labs/infra-desktop-client-tauri/README.md)).

Never tested: any trained model reading from the store, the M3 memory bars on a trained model, and storage cost on real chat logs ([object-store dossier](../mechanisms/object-store.md)). The store keeps exact identity (what was said, where, in which version) separate from any geometric address, as the charter requires (section 3.12).

## Security model: local only

| Risk | Requirement and implementation (`#2826`) |
|---|---|
| Data leaving the device | No telemetry. The host starts a loopback `uor-chat` sidecar automatically; external MCP connections require an explicit user action and native confirmation. Custom third-party providers and remote model URLs remain browser-only. The separate web Studio offers user-configured API sources. [`web/studio/index.html`](../../web/studio/index.html) self-hosts all vendor functionality in [`uor_offline_vendor.js`](../../web/studio/assets/js/uor_offline_vendor.js) and [`uor_offline_fonts.css`](../../web/studio/assets/css/uor_offline_fonts.css) (zero external page-load resources; explicit native MCP and user-clicked links are separate actions), gates `callGithubApi` off in desktop/offline mode while preserving online browser mode, and [`tauri.conf.json`](../../src-tauri/tauri.conf.json) sets `connect-src 'self' ipc: http://ipc.localhost` (`'unsafe-inline'` in `script-src` is retained for existing inline DOM event attributes in `index.html`) |
| Broad file access | `native_grant_folder` is host-owned (`--grant <dir>` CLI flag on `uor-desktop-client`, refused over page RPC). `native_read_file` (capped at `16 MiB`), `native_write_file`, `native_list_directory`, `native_git_status` (`-c core.fsmonitor=false -c core.hooksPath=/dev/null`) and `set_durable_store_dir` check canonical paths against `granted_folders` in [`src-tauri/src/lib.rs`](../../src-tauri/src/lib.rs). Paths outside user-granted roots, `..` traversal, symlinks and dangling symlinks (`DesktopClientError::SymlinkRefused`) are refused. On `--serve-studio 127.0.0.1:<port>`, `POST /__tauri_invoke` additionally requires a per-launch random `X-UOR-Desktop-Token`, `Host: 127.0.0.1:<port>`, `Origin: http://127.0.0.1:<port>`, and `Content-Type: application/json` to block cross-origin browser requests and DNS rebinding |
| Running shell commands | The terminal is disabled by default and requires native enablement plus a matching one-shot native command approval, valid for 60 seconds. It directly executes only the named allowlist, rejects shell metacharacters, execution flags and attached file-option paths, checks path arguments against granted folders, bounds runtime/output, and runs terminal Git with hooks, fsmonitor, pagers and external diff disabled. This is an explicitly approved tool runner, **not a general filesystem or process sandbox**: build tools can execute their own project code. |
| A tampered model file | `native_load_model` verifies `b"UORLUT01"` magic and checks SHA-256 against `PinRegistry` before calling `IntegerStackModel::parse`; `native_list_local_models` stream-reads the 8-byte header first and skips unpinned files so unrelated `.bin` files do not abort discovery |
| A malformed saved session | The `UR4SESS1` parser checks varint counts before allocating and returns an error on truncated input ([record](../labs/wasm-serving-runtime-2026-10-18/README.md)), and `verify_memory_envelope` authenticates the `UORMEM01` store tree before restore |
| Memory-store sync between machines | Pins prove integrity, not authentication. Peer sync stays off unless the user sets it up, and is out of scope for the first release ([object-store dossier](../mechanisms/object-store.md)) |
| Unsafe code | `#![forbid(unsafe_code)]` is enforced in [`src-tauri/src/lib.rs`](../../src-tauri/src/lib.rs) as well as the runtime and format crates ([charter](../../CHARTER.md), section 3.13) |

### Offline vendor shim scope (`uor_offline_vendor.js`)

To eliminate all 9 external CDN `<script>` and `<link>` dependencies from [`web/studio/index.html`](../../web/studio/index.html) without committing multi-megabyte minified third-party bundles, [`web/studio/assets/js/uor_offline_vendor.js`](../../web/studio/assets/js/uor_offline_vendor.js) provides self-hosted local shims verified by [`web/studio/verify_desktop_client.mjs`](../../web/studio/verify_desktop_client.mjs):

- **`monaco.editor` + AMD `require`:** `<textarea>`-backed code editor supporting `createModel`, `setModelLanguage`, `getModelLanguage`, `create`, and a line-by-line LCS unified diff viewer (`createDiffEditor` rendering `.uor-diff-del` removed lines, `.uor-diff-ins` added lines, and `getLineChanges()`), without full Monaco token syntax highlighting or IntelliSense.
- **`marked`:** Renders fenced code blocks, headings (`#`–`####`), unordered and ordered lists, blockquotes, pipe tables, links (blocking `javascript:` URLs), bold, italics, and inline code.
- **`katex` + `renderMathInElement`:** Formats fractions (`\frac{a}{b}`), square roots (`\sqrt{x}`), superscripts (`^`), subscripts (`_`), Greek letters, and mathematical operators into structured `.katex` spans.
- **`THREE`:** 2D-canvas software 3D projection shim (`Scene`, `PerspectiveCamera`, `WebGLRenderer`, `Points`, `LineSegments`, `Line`, `OrbitControls`, `BufferGeometry`, `Vector3`, `Color`) driving the Studio's 3D lattice visualizer without external WebGL bundle fetches.
- **`pdfjsLib`:** Extracts printable ASCII text runs from simple PDF buffers and emits an explicit offline notice that binary PDF stream/font rasterization is not bundled offline.

## Update and model download

- **Model files are versioned releases.** Each is one `UORLUT01` file with a published SHA-256 ([releases](./releases-and-artifacts.md)). The app never runs an unpinned file.
- **First download.** Fetch the file once, verify the hash, store it locally. After that the app needs no network.
- **App updates.** Use Tauri's signed updater, or manual install. Signing keys and the hosting choice are open questions.
- **Delta updates for models (hypothesis).** The object store can send only the pieces that changed. In one test a receiver holding a slightly older 1 MiB object fetched 22 records, 1,014 bytes, in 3 rounds. But a cold pull of unique content through the store is far larger than a compressed download (5,725,408 bytes against 39,920 for a 2 MiB artifact), so the supported recipe is a compressed download first, then deltas ([object-store dossier](../mechanisms/object-store.md)). Whether deltas help for real model files is untested.

## Open questions

1. **Superseding the old plan.** [`archive/integration/frontend-port-plan.md`](../../archive/integration/frontend-port-plan.md) (historical, 4 September) says Tauri should not be the main client. The owner's 19 October decision replaces it, and that file needs a supersession note.
2. **Sharing one interface.** The Studio is one 7,107-line HTML file with inline scripts. Does it need to be split into modules before two shells can share it cleanly?
3. **The terminal command.** Keep it (with consent and folder limits) or drop it from the first release?
4. **Where memory meets the model.** Which comes first: storing session snapshots in the object store, or exact quotations from the store feeding the model's output? This is the object store's open path to ACTIVE status ([object-store dossier](../mechanisms/object-store.md)).
5. **Threads and D11.** The five D11 rules say nothing about threads. Whatever kernels the app ships, threaded or vectorized, must still pass their engine's serving audit. Every audit refuses float. The FBS stack's audit also refuses vector and matrix multiplies, and since D80 and D81 allows the scalar integer multiply and divide. The other engines' audits keep the zero-multiply rule.
6. **Engine format.** The legacy Studio also calls `native_list_local_models`, written for an older model format. The model manager must accept only `UORLUT01`.
