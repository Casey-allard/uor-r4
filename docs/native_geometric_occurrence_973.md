## Mechanism and frozen environment

The previous span reader marks every source occurrence matching any query word as a payload barrier. A word shared by the known endpoint and answer can therefore exclude the correct answer span. The unchanged-artifact diagnostic measures 144/384 complete answers: all 144 disjoint cases pass and all 240 overlapping cases fail. In 168 failed rows, an oracle-answer word is directly marked as a barrier on an actual generated query. Other rows diverge earlier; the report does not attribute all 240 failures to that separately observed final-query symptom.

The new occurrence module reuses the existing candidate window, source/word/byte identity, signed ordered word-prefix geometric comparison, local learned context boundary, whole-phrase updater, completion policy and byte/EOS writer. Each candidate answer span gets query-to-source assignments outside that span. Every query occurrence that originally matched the source must retain a match; exclusion cannot silently turn it into unmatched syntax. Assignments are injective, so one source occurrence cannot satisfy two query occurrences. Unmatched syntax keeps its None entry. Existing span predicates are evaluated separately on each complete assignment, without OR-combining evidence across assignments. Multiple witnesses for one source/span yield one offer; multiple admitted source/spans remain ambiguous.

Search is explicitly bounded at 16,384 visited partial assignments per route, across all candidates and records. Exceeding the bound returns CorrespondenceLimit for the whole route before a truncated result can claim uniqueness. The measured development maximum is 183 nodes and training preparation maximum is 303. Four raw records, at most three questions, 256 prompt bytes, 128 record bytes, 16 words per query/record, one-to-three-word spans, 50 span bytes and 96 completion steps retain their declared windows. This opt-in experimental path does not replace the normal model or claim the frozen no-allocation R4G1 kernel contract.

Rust prepares 384 rows in 32 matched families: eight disjoint/overlap/repetition patterns, two endpoint roles, one or two reads, four record rotations and baseline/active/inactive source changes. An independent raw-language oracle checks complete spans and expected paths. Training adds 192 one-read cases after a bijective lexical reassignment to the 2,624 preserved direct span-training rows. Gold spans and paths are removed from learner inputs; compatibility is actual forced completion of answer bytes plus EOS. Training and development exact inputs differ, but their structural templates are shared. This is supervised mechanism repair with familiar authored grammar, not an independent structural holdout.
