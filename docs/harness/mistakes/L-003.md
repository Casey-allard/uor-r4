## What happened

On 2026-10-03, during a disk cleanup, `claude-protocol/` was archived to iCloud as "superseded
emitters". But `chat-8m-a`'s training argv reads `claude-protocol/instr2-p2-dev` as its dev
corpus. DeepSeek found the recipe unreproducible. The folder had to be restored from iCloud
(`claude-protocol-full-20261003`, MD5-verified, tokens sha `0919e90f…` matching).

The same mistake has a second half: "the remote still has the bytes" is not sufficient, because
the bytes can be present and still unreachable by the recipe that needs them.

## Symptom

A retained run cannot be reproduced. Its recorded argv or `attempt.json` names a path that no
longer exists locally, and the check happens weeks later when someone tries to re-run or audit it.

## Lesson

Before moving any folder out of the working tree, search every retained run's recorded inputs —
`attempt.json`, `report.json`, `manifest.json`, launcher `*.sh` — for paths inside that folder.
Also check the argv of running processes. If any retained or active recipe reads it, either keep
it or record the substitution explicitly.

This is exactly how the `research/` archives were handled on 2026-10-12: the archive was written
and MD5-verified, `prime-analysis` was **restored and compared** (7,713 files, matching content
digest), and only then was the local copy removed.

## How to apply

1. Archive first: `cloud-store put <lab> <dir>`. It verifies by re-downloading.
2. Before deleting, prove recoverability: `scripts/storage/research-data restore <name> --run`
   into a scratch path and compare, or record why a comparison is impossible.
3. Grep retained recipes for the path: `git grep -n '<folder>' -- '*.md' '*.json' '*.sh'`.
4. Record the archive in [docs/harness/research-data.json](../../harness/research-data.json)
   with size and md5, so the path is discoverable without knowing the store layout.
