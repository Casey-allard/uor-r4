# Survey C: outside literature and practice (16 Nov 2026)

STATUS NOTE: this agent's context reached its 144k budget mark during setup (session system prompt), before any web call could run. Every number below is therefore marked "from memory"; NONE is "verified". Each needs a check against the named arXiv id before it goes into a decision card.

## Family table (quality / fits limits? / copy what)

1. MatMul-free LM (Zhu et al., arXiv 2406.02528, 2024; from memory). Ternary BitLinear dense layers + MLGRU token mixer; scaled to 2.7B; reported near Transformer++ at 2.7B; up to ~61% lower train memory, ~10x lower inference memory; FPGA demo ~13 W. Fits? NO as is: the gates use sigmoid and SiLU, it uses RMSNorm, and a ternary dense layer is still a dense matrix-vector product done with adds. Copy: element-wise recurrent token mixing (no attention) is enough for 1B-class quality when channels are wide.
2. BitNet b1.58 (2402.17764, 2024) and BitNet b1.58 2B4T (2504.12285, 2025) (from memory). Ternary weights, 8-bit activations; matches FP16 LLaMA perplexity at ~3B; 2B4T: 2B params, 4T tokens, ~0.4 GB weights, fast CPU decode. Fits? NO: softmax attention, squared-ReLU, dense ternary GEMM. Copy: ternary/low-bit state is not the quality limiter; tokens seen (4T) is.
3. infini-gram (Liu et al., 2401.17377, 2024) (from memory). Suffix-array unbounded-n-gram over up to 5T tokens, ~7 bytes/token index; ~47% next-token agreement; mixed with neural LMs cuts perplexity up to ~73%. Fits? YES (counts and ratios only; backoff by longest match is integer). Weak alone at open generation. Copy: longest-suffix exact match as the copy/recall path; suffix array over the 1B corpus (~7-8 GB) fits the M1 on disk/mmap.
4. Kneser-Ney n-grams (Chelba et al., 1312.3005 One Billion Word benchmark) (from memory). KN 5-gram ppl ~67.6 (word level, ~0.8B training words); LSTM/transformer LMs later reached ~24-30 (Transformer-XL ~21.8). Fits? YES (counts; KN discounts are rationals; no softmax needed when the distribution is a normalized count ratio, though sampling needs a division or integer CDF). Copy: KN-style discounted backoff is the floor any count model must beat.
5. Context-mixing compressors (from memory). enwik8: cmix ~1.17 bpb, paq8 variants ~1.2-1.3, PPMd ~1.7-2.0; enwik9: cmix / fx-cmix ~0.89-0.93 bpb; nncp (transformer, online) ~0.86. Speed: cmix ~ a few kB/s, tens of GB RAM; PPM is MB/s. Fits? PPM/CTW YES (counts); cmix/paq NO as is (logistic mixing = sigmoid/stretch-squash, neural mixer). Caution: these are online, single-file adaptive codes, not generalizing LMs. Copy: many orders + match model + SSE-like secondary estimation, all integer; replace logistic mixing with integer hinge-trained weights.
6. kNN-LM (Khandelwal et al., 1911.00172) and RETRO (Borgeaud et al., 2112.04426) (from memory). kNN-LM: WikiText-103 ppl ~18.65 -> ~16.1 with a 103M-token datastore; RETRO: 7.5B + 2T-token DB ~ matches 25x larger models on Pile. Fits? NO as is (transformer encoder, softmax over distances). Copy: retrieval gains scale with datastore size, so the 1B corpus as exact memory is worth more than extra parameters at this budget.
7. Engram (2601.07372, DeepSeek, Jan 2026) (from memory, low confidence on details). Hashed n-gram embedding tables looked up in O(1) and gated into a transformer/MoE backbone; reported gains over iso-parameter MoE. Fits? lookup YES, backbone NO. Copy: hashed multi-order n-gram tables as a separate memory budget beside the reasoning core, with hashing (not exact keys) to bound memory.
8. Product-key memory (Lample et al., 1907.05242) (from memory). 12-layer + PKM ~ 24-layer perplexity, faster inference. Fits? NO as is (softmax over top-k keys, dense query). Copy: factorized key search (two half-key top-k) for million-row memories; can be done with Hamming distances.
9. HDC / VSA for language (Kanerva; Joshi et al. 2016 language ID) (from memory). Language ID ~97% over 21 languages; no LM anywhere near transformer perplexity. Fits? YES (binding by XOR, bundling by majority). Copy: binding-by-XOR for conjunction keys; no evidence it carries fluency.
10. Hopfield / dense associative memory (Krotov & Hopfield 2016; Ramsauer et al. 2008.02217) (from memory). Modern Hopfield update = softmax attention (fails); polynomial/rectified-polynomial energy DAM has no softmax, high capacity. No LM results at scale. Copy: polynomial (power-of-overlap) separation as an integer sharpening rule instead of softmax.
11. Sparse distributed memory (Kanerva 1988; Bricken & Pehlevan 2111.05498) (from memory). Hamming-radius addressing; attention ~ SDM under conditions. No LM benchmark. Fits? YES. Copy: radius reads give graded recall when the exact top-1 misses.
12. Tsetlin machines (Granmo 2018 and text work) (from memory). Small text classification, word embeddings; no generative LM at scale. Fits? YES (integer automata, clause voting). Copy: integer-state reinforcement with hinge-like feedback; not a quality path.
13. Integer / LUT training (from memory): NITI (2009.13108) integer-only CNN training near FP on CIFAR-10; Bop (1906.02107) binary flips by momentum threshold, no latent float; EGGROLL (2511.16652) low-rank evolution strategies at population scale, demonstrated pretraining of integer-only (int8) recurrent LMs; HAD (2502.01770) binarized Q/K with Hamming-distance attention scores (still softmax-normalized over survivors, low confidence). Fits? NITI/Bop/EGGROLL YES in principle; HAD partly. Copy: Bop-style flip thresholds for sign codes; EGGROLL as a gradient-free integer training fallback; HAD as direct precedent for XOR+popcount reads.
14. SSM / RWKV (Mamba 2312.00752; RWKV) (from memory). 1B-class quality comparable to transformers. Fit? NO as is: dense projections everywhere; Mamba uses softplus for dt and SiLU; RWKV uses sigmoid receptance and exp decay. The scan itself is element-wise and can be integer. Copy: diagonal linear recurrence as the context carrier.
15. 2025-2026 softmax/matmul-free at 1B (from memory): no published model meets BOTH no-softmax-anywhere and no-dense-matmul at 1B quality. Closest: MatMul-free LM 2.7B (sigmoid gates), BitNet 2B4T (softmax), EGGROLL integer RNNs (small scale).

## (a) Cheapest combination under these limits
A two-part model: (1) an exact count memory over the whole 1B corpus (suffix array / infini-gram longest match + KN-style discounted backoff + hashed multi-order tables a la Engram), integer end to end; (2) a small integer recurrent core (diagonal recurrence, sign codes, Hamming reads) trained by hinge/perceptron credit only to correct the memory's errors (residual on the count prediction, like PPM SSE or kNN-LM interpolation). The memory supplies fluency and facts; the core supplies smoothing and generalization. This is the only route with outside evidence of usable text without matmul/softmax.

## (b) Realistic "1B-equivalent" bar (from memory, to verify)
Count/compressor models on ~1B tokens of web text land near 1.2-1.5 BPB held-out; a 1B transformer trained on far more tokens is ~0.8-0.95 BPB on Pile-like text; GPT-2-small class ~1.0-1.1. cmix's 0.9 on enwik9 is online single-file adaptation, not a held-out LM. Realistic target: beat a KN 5-gram / infini-gram on the same 1B tokens by a clear margin (>=0.15 BPB) and approach GPT-2-small (~1.05 BPB); "1B parity" has no precedent under these limits. Note: a 1B transformer itself is under-trained on 1B tokens (Chinchilla wants ~20B), so a same-data 1B transformer is a softer bar.

## (c) Outside support for project mechanisms
Supported: hard XOR+popcount reads (HAD, SDM, binary hashing, VSA binding); exact conjunction memory written from output error (n-gram/infini-gram/Engram/PPM counts, delta-rule memories); hinge/margin integer credit (perceptron, Bop, NITI, EGGROLL); E8 as a codebook (QuIP#, 2402.04396, E8 lattice weight quantization; from memory); nearest-lattice-point decoding (VQ / lattice decoders).
No support found: E8/Cl(0,6) 16-root anchor orbit as token geometry; SpiralCore signed-permutation/icosian transport and causal prefix holonomy as a RoPE replacement; prime-product addressing (any hash does the same job); nearest-root readout as a vocabulary head at LM scale.

## C2 verification (16 Nov 2026, sources opened through the Firecrawl research index and a live scrape)

1. MatMul-free LM (arXiv 2406.02528, full text read). VERIFIED with additions. The MLGRU forget gate is sigmoid, the candidate is SiLU, the output gate multiplies by sigmoid(h_t), and the GLU channel mixer uses SiLU/Swish. Training uses an STE surrogate gradient and BF16 activations, so it is not integer. The model sizes are 370M (15B tokens), 1.3B (100B tokens) and 2.7B (100B tokens). The 6-task zero-shot average was 40.3 against 41.1 for Transformer++ at 370M, 46.2 against 48.0 at 1.3B, and 49.9 against 50.7 at 2.7B. CORRECTED: the training memory figure is a 61.0% cut for the fused against the vanilla BitLinear kernel at 1.3B (82 GB to 32 GB), not a cut against Transformer++. The ~10x inference memory figure is a 13B simulation with random weights (4.19 GB against 48.50 GB). Not checked: the FPGA ~13 W (the passages opened cover Loihi 2, not an FPGA).
2. infini-gram (2401.17377 v4, read). VERIFIED. The infinity-gram alone predicts the next token with 47% accuracy (a 5-gram gets 29%). Its own perplexity is not computed (zero probabilities). The 7 bytes/token index is VERIFIED. "Up to 73%" is the reduction when it is interpolated with neural LMs, P = lambda*P_inf + (1-lambda)*P_neural. Per-model reductions: GPT-2 1.6B -34%, GPT-Neo 1.3B -16%, Llama-2 70B -12% (Pile-train reference). Implication: infini-gram has no published standalone perplexity or BPB, so it cannot serve as a standalone floor.
3. Engram (2601.07372, read). EXISTS and VERIFIED as "Conditional Memory via Scalable Lookup" (DeepSeek authors, including Wenfeng Liang). It uses suffix N-grams of compressed token ids, K multi-head multiplicative-XOR hashes into prime-sized tables, and concatenated embeddings. Its gate is sigmoid(RMSNorm(h)·RMSNorm(W_K e)/sqrt d), followed by a SiLU depthwise conv. The model has 27B params against an iso-parameter, iso-FLOP MoE-27B, with gains of MMLU +3.4, CMMLU +4.0, BBH +5.0, ARC-C +3.7, HumanEval +3.0, MATH +2.4, and Multi-Query NIAH 84.2 to 97.0. CORRECTION to the survey's framing: the gate and conv are squashing functions, and the memory is a learned float embedding, not counts. Only the hashed addressing transfers.
4. EGGROLL (2511.16652, read). CORRECTED, and the correction is material. The integer LM ("EGG") is a 6-layer, 256-dim character-level minGRU on minipile with a best test loss of 3.40 bits/byte, which is far from usable text. It does beat a same-size backprop Transformer at the same data batch, at roughly 180x the GPU-hours. It is int8 throughout and has no activation functions (saturating int8 add is the nonlinearity), but it uses int8 matmuls (u@W^T, head @), LayerNorm, and a fitness of y[t] - LOG2(sum EXP2(y)) via lookup tables. That fitness is a table-form log-softmax, which CHARTER §3.2 bans. So it is not matmul-free and its loss is not softmax-free.
5. HAD (2502.01770, read). VERIFIED: it still uses softmax. A = softmax(topN(sign(Q)·sign(K)^T)/sqrt d_k). It is distilled from a float teacher with tanh-annealing stages, and it was evaluated on GLUE, ImageNet and QuALITY, with no generative LM.
6. KN 5-gram on One Billion Word (1312.3005, read). VERIFIED: interpolated KN 5-gram with 1.1B n-grams has perplexity 67.6 (Katz 79.9). Training is ~0.83B words (829,250,940) with a 793k vocab. The best 2013 combination is 35% lower perplexity, about 10% fewer bits. Not checked: Transformer-XL 21.8.
