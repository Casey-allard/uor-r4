# DESIGN: evidence-bounded LexLean reuse

## Intent

Make the Studio more useful without mislabeling a heuristic dispatcher or an incompatible artifact as a coherent default model. Preserve the existing UOR-R4 research model and all current client safeguards.

## Findings that cancel the default swap

- The public LexLean page loads its 188,728,472-byte pack and computes `17 + 25 = 42` through an exact-arithmetic path. The same live session answers `Explain in two sentences what you are.` with an unrelated Hunger Games review and `What number did I just ask you to compute?` with Fibonacci code.
- The strong arithmetic/code replies come from deterministic tools/templates before the LUT model. The model is not a transformer, but its deployed `/8` header, memory key length and sigmoid-table semantics differ from the current UOR engine and charter.
- There is no hosted OpenAI-compatible inference endpoint to select as an external API baseline. Importing the WASM would add a second runtime and its heuristic corpus; converting only weights would not reproduce the observed composer behavior.

## Approaches

1. **Full deployed WASM as default:** rejected at this scope. Incompatible artifact semantics, second runtime, unresolved weights/corpus provenance, table-form squashing and unreliable ordinary chat.
2. **Model-only conversion:** rejected as a quick port. The header and memory layout differ and the observed usefulness is not model-only. A future export/retrain needs its own item and matched acceptance evidence.
3. **External OpenAI baseline:** not currently available; the static page has no inference API. It would remain non-default even if a user-hosted server appears.
4. **Repair and shared exact tool (selected):** fix the real silent loader failure, keep the synthetic default honest, and expose the existing UOR geometric arithmetic engine through a small shared Rust function in the browser worker and Tauri host.

## Implementation

- Add a strict bounded parser for one decimal `+` or `-` expression with only recognized optional instruction wording. Return `None` for ordinary prompts, signed numeric statements including spaced/hyphenated/parenthesized telephone-like fields, numbered bullets, number-leading dash prose, punctuated numeric ranges followed by unit text, clock-time ranges including spaced meridiems and seconds (prose tails are allowed only when they contain no digits or arithmetic/grouping glyphs), ISO date/time prefixes including sentence punctuation/comma/trailing prose and trailing time ranges, and no-space subtraction; return an explicit error for recognized invalid/underflow requests, unsupported arithmetic-shaped forms including bitwise/shift/comparison/grouping/`~`/Unicode-minus/non-ASCII-comparison forms and operator-only plus/minus, trailing/incomplete subtraction, time-range tails containing digits or arithmetic/grouping glyphs (`5 pm - 6 pm + 3`, `2026-11-05T17:25 - 1`) and arithmetic over 160 bytes. Trim ISO date/time tails before these checks so whitespace cannot hide arithmetic. Date-prefixed arithmetic remains an error. Only no-space date forms fall through; spaced numeric dates are arithmetic, not date parsing: `2026 - 11` computes 2015, while `2026 - 11 - 05` is an explicit multiple-operator error. Telephone fallthrough is limited to the explicit optional-`+`/optional-`1` 3-3-4 shape with spaces or single hyphens between groups; dotted forms without parentheses fall through as ordinary prose, while `(800).555.0100` remains an explicit unsupported/grouping error. Unprefixed numeric ranges may end with `?`, `!`, `,` or `.` and fall through as prose (`10 - 20?`, `10 - 20,`, `10 - 20.`), while prefixed underflow questions such as `What is 10 - 20?` remain explicit underflow errors.
- Format the numeric answer first, then `R4 geometric exact arithmetic — tool, not model generation` and the actual `PlaceStepRecord` trace. Reuse `GeometricArithmeticEngine`; do not copy LexLean's solver or probability labels.
- Export the function to WASM. On the supported stack-backed chat path, the worker handles it before tokenization and emits one text result with zero model completion tokens; ordinary generation remains on the existing path. The M1 discrete artifact remains next-token-prediction-only and does not become a new chat mode. Exact turns do not request session checkpoints because they do not advance model state. Browser and native renderers label the result `0 model tokens · tool`, with no computed model rate, model stop reason or allocation delta.
- Add a Tauri RPC command with the same shared function. `desktop_openai.js` tries it before starting a sidecar request and returns a normal JSON fallback envelope with zero model usage. The sidecar remains unchanged for all other prompts.
- Keep the exact-tool exchange visible locally but remove its user prompt and assistant result from subsequent OpenAI context. A real native probe first proved that removing only the answer still left an 81-position turn; the paired-filter regression failed before the repair and now leaves only the ordinary follow-up.
- Convert worker filename/expected-hash mismatches into an explicit error. Live loads carry monotonically increasing operation IDs and the worker uses an internal latest-load token, so stale responses cannot replace current capabilities or report errors. Wrap every exported page source-load method with start-time operation metadata and capture the panel's bundled click before its legacy handler. During generation, preserve the healthy model and retain only the latest deferred wasm/API source selection, then apply it through the existing generation-finished event so the manager label and send path agree; API-use and removal clicks are blocked, while programmatic active-API removal fails closed by aborting and clearing the deleted configuration. Pass current rejection to the existing error toast, mark and suppress stale rejection without hiding it from callers, and preserve the healthy loaded model on the worker's stop-generation-before-loading warning. API selection invalidates an already-posted worker load and clears old capabilities. A current identity failure clears capabilities and model metadata and disables the composer; the live page requires a current numeric load ID and fails closed when it is missing; only the typed model-source adapter separately accepts an identity-valid no-ID response for its single pending operation. Add a no-storage/default regression for missing and throwing storage; `primary` remains display metadata, not an automatic selector.

## Verification and remaining limits

Prove parser/tool negatives and positives first, then the actual WASM worker, Tauri command/transport, real browser and packaged app. Compare arithmetic and ordinary prompts side by side; confirm no fabricated token usage and no special-token sanitization. Full existing suites and hosted Pages checks are required. This adds a deterministic tool, not a conversational model, visual understanding, a new milestone, or a qualified trained bundle.
