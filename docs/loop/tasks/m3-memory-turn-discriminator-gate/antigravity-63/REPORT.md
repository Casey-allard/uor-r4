## Plain summary

Before a conversation assistant stores or updates a personal fact in memory (such as your name or your dog's name), a gate must check whether the sentence is actually stating a fact or is just ordinary small talk, so casual prose never overwrites stored facts. Earlier attempts (`claude-94` and `claude-102`) used an exact prime-number word sieve (where each vocabulary word is a prime number and a sentence template divides a turn's product if all its words appear in the turn), which kept all `50` small-talk test sentences (`P`, the frozen non-relation prose panel) from writing to memory (`0` false writes), but either rejected `56` valid correction sentences when two templates matched different spans (`R1 = 406/462`) or compiled `0` of `220` unseen sentence templates (`R2 = 0/220`). In this unit, we added `CoreCofactorTable::derive`, which inspects only the `84` training templates (`Split::Train`) to factor out two-sided correction words (like `"actually ... now"` or `"really"`) and complete missing template combinations by analogy ("fourth-proportional completion", such as combining `"My dog's name is {v}."` and `"My new job is {v}."` to form `"My dog's new name is {v}."`), and updated the GPU kernel (`sieve_frame.cu`) so a more specific template match refines a broader match whenever one value span sits strictly inside the other. Tested on an NVIDIA RTX 5090 GPU (`vast-57652110`) at `708,843` words per second (`tokens/s`), the gate kept all `50/50` small-talk sentences clean (`0/50` false writes and `0/50` false overwrites), recovered `462/462` (`100%`) of training phrasings (`R1`), and compiled `8/220` unseen development phrasings (`R2`, all `8` instances of `"My dog's new name is {v}."`) while abstaining cleanly on the remaining `212/220` (`0` wrong writes), meeting every clause of the pre-registered bar.
