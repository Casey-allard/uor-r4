## What did not work, first

- **Hex-character mnemonic token skip in `antigravity-29` (`report_output.rs:584–586`):** Using `.find(|tok| !tok.chars().all(|c| c.is_ascii_hexdigit()))` to skip raw instruction-encoding bytes after the address colon also skipped any mnemonic whose letters all belong to `{a..f}`—specifically `fadd` (`f`, `a`, `d`, `d`), `fabd`, `fcadd`, `add`, and `b`. Fixed by replacing the hex-character filter with `extract_mnemonic_and_operands`, which parses `llvm-objdump` / `objdump` instruction lines by column position (identifying an encoding column strictly as a single 8-hex-digit 32-bit word or `1..=15` space-separated 2-hex-digit bytes before the mnemonic column), and verified by planting `fadd s0, s1, s2` into a real symbol and asserting `verify_step_disassembly_text` fails.
- **Name-list-only symbol filter vs transitive call-graph walk (`report_output.rs:479–549`):** Checking a static symbol name list without walking `bl`/`b`/`call`/`jmp` edges would miss a newly added helper in `uor_r4_integer::stack` or a compiler-emitted multiply/divide builtin (`compiler_builtins::__multi3`, `__udivti3`). Conversely, walking only call edges without checking mandatory kernel entries could miss inline-changed kernels. Fixed by combining both: requiring all 43 mandatory `STACK_MANDATORY_SYMBOLS` (`IntegerStackSession::step` + 13 `stack::session::stack_*` mixers + 29 `stack::kernels::stack_*` kernels, `0` missing) AND walking the transitive call graph (`extract_branch_target`) across all reachable `uor_r4_integer`, `core`, `alloc`, and `compiler_builtins` callees (excluding formatting/panic paths and rayon/crossbeam thread-pool internals) plus every `uor_r4_integer::stack` closure instantiation.
- **AArch64 `d0..d31` register alias on 64-bit NEON integer SIMD (`stack_step`):** Banning all `d0..d31` loads/stores flagged `ldr d0` / `str d0` inside `stack_step`, where LLVM uses the 64-bit NEON register `d0` (`v0.2s`) for 2x`i32` saturating integer vector addition (`sqadd.2s v0, v0, v1`). Fixed by banning 32-bit scalar float register (`s0..s31`) loads/stores together with all scalar/vector float arithmetic, conversion (`fcvt*`, `frint*`, `cvtsi2sd`, `cvttsd2si`), and NEON/SSE/AVX multiply/float mnemonics (`smnegl`, `umnegl`, `mulx`, `div`, `pmulld`, `pmuludq`, `pmaddwd`, `mulss`, `mulsd`, `addss`, `addsd`, `vmulpd`, `vaddpd`, `<f...|bf...>.<lanes>`).
- **Circular work-rate check in `uor-r4-stack cost` and CI95 validator shortcuts:** Checking `((1.0 / mean_s) * mean_s - 1.0).abs() <= 1e-9` was an algebraic tautology, and falling back to `[min, mean, max]` or `gross_mj_per_tok` hid missing sample arrays. Fixed by requiring `--energy-receipt` in strict qualification mode (`!allow_provisional`), setting `work_rate_identity_verified` to `validated_energy_receipt.is_some()`, removing the `net` $\to$ `gross` fallback on v3 receipts, always emitting `InvalidSampleCount` when `samples` and `(sd, n)` are absent, and reconstructing the 3 archived v2 observations via exact 3-element sum algebra $x_2 = 3\bar{x} - x_{\min} - x_{\max}$ (`[3.135, 3.182, 3.199]` mJ) to diagnose the v2 $z$-vs-$t_2$ defect (`0.037 mJ` vs `0.082352 mJ`) alongside `InvalidSampleCount`.
