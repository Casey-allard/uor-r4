## Plain summary

Milestone M5 (`#2033`, `#2862`) measures how much time, memory, and battery energy the integer language model uses per word-piece (token) on a laptop across all four stages of a step: reading the input token (`ingestion`), updating the recurrent state (`routing`), looking up past context (`memory_lookup`), and scoring the next token (`emission`). Previously, the `uor-r4-stack cost` tool printed a hardcoded weight count (`7,238,304`), did not break step time down by phase, sampled memory only once at the end, and the earlier energy protocol (`v2`) had two math bugs in `archive/ops/measurement_report_rnd.json` (a `25.7%` power-versus-speed mismatch and a `53.6%` too-narrow confidence interval that used a normal-curve multiplier `1.96` instead of the small-sample Student-$t$ multiplier `4.303` for 3 runs). This change upgrades `uor-r4-stack cost` to compute exact per-phase parameter counts, per-phase latency, kernel peak memory, and background-daemon checks without adding any multiply or floating-point instructions to the served `step` function, documents Protocol v3, and seals a provisional Apple M1 rehearsal receipt and automated test suite while waiting for the exported M4 `UORLUT01` model (`#2859`).
