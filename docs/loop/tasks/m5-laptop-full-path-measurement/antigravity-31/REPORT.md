## What did not work, first

- **Substring `"alloc"`, `"free"`, and `"realloc"` in `ALLOW_PATTERNS` (`report_output.rs:659–670`):** Matching `lower.contains("alloc")` in `is_call_graph_allowlisted` matched every `alloc::` namespace symbol (`alloc::vec::Vec::from_iter`, `SpecFromIter::from_iter`, `alloc::slice::*`), contradicting the claim that `verify_step_disassembly_text` walks reachable `alloc` callees. Removing `"alloc"`, `"free"`, and `"realloc"` revealed that only `<alloc::raw_vec::RawVecInner>::finish_grow` (which computes byte capacity `cap * elem_size` on heap growth) and `<core::mem::alignment::Alignment>::new_unchecked::precondition_check` contain multiplies/fmov. Fixed by moving raw C/Rust allocator entry points (`__rust_alloc`, `__rust_dealloc`, `__rust_realloc`, `malloc`, `free`, `realloc`) to exact `EXACT_ALLOC_ENTRYPOINTS` and allowing only `"alloc::raw_vec"`, `"5alloc7raw_vec"`, `"handle_alloc_error"`, and `"precondition_check"` in `ALLOW_PATTERNS`, so all `alloc::vec::*` (`SpecFromIter::from_iter`, etc.) and `alloc::slice::*` functions are audited (`107` symbols / `13,801` instructions on `--release`, `114` symbols / `14,473` instructions on `CARGO_BIN_EXE_uor-r4-stack`).
- **Inlined Mach-O `TLVDescriptor::thunk` `blr` in `--release` `stack::session` (`report_output.rs:1304–1346`):** Forbidding `blr` across all `stack::session` symbols worked on the `test` binary (`opt-level = 0` on `rayon-core`), but failed on the `--release` binary (`opt-level = 3` on `rayon-core`), where LLVM inlined `rayon_core::registry::WorkerThread::current()` (`thread_local!` lookup) into 10 `stack::session` functions (`ldr xN, [x0]; blr xN`). Fixed by permitting `blr`/`call *` only inside `rayon_core::*` / `LocalKey` / `thread_local` runtime wrappers and on the exact Mach-O `TLVDescriptor::thunk` `ldr xN, [x0]; blr xN` sequence in `uor_r4_integer::stack::session::*`, while unconditionally rejecting any `blr` / `call *` in `uor_r4_integer::stack::kernels::*`, `core::*`, `alloc::*`, and `compiler_builtins::*` (verified by planting both `blr x8` and `ldr x8, [x0]; blr x8` inside `stack_gemv_pairs` and `step`).
- **Clippy warnings on touched files (`report_output.rs:1167`, `uor-r4-stack.rs:426`):** `report_output.rs` had a `collapsible_if` at line 1167 and `uor-r4-stack.rs` had a `needless_enumerate` at line 426. Fixed both so all touched files have zero clippy warnings.
