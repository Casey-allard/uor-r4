## What did not work

- `web/studio/foundry/studio/shell/v86/libv86.js` `N.prototype.SearchPath` returns `name: a[f]` where loop index `f === a.length`, leaving `info.name === undefined` on found paths. Fixed `delete9pEntry` in `linux-vm-host.mjs` to derive `fileName` explicitly from `clean.split('/').pop()` before calling `fs9p.Unlink(info.parentid, fileName)`.
- `libv86.js` `N.prototype.RecursiveDelete` only unlinks descendant entries inside a directory and leaves the directory node itself linked in its parent (caught by fresh-context reviewer `93d2b0d4-e309-4949-8e06-28530cf63fa2` on commit `59977138e`). Fixed `delete9pEntry` in `linux-vm-host.mjs` to invoke `fs9p.RecursiveDelete` followed by explicit `fs9p.Unlink(info.parentid, fileName)` across `write9pFile`, `delete9pFile`, and `clear9pWorkspace`, and updated `createMockFs9p().RecursiveDelete` in `stage3_os_github_stitch.test.mjs` and Check 6 in `verify_foundry_studio.mjs` to test subdirectory removal across app switches.
- Mounting `host9p` (`virtio-9p`) twice simultaneously on `/workspace` and `/mnt` risks `-EBUSY` on v86's single virtqueue; fixed `setupCmd` in `linux-vm-host.mjs` to mount `host9p` once on `/mnt` and bind-mount or symlink `/workspace -> /mnt`.
- First multi-origin run of `web/studio/verify_foundry_studio.mjs` shared a single `mockGitHub` instance across `/` and `/uor-r4/studio/`, causing the `/uor-r4/studio/` clone check to observe the `"hello v2 from studio"` commit pushed during the `/` run (`Clone content mismatch`). Fixed by giving each isolated browser origin its own fresh `mockGitHub` instance.
- Second CDP run hit `A V13 generation turn is already active` on `/uor-r4/studio/` because `verify_foundry_studio.mjs` called `chat:cancel` after `promote-to-studio` and immediately submitted the next Home Build App prompt while `uor_foundry_v13_wasm` was unwinding the canceled turn chunk in the worker. Added a 1.5 s settle delay in `verify_foundry_studio.mjs` after `chat:cancel`.
- Fresh-context exact-head review (`e237e7d6-4100-4667-87ec-aca17ed48bda` on `b4294ef50`, `93d2b0d4-e309-4949-8e06-28530cf63fa2` on `59977138e`, `710a2d3f-7fdf-435a-9e3b-8a65cd0af369` on `978cc5eaa`, and `0a91209a-f263-4e34-b626-4045c6e7dbc3` on `d4bf6ea4b`) caught five defects plus three small cleanups that were all resolved before final verification:

Fixed `parseGitHubRepoSpec` in `github-client.mjs` and `tools.github_clone` in `host.js` to accept `repo` as `owner/repo` or URL, with a unit regression test.

  3. Connected `connection-flow` IPC state in `github-client.mjs` (`emitConnectionState` and `getFlowState`) returned `{ status: 'connected', revision }` without the required `provider: 'github'` and `invocationRef: { kind: 'connection-flow', entityKey: 'github', operationId }` fields from `ConnectionFlowStateSchema`.   4. `github-client.mjs` `pull()` pushed raw string paths (`deletes.push(oldPath)`) instead of `{ path: oldPath }` to `applyWorkspacePatch` (which runs `assertCanonicalGeneration` / `stageGenerationPatch`), crashing any remote deletion with `invalidGenerationPatch`, while `linkRepo` set `headSha` with empty `baseBlobs` without marking `syncedFromRemote: false`. Fixed `deletes.push({ path: oldPath })`, added `syncedFromRemote: false` on `linkRepo` (`true` on `clone`/`pull`/`push`), checked `state.syncedFromRemote !== false` in `pull()`, and validated mock patches through real `assertCanonicalGeneration` + `stageGenerationPatch` plus remote deletion and `linkRepo` immediate-`pull()` tests in `stage3_os_github_stitch.test.mjs` and Check 7 of `verify_foundry_studio.mjs`.
  5. `linux-vm-host.mjs` `syncVmToWorkspace()` also pushed raw string paths in `deletes` and updated `lastSyncedHashes` before committing `applyWorkspaceChanges`, risking `invalidGenerationPatch` and file resurrection on `/workspace` `rm`. Extracted `syncVmSnapshotToWorkspace()` emitting `{ path: oldPath }` objects and committing `lastSyncedHashes` only after `applyWorkspaceChanges` succeeds, covered by unit regression tests (`syncVmSnapshotToWorkspace`) and Check 6 `/workspace` `rm` non-resurrection verification in `verify_foundry_studio.mjs`; also included `path: msg.path` in `stitch_fetch_res` packets in `stitch-network.mjs`.
