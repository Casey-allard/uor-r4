## What did not work

- Initial integration and exact-head adversarial review (`363120bf-ecc0-4053-bb33-8d7597feebf0`) caught seven real defects that were fixed before re-verification:
  1. `lookupStandards` in `web/studio/foundry/studio/shell/host.js` searched `sec.body`, whereas `build-standards-index.mjs` emits `sec.content`, `sec.tags`, and `sec.topic`, causing `standards:lookup` (`softmax`) to return `0` matches. Fixed `lookupStandards` to search all indexed fields.
  2. `verify_foundry_studio.mjs` timed out on `Page.reload` when reloading mid-stream while Run 5 V13 WASM inference was still running, used wrong field names (`stitch.sha256` instead of `stitch.recoveredSha256` / `stitch.expectedSha256`) and wrong actor subscription channel (`chat-stream:subscribe` instead of `distributed-machine:subscribe` with `protocolVersion: 1`), and initially dropped `reloadExternalReqs.length === 0`. Fixed stream settlement, field checks, restored `reloadExternalReqs.length === 0`, and added explicit assertions requiring `builtFromHome.hasToolCall && builtFromHome.hasToolResponse`.
  3. Staging Run 4's `catalog.mjs` output (`models/m1-discrete-trunk-seed-1.uorlut.audit.json`) inside `web/studio/dist/models/` caused `test_prepare_verifies_pinned_runtime`, `test_pages_stages_trained_models_and_rejects_unexpected_files`, and `test_studio_stages_only_a_receipted_trained_artifact` (`3` of `18` Python tests) to fail with `Unexpected model artifact` when replacing `models.json` from `--trained-manifest` or pinned archives. Fixed `scripts/stage-studio-site.sh`, `scripts/studio/prepare-tauri-runtime.sh`, and `web/studio/build_foundry_studio.sh` to clear stale `models/` before regenerating `models.json`.
  4. `?v13Mirror=` in `uor-r4-runtime.mjs` / `uor-v13-worker.mjs` previously nulled out `manifestSha256`/`stitchManifestSha256` and allowed arbitrary mirror URLs, while `handleTestStitchRecover` hardcoded `manifest.packs[0]`. Hardened `sanitizeMirrorBase` and `resolveBase` to allow only same-origin or loopback (`127.0.0.1`, `localhost`, `[::1]`) URLs, preserved pinned `manifestSha256` / `stitchManifestSha256` enforcement even with mirrors, and resolved the exact pack holding each stitch group's shards.
  5. `stitch_fetch` in `host.js` allowed arbitrary HTTP methods, default redirects/credentials, unallowlisted external hosts, and full text buffering before slicing. Hardened `stitch_fetch` to `GET`/`HEAD`, `credentials: "omit"`, `redirect: "error"`, streaming `<= 8192`-byte read cap with early `reader.cancel()`, and a default-deny cross-origin HTTPS host allowlist (`STITCH_DEFAULT_ALLOWED_HOSTS` + `uor.stitch.allowedOrigins`).
  6. `home-chat:send` vs `home-chat:clear` / superseding send had an IDB/chunk overwrite race, unserialized `onText` persistence, and `load_v13` ignored `AbortSignal` cancellations; `ModelPicker.tsx` could leave `selecting` true if `unavailable` flipped during local file load, and `HomeChatSurface.tsx` lacked a synchronous `promotingRef` guard against double-clicks. Added `homeChatEpoch` + serialized `homeTextWork`, `turnRunning()` awareness for `homeChatAbort`, `activeLoad` `AbortController` handling in `uor-v13-worker.mjs` (plus cancellation timeout in `callV13Worker`), `finally { setSelecting(false); }`, and `promotingRef`.
  7. `web/studio/foundry/studio/tools/prism_r4_route.test.mjs` failed against the single-provider D90 model surface because it asserted `LOCAL_MODELS` and `selectedModel: { name: UOR_R4_DEFAULT_MODEL, ... }`; updated `prism_r4_route.test.mjs` to assert the single `UOR_R4` provider and absence of `LOCAL_MODELS`. (`browser_telemetry_isolation.test.mjs` tests `1–5` pass, while test `6` continues to fail with `ENOENT` on `web/studio/foundry/.github/workflows/studio.yml` due to the pre-existing monorepo layout.)
  8. `audit_zero_matmul_wasm.py --serving` passes all `7/7` symbols (`mul`/`div`/`float=0` except D80/D81 integer stack mul/div) on `web/studio/dist/pkg/uor_r4_integer_bg.wasm`, whereas `v13/uor_foundry_v13_wasm_bg.wasm` exposes `v13_*` entrypoints instead of `stack::*` and is verified by `eval_foundry_v13.py` WAT analysis (`49` inference functions scanned, `compute_float_ops: 0`).
