## What did not work, first

- **Nothing was built or measured.** No kernel exists yet, and no GPU profile has split a step by op chain. The item's fusion waits on one.
- **The fusion may not be worth its pin.** DeepSeek's [served-rounding-cost](../../../../roadmap/items/served-rounding-cost.md) (#3594) traced training as served's slowdown, 6.83–6.96× plain, with a host probe. The probe points at the export rounding: `grid_code`'s 2,032-candidate search on the host for every rounded gain, and nine matrices copied each step. Replacing the activation-scale loop saved about 2% of one CPU activation there. That is not a GPU measurement, but it means the quantizer chains may be a small share. So the item now measures first, and its cancel rule (the chains under 5% of wall seconds per step) can fire.
- **`loop claim` could not claim this unit.** The umbrella's `docs/roadmap/items/*.md` overlaps Kimi's open draft #3675, so it was claimed by hand under Casey's 1 Nov direction, quoted in the [ORDER](ORDER.md#how-this-unit-was-claimed). #3675 changes no file this unit edits.
- **The draft item had seven faults,** found by a fresh fact-check against `origin/main` before the item was committed. The worst would have broken runs: a dispatch check keyed to the two scanned sources would have refused the FBS arms module's two kernels on every arms run. All seven were fixed; details are in the ORDER's cancel probe result.

The exact-head review caught it: `:2109` is the recurrence's output gate and `:1757` the MLP gate, and the layer loop calls both, so it is twice a layer. Restored, with both sites named. The same review also tightened four lines:

## Plain summary

Casey approved writing custom GPU code that does in one step what now takes dozens of small steps, so training and scoring spend less time starting tiny jobs on the card. This unit writes that work down as a tracked item (#3678), checked line by line against the code. Checking it turned up two things. The first plan would have broken one kind of training run, and that is fixed. Another lab's earlier probe suggests the real slowdown may be elsewhere, in a rounding step done off the card. So the item now says: measure first, and only build the new GPU code if the steps it replaces are a real share of the time.
