# [codex] Pre-registration — P1(a) full and declared counts into D11

**Question.** Can the existing CUDA positional-prime counter produce one frozen S2 count family on the actual D87 1% record slice that the ordinary D11 loader can validate and read exactly? This test isolates P1(a). P1(b–d), the final entropy-pruned Elias–Fano layout, integer mixer, and 10/100% predictive curves require a scored candidate. They receive no pass here.

**Data.** Hash the full canonical c420 TRAIN `train.tokens.u16` against `c6cba29ead4c745fb47b3f87007d982e72defc9f04102a268709ba0d34d51460`; validate framing, range and 519,580 records. Keep every 100th complete record, zero-based ordinal 0,100,… (5,196 records). Full orders k=0..10, no crossing BOS, no BOS target. Use seed-1 trunk SHA `04652a3de8e966a23539b04fbd77c7d9872d9f13a541fcb224d48e766e2c147d`. Its bound tokenizer and c420 tokenizer share the ordered vocab and merges. No DEV input and no BPB or speed comparison.

**Native state.** Reuse the packed PrimeRouteKey and NgramCounter. Preserve exact integer counts from GPU additions. On each context retain successors with count ≥2, at most four ordered by descending count, smaller token ID on ties. Declared rank is floor(log2(count)) implemented as the top set bit; declared native count = 1 << rank. Enumerate retained triples sorted by numeric key then token with canonical 22-byte LE representation. Use a versioned integer trunk section with fixed-width packed keys and token/rank words; a reference codec for P1(a), not the final compression design. Bind the selection rule, full TRAIN, base model and slice identity. Add a D11 lookup for a typed count row without altering legacy artifact evaluation. The probe loads the new complete trunk via IntegerDiscreteModel::load, enumerates every retained triple and probes every stored key/token (plus a missing-key control).

**Controls and pass.** Existing independent CPU positional counter applies the document-boundary rules on the *identical slice*. Compare GPU and CPU raw order digests including context statistics; use independent pruning implementations for CPU and GPU counts, then require equal declared SHA and row counts for both and the D11 loader. Emit per-order hashes, total rows and token/record counts. Repeat the declared hash from loaded artifact, verify baseline prior sections/identity, tampered ordering/malformed rank/missing-key and reversed-order finite controls. Any mismatch blocks the replay claim. Encoding and pruning are frozen before measuring. This is a deterministic byte-equality test without a statistical threshold or end-user quality claim.

**Resources.** Ahead-of-time CUDA on Wick under the existing Codex flock. One order at a time, ~21M tokens, device partition budget ≤1M events except unsplittable heavy digits; target ≤1.5 GiB VRAM, ≤10 GiB host memory, 15 GB free storage plus 128 MiB margin, initial allowance 2 h. No rentals or other job interruption. Record wall and peak RSS, on-disk bytes, hash and artifact location. If device free memory is below 2 GiB wait for a slot. A failed gate leaves its downstream identity assertion unqualified. CPU work is the separately scoped exact counter oracle and client read-back. All model counts used for the frozen artifact originate on the CUDA path.
