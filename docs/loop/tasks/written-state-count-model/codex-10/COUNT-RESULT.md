# [codex] P1(a) count stream and D11 read-back on the 1% record slice

**Wick reproduced all 11 raw orders and all 14,634,359 retained count words.** The ordinary `IntegerDiscreteModel::load` parsed the new 20-section trunk. Enumerating its S2 family reproduced the writer's declared SHA-256. Looking up every retained (ordered key, original token ID) returned its declared count. A missing key/token returned zero. In the JSON, `declared_sha256` hashes the concatenated 22-byte LE triples rebuilt from the loader after equality with the independent CPU and device streams was enforced. `loaded_sha256` hashes every byte of the entire 379,223,660-byte D11 file. The two fields have different inputs. **Scope and limitation.** This is a P1(a) raw/declared replay for the registered top-four fixed-width codec. It retains four of 3,989 observed unigram successors and 14,634,359 of 97,154,030 distinct triples across all orders. It stores the reference count family alongside the original serving tables. The ordinary decoder still uses the original predictor. The full-support unigram, floor, S5/Pick expert, fitted S6 weights, compact deployment layout, 10/100% curves and P1(b–d) quality tests remain open. There is no held-out BPB or speed-of-generation measurement in this count result.

The base artifact, full TRAIN file, slice token stream, executable and SM89 cubin are pinned. Vocabularies and BPE merges in the differently packaged M1 and C420 tokenizer JSONs compare equal after canonical key ordering. TRAIN checks every native ID and record boundary as it verifies the complete 4.18 GB file SHA. Each order emits raw CUDA counts and context statistics through the existing positional-prime counter. The independent ordered-map oracle must agree on both digests and all order totals. Within each context the new CUDA kernel chooses the four largest counts ≥2, resolves ties by lower original token ID and maps counts to their highest set-bit value. A separate CPU insertion rule computes the declared reference. The packed D11 section binds the base, full TRAIN and slice digests, preserves all original payload bytes, and adds a binary-search count reader. A preliminary run computed raw counts on the GPU and selected retained words on the host. The final run executed both operations on the GPU. Both produced byte-identical trained artifacts. The finite GPU run checked a strictly higher count among five tied candidates, count quantization, reversed high-order contexts, missing addresses and rejection of a duplicate entry or invalid count rank. The 68.48 s figure includes the CPU verification and measures this sample on the shared 4090. The class count for order 0 illustrates why an S6/full-support score is required before a scaling claim.
