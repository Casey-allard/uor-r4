# Copy eligibility on the role-only path

The input is the frozen chooser's query occurrence, proposed copy source, raw prompt IDs, tokenizer word classes and learned geometric role prototypes. The output is one bit. When the gate returns true the caller uses the proposed source; otherwise it invokes ordinary generation. Copy IDs, span cursor, continuation and EOS remain the same typed writer operations as the role-only arm. [Registered design](../SHEET.md)

`operator.rs` is the native Rust reference for extracting the descriptor and comparing integer distances. It can be exercised directly on an existing client-side role handoff. Use the original bound q token offset, **not** the value source as q. `action.cu` reuses the exact full-word bounds and root-distance definitions from the prior sealed selector. Both implementations independently recover the same nominee, match count, descriptor words and expert distances. A tie produces ordinary generation. The fitting executable binds the action bank to the model digest and parent banks. Its role trace must match the model and bare input. Only the fit command accepts the TRAIN grade. SHA-256 seals for the deciding TRAIN and held payloads are enforced by the shell launch receipt.

Build with the registered selector source at the same repository-relative path. On Wick, compile `action.cu` with nvcc -O3 -std=c++17 -gencode arch=compute_89,code=sm_89, and build the locked Rust manifest in release mode for x86_64-unknown-linux-gnu. Install the executables as bin/action-device and bin/action-final. Run the finite fixture, then [run-wick.sh](run-wick.sh) in the released private run directory. The old role-only source and new TRAIN/held handoffs are described in the [panel specification](../PANEL-SHEET.md). All 194+194 new rows use frozen BPE and opposite-role permutations. Both public checkpoint digests and all five positive panels are inherited from the [source experiment](../../SELECTOR-RESULT.md).
