# [codex] The role-only candidate through the ordinary one-turn text client

The learned role reader is now executable from a single experimental UORLUT01 file. It also exposes an action-selection failure from real text. Asked “Which possession was named for Anne?” after Dan kept blue and Ben kept gold, the reader copies **gold** from position 10. Anne had no stated possession. Asked “How do you know when a question is unclear?”, seed 1 binds the colon after `Assistant` to the colon after `User`. It starts copying at position 6, reaches the eight-token cap, and the ordinary predictor continues to produce “you know when a question is unclearis.” Disabling the role read produces the generic acknowledgement. The known first error on the absent-entity case is the decision to copy, upstream of exact ID emission. [Registered cases](CLIENT-INTEGRATION-SHEET.md) · [Observed turns](client/turns.jsonl)

Each artifact embeds the released base model bytes and the trained requested, excluded and fact six-root prototype banks, word classes, ordered geometric connector relations, exact connector IDs and legacy geometric root. Its version chooses the whole-word rank, boundary, continuation, exact-ID writer and completion policy. The original D11 carrier's SHA-256 and bound tokenizer must match before execution. The client builds the BOS-inclusive literal-role v2 prompt from text. It searches all admissible complete-word pairs, applies the existing span/value/continuation operators, then feeds each emitted ID into the integer predictor. The cursor always addresses the original immutable prompt, including after the live context slides. `--read-mode no_read` disables the role-copy action; the original predictor still executes. Raw-ID mode retains its fixed token-count contract. Selecting either experimental file opts into this policy. The released M1 and count-replay carriers keep their original prediction rule. A supplementary client check, selected after registration from the sealed unseen tape (row 433), holds the Ben question fixed and swaps only the two stated values. Both seeds change the answer from gold to blue, still reading position 10. The no-read answer remains the acknowledgement. This complements the registered role swaps.

The two output files are 86,547,460 and 84,954,656 bytes, adding 11,328 bytes to each base. Repacking reproduced their bytes. Both were downloaded from the pinned store and compared byte-for-byte. Tests refused a changed base digest, an invalid prototype word, a nested policy and a wrong tokenizer. The direct text client runs on the local machine. Across the six registered prompts plus the supplemental fact swap, both seeds and both read modes, 28 primary invocations reproduced their fresh-process repeats (56 client calls). The six Wick-backed prompts produced 24 matched traces and 148 writer steps. The comparison covers exact prompt IDs, selected source, role-enabled query and fact locations, all eight state/ID/release words of every writer step, and EOS on the recorded arms. The additional prose prompt is a client observation. This replay qualifies this single-turn interface. Held-out reply and safe discretionary copy decisions belong to the crossed writer experiment and the separate action test. The final optimized client reproduced all 28 recorded turns and their fresh-process repeats. It also opened both a base file and a role-copy file with a JSON-escaped schema tag. The latter emitted gold and EOS (IDs 2551 and 1). [Executable identities](client/identities.sha256)

**Reproduce.** Build `uor-chat` with `cargo build -p uor-r4-integer --features serving-wasm --bin uor-chat`. Build the packing tool via the selector's Cargo manifest and `--bin role-artifact`. Run `role-artifact BASE.d11 ROLE.json CONTENT.json SPAN.json EXACT.json NEW.d11`. The two receipts identify every bank and input. With the bound tokenizer beside each carrier, `uor-chat --discrete seed1-role.d11 --tokenizer seed1-tokenizer.json --say "Dan kept blue. Ben kept gold. Regarding Ben, which possession was theirs?" --max-tokens 16` is the normal client invocation. The [replay driver](client/replay.sh) exercises both read modes and reopens the model for every request.
