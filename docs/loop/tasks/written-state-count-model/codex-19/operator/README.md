# Assertion-agreement requested occurrence

The D11 `uor-r4.lut-discrete-requested-occurrence/1` header carries `requested_policy: {"assertion_agreement": <protocol-2 framing>}`. The packer derives the framing from the identical tokenizer bound by the frozen paired carrier. The policy is only valid with the original ordered value profile. Its native inputs are original `u32` token IDs and half-open word spans, the frozen root and word-class tables, the trained assertion delimiters and the frozen sparse role counts. The contained onset bank, span state and paired carrier are serialized byte for byte. A header with no requested policy uses the original frozen role reader.

The ranker finds the last complete word in the framed user content, then the last earlier delimiter in the frozen assertion table. Query candidates are complete frozen role word spans between that delimiter and the framed content end. A candidate is eligible when its full original token sequence equals an earlier assertion head in the same content. The head must be a WordStart immediately after a frozen assertion delimiter, and every continuation ID must match. The existing role cells assign each candidate a signed requested score and excluded score using the original full-prefix offsets. The new rank is requested minus excluded. A unique eligible candidate can win with negative contrast. Equal best contrast or no eligible candidate yields no requested endpoint. The original excluded decision follows its existing evidence floor. There are no learned updates.

For ordinary text, `pack-all-starts` accepts the original four input paths and output path followed by `--requested-policy assertion_agreement TOKENIZER_JSON`; build with `--features serving-wasm`. Use the packed artifacts in the ordinary protocol-2 client. The accepted query span still goes through the frozen assertion/value reader and exact-copy cursor. A positive agreement admits a role candidate based on a prior head. It says nothing about whether the downstream reader can find the correct object or whether the prompt expresses an unambiguous request.

The Rust driver loads native inputs from the persisted carrier and takes only blind prompt prefixes. Its CUDA packet begins with four little-endian `u32` words (ABI tag `0x3141524f`, mode, row count, sparse-cell count). Each vocabulary site has four words (packed root, role class, assertion class, delimiter bit). Each sparse cell has four words (key, three counts). A row carries 192 padded original token IDs, true length and both framed endpoints. Each complete device result has eight raw role decision words. The driver compares them individually with the same packed artifact's Rust model before sealing a receipt.

For the treatment, each receipt row also carries the framed content, the query boundary, and every candidate span with its six feature keys, two frozen scores, eligibility and signed contrast. Eligible rows retain the first matching assertion head. The driver independently sorts this census and checks all eight device words again. CUDA uses four descending shift-and-compare steps for the cell quotient. The numerator has magnitude at most 13 times the cell total and the denominator is the total plus two, so four quotient bits suffice. The sign is restored after truncation.

```bash
cargo build --release --locked --manifest-path docs/loop/tasks/written-state-count-model/codex-19/operator/Cargo.toml --target-dir "$build"

```

The six finite prompts hold the two assertion heads fixed. Swapping the two query context roots reverses the eligible rank from `[11,13)` to `[14,16)`. Giving both the same positive root produces a tie. The remaining cases exercise a unique supported negative contrast, a matching initial piece with a different continuation, and a query word that never appeared at an assertion head. The Rust host test checks all planted endpoints and margins. Execution of the CUDA finite probe additionally compares all 96 words across the two modes.
