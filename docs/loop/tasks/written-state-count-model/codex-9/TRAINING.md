# Training, addressing and scale

The next training deliverable is a count table written on Wick and read back through the released model's D11 loader. It can proceed alongside the selector work. One path tests whether a geometric address predicts held-out text. The other tests whether the writer uses the entity the user requested. Passing either experiment leaves the other question open. ## What the corpus and compute already establish

D87 split v1 has 519,580 TRAIN records and 2,091,560,001 tokens. DEV-test has 5,321 records and 21,349,576 targets. The initial 13-gram overlap was 30.5%. Two proposed deduplications cost too much data. The accepted decision retained v1, kept the record-level 50-token overlap gate visibly **FAIL**, and required the novel subset for Q. A novel target has a preceding 13-token context absent from TRAIN. Report both sealed series. The order-10 modified Kneser–Ney reference scores 1.418136 bits per byte (BPB) overall and 1.743746 on 14,795,227 novel targets. The 0.80× thresholds are 1.134508 and 1.394996 respectively. Order 10 reached the key-width limit while still improving. The PPMd anchor remains an outstanding non-gating diagnostic. [Split decision](../claude-417/REPORT.md) · [Corpus receipts](../claude-420/REPORT.md) · [Sealed reference](../claude-422/REPORT.md) · [Decision card](../claude-409/REPORT.md)

A full TRAIN sweep against DEV-tune's keys took **288 seconds** on a shared Wick 4090, with byte-identical counts. The next revision encountered GPU memory exhaustion on Wick. On an idle rented 5090 its same-machine comparison reduced 444.8 to 262.7 seconds at 16,028 MiB peak GPU memory. The historical 4,096-row scorer measured **32,368 targets/s** at one coordinate. These operations measure different work. The PI review estimated a billion-coordinate search at 900–2,000 GPU-days. The adopted path counts integer cells, refines selected cells and reserves coordinate search for a small transport core. ## Sequence and stop conditions

1. **P1 — write and reload the count base.** At 1%, 10% and 100% of TRAIN, write ordered prime context keys, count rows, Pick and the integer mixer. On the 1% slice, match unpruned triple hashes on GPU and CPU. After declared pruning and rank quantization, match writer, CPU oracle and D11 loader hashes. Fit deployable mixer weights on held-out TRAIN. Require ≤4 GB resident, ≤1.03× reference BPB and the paired 7,002/14,287 ft/dev floor. Compare with Pick disabled. Report the test-fitted mixer ceiling separately. At ≤0.85× the reference, counts carry much of Q. Above 0.90×, P2/P5 carry the quality risk. Record bytes, pruning cost and run time at each size. Above the 3% pruning-cost limit the decision provides an optional memory-mapped higher-order suffix index. Report its disk bytes and cold access time. [Native state and replay](../claude-409/NATIVE-SPACE.md) · [Gates](../../../../../PLAN.md#approved-sequences)
2. **P2 — establish whether transport carries predictive information.** After P1 identity and pruning cost pass, run E8-snapped state rows, exact backoff, Starling neighbour reads and the geometric output expert. Require ≥1% fewer DEV-test bits than the best equal-byte control, with paired prompt-bootstrap 95% interval excluding zero. Controls are tuned token suffix, re-seeded group transport and SplitMix on the same prefix. The 128 KiB two-frame diagnostic lost to a one-token suffix (4.606925 vs 3.844426 BPB), with 61 held records against 200 required. Compare occupied addresses, successor dispersion, retained events and miss/backoff rates to locate the lost bits. On failure, try VSA SplitMix binding, Hopf sector, the 600-cell and the golden shell in the registered order. If all four lose, keep their results and raise the planned geometry decision with the owner. [Diagnostic](../codex-1/COUNT-RESULT.md) · [Registered arms](../../../../research/reviews/pi-review-2026-11-16/DECISION.md#p2-geometric-state-rows-s3-and-the-geometric-output-expert)
3. **P3 — couple selection to learning.** After P1 and P2 or its registered next arm, run 2–3 epochs of integer Brier error writes to S3/S4/S6, in canonical order. Keep S2 errors a separate arm. Compare count-only, no-memory and shuffled-role controls. Require ≥1% fewer test bits than count-only, Brier falling each epoch, R1 ≥52/128 and R2 ≥200/256, with fresh R4 ≥200 rows. Score free replies against both controls with the paired band. [State update](../claude-409/NATIVE-SPACE.md) · [Reply gates](../../../../research/reviews/pi-review-2026-11-16/DECISION.md#p3-conjunction-pointers-error-written-learning-replies)
4. **P4 then P5 — qualify the artifact before tuning transport.** P4 requires the frozen S0–S6 artifact, ≥64 raw-word CUDA/M1 replays including misses, ≤4 GB resident and ≥1,000 warm tokens/s at 2k context on one M1 performance core. Report cold performance and score pinned chat-v0-p2 on GPU against the absolute 0.90 BPB bar. After P2 and P4, tune ≤100,000 S1 coordinates. Require ≥1% DEV-test Brier improvement per GPU-day over the first two days against equal-trial re-seeding, without rising BPB. Otherwise freeze S1. The original estimate allowed ≤2 GPU-days through P3 and 2–6 for P5. Implementation, rework, device contention and M1 qualification add wall time. P6 needs a ≥2% BPB gain per doubling over the 10–100% P1 curve and owner release for donor compute. Measure tokenization, counting, freezing/loading, prefill and decode separately. Publish CPU/GPU wall time, peak device and resident memory, serialized bytes and D5-a/D5-b for the same artifact. Count ≥1 billion cells actually written or refined and report their bytes. The stronger equivalence label requires simultaneous quality, reply and local budget evidence.
