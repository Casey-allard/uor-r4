# [codex] Draft sheet — ordered versus unordered query context

**Comparison.** On identical ordinary text and complete word candidates, vary only the transport of context around each span. The measured effect is paired accuracy in both role-swap directions, with exact writer replies and no-request controls. This is a component diagnostic with annotated question bounds as a common intervention. The full-prefix frozen arm provides the corresponding ordinary runtime reference.

## Input, operator and state

Tokenize the complete ordinary one-turn prompt with the pinned D11 tokenizer and chat framing. Keep the original BOS-inclusive tape and half-open whole-word endpoints. Give both learned arms precisely the same candidates and the same noncandidate context. The tape and question bounds are common. Labels are restricted to TRAIN updates and separate grading/oracle files.

Decode the four existing D11 orbit root IDs for each context token into four signed integer eight-coordinate blocks using the D11 orbit table. For each candidate, take up to 12 actual tokens outward from each endpoint inside the question, with distance starting at 0. Omit the candidate's own tokens. Pad unavailable context with zero. In each eight-coordinate block, let P cyclically permute the eight coordinate indices and negate the wrapped coordinate. This is an exact orthogonal signed permutation with period 16. For distance d use P^(d+1) on left context and P^(-(d+1)) on right context. Sum into a single 32-coordinate candidate vector. The unordered arm sums the identical context tokens under the identity map on both sides. Both arms read the same IDs, use the same clipping, spans, coordinate table, number of coordinates, weight slots, update schedule and writer. Roles never depend on a cue list or a fixed position. A permutation of the same local token bag preserves the unordered sum. The ordered sum can change under that permutation and is still subject to actual signature collisions.

Train three signed i16 32-vectors plus one i16 bias per class for requested, excluded and neither, initialized at zero. Use integer dot-product accumulation in i64 per candidate/class, floor-free signed comparisons and the same deterministic unit-step multiclass hinge in both arms. For each canonical TRAIN candidate, with gold class g, choose highest rival r in fixed class order. When the margin is below 1, add the integer feature and bias 1 to g and subtract it from r, saturating i16 on write. Make two TRAIN passes in fixed prompt and original-start order. Decode each semantic role by its best strict positive margin against both other classes, with abstention on equal best margins or a margin ≤0. Publish saturation counts and signatures before interpreting a negative. Each arm has 198 bytes of learned weights and biases. Bind both arms to the same codebook, tokenizer, word classes, zone definition and rule version. Serialize flags and state words in canonical little endian, binding training tape, ordering and hashes. No post-fit numerical conversion.

Use one typed `RoleFeatures`, `RoleScores`, `RoleDecision` and `RoleUpdate` contract behind the Rust and CUDA paths. The forward operation used to compute updates is the forward operation used after reload. Before deciding measurement, exercise exact raw replay on finite counterfactuals through serialized reload and D11 writer. Compare 32 feature coordinates, scores and rank margins, selected original spans, any source address, read/cursor/release fields, feedback IDs and stop step. Include reversal, ties, missing tokens, saturation, malformed bounds, multipart pieces and no-request. Reserve a WASM compile check when the shared Rust path is connected. A backend discrepancy or inadequate resource receipt stops deciding collection. Finite operator/oracle checks can still identify the instrument limitation.

## Frozen panel and arms

Use 8 whole TRAIN wording families, two distinct clause-order realizations per family and 32 fact pairs per family, both directions. Use 4 independent evaluation wording families with 32 distinct supported fact pairs per family and both request directions (128 pairs / 256 supported rows). Sample fact order and value order independently of query orientation; keep facts and values fixed within a pair. Alongside the supported pairs include 32 rows each of unbound ordinary prose, incidental supported name with no request, explicit unmentioned name, and explicit conflicting values (128 controls). Independently freeze cases for simple request without exclusion, “Regarding” without exclusion, reversed “except”/“set aside,” and two-clause redirects with an incidental supported name. Each evaluation family must have distinct wording and construction from TRAIN; if a named pattern already appears in historical panels, author a distinct construction within the family. Require paired lexical-bag identity on at least 64 of the 128 pairs at tokenized question scope and separately report actual per-candidate unordered feature collisions. Match single/multipart names and casing across labels. Use independently assigned disjoint name strings, literal values, connector constructions and prompt hashes across TRAIN and evaluation. Audit normalized complete prompts, delexicalized/tokenized wrapper sequences and role-cue phrase overlap against TRAIN and exposed fixtures before release. Shared subword pieces and language function words are expected. Report overlap and alias counts; do not drop hard rows after the seal.

Author held prompts and judgments independently of training patterns and model outputs. Seal TRAIN-only data and both architectures and fit rules before exposing held labels. Record all seeds and exact panel hashes. Train with both existing seed artifacts as separate reads of the same questions. Count each pair once in uncertainty estimates. Keep the sealed count DEV-test outside this work.

Compare frozen full prefix, frozen true question, frozen true question with lexical-only exact prior-fact eligibility, unordered geometry, ordered geometry, and exact requested-role oracle. The lexical filter is a diagnostic coverage bound; both trainable arms retain all question candidates and therefore can nominate a requested entity even when no fact exists. A matched wrong-endpoint oracle uses the other factual name on supported pairs, and a no-read arm forces ordinary generation. Run both through the same frozen writer and actual feedback. Include finite shifted-region replay from #4101 as a plumbing control.

## Readout and decision

Log by row: original labeled and proposed spans, enumeration and lexical-eligibility status, features, role scores and tie/abstention, supports and agreement, source and first writer action, expected/actual token and index at the first mismatch, EOS and full IDs. Grade exact through EOS for literal requests, exact requested and excluded endpoints, and both directions correct. Give the blinded prose grader a row-specific acceptable response or explicit abstention reason before inference. A reply must address the actual noncopy question or state the relevant uncertainty. Code a context-free acknowledgement as generic and failure to reach EOS within the fixed 16-token limit as truncation. Log unsupported copying as an independent trace flag. Record generic acknowledgements verbatim. Report no-request abstention separately from no-copy and from correct prose.

Draft advance rule for independent review: ordered must gain at least 8 of 128 supported both-directions-exact pairs over **each** of unordered and the frozen true region, with paired 95% interval excluding zero against unordered (stratify by family, resample fact-pair blocks), agreement in direction across both seed artifacts, and no added unsupported copies on controls. No-request false nominations must not increase over either comparison. Report each family, token-zero gains and harms, and exact-source gains even if answer strings coincide. If only lexical filtering helps, investigate coverage. If lexical sets match and the role-only oracle repairs output while learned transport does not improve, preserve the role-model negative and report whether ordered feature collisions explain it. If the role-only oracle still misses, trace the fact/value/writer transition. A guard, bind, or replay failure leaves the comparison unread.

Before authorizing collection, register source/fixture hashes, budget and independent FIT. Provisionally bound to one 4090 already on Wick, a 30-minute allocation estimate and one independent cold replay. Record elapsed/device time, peak memory, bytes and candidate work.
