# Ordered role panel custody audit

Review these artifacts before fitting any role bank. The panel generator reads tokenizer and D11 asset bytes and the frozen paired-role class table. It decodes and enumerates candidates without calling the role ranker, source selector, training loop, writer or autoregressive model. The audit uses pinned seed-specific artifacts. The texts and intended judgments are common across seeds. Test whether the original token tapes and all grades other than seed metadata coincide before reusing them.

## Sources and ordering

- `design.rs` contains the wording templates, case-independent name spellings, value vocabulary and prose judgments. `panel.rs` contains the deterministic ordinal assignment to rosters, case, fact order, value strings and direction. The facts and the third person's incidental role stay fixed during each reversal. The two competing referents take opposite requested roles in the paired rows.
- TRAIN comprises eight wording families, each with 32 factual pairs, two question realizations and two directions, followed by 32 rows in each of four control strata. Held comprises four new families, each with 32 factual pairs and two directions. Their realization is determined by the high bit of the fact-pair ordinal. The held panel includes the same four control strata at 32 rows each and 32 extra role-preserving question reorders.
- Each reversal preserves fact order and history bytes. Fact order reverses at ordinal bit 3, case flips at bit 2 and roster changes via the two lowest bits. Direction reverses the requested identity. The first requested identity is a function of the roster, fact order and family and is balanced by the opposite direction. Check these conditions independently of the grades.
- The supported counterpart for each incidental question is picked by the prespecified family and pair order. It keeps the assertion text and changes only the question from a request for the named person's item to an ordinary question with that same name incidental. Compare facts, literal target, request role and exact original IDs before releasing the custody files.
- The three authored abstention reasons distinguish no unique request, absent support, and incompatible simultaneous support. Explicit absent or conflicting requests still have a gold requested endpoint. Treat unrelated acknowledgements as failures of relevance on the prose controls. The prose expectations describe semantic content and allow paraphrases. Grade cutoff at the 16-token cap separately from relevance.

## Review record

Record the reviewer, UTC time, source SHA-256, executable SHA-256, seed model/tokenizer/role-bank SHA-256, protocol identity, and SHA-256 of each custody file. Use separate output directories for independent regeneration and the cold replay.

1. Reconstruct every blind text and expected assistant continuation directly with literal protocol 2. Verify the original BOS-inclusive IDs, the assertion/question/assistant split at exact decoded byte boundaries, and each requested and excluded full-word endpoint. Require exact literal continuation IDs copied from the declared assertion value and finished by EOS. Rows in the four unsupported strata carry null expected IDs. No gold text, interval, positional evidence or matched identity appears in the blind file.
2. For each actual factual name in a held pair, look up the whole-word ID sequence from its assertion and resolve the first occurrence of that sequence among admissible question spans. Verify that the unique match in both directions maps the same identity, and both exact requested labels reverse. Evaluate the two 12-token outward windows after question clipping, leaving absolute locations intact and skipping structural positions. Compare the sorted original IDs, the 32 identity coordinates and the 32 positional coordinates. Record both edge distances, admit both candidates, and retain every failed pair. The census fingerprints every alternate admitted span and records all nonadmitted spans.
3. Compare exact prompt hashes, normalized question wrappers and delexicalized constructions, complete names and case aliases, full literal values, and shared tokenizer pieces with TRAIN and the historical paired-role generator. Inspect label-independent case, fact order, absolute query order, position and segmentation within each direction. Record overlaps by category. Shared function words or subword pieces do not replace the exact leakage check.
4. Verify minimum 16 matched pairs per family for both seeds independently. Keep the matched indices and grades separate from any full-prefix or globally bounded scoring run. Run a finite feature audit before fitting. For every row and arm under public and bounded replay, check grade-file removal and label permutation leave inference trace bytes identical. Record execution checks separately from pre-inference structural isolation.

## Grading key

Each row in `*-grades.json` includes its exact request and exclusion spans if any, stratum, pair and direction, authored question, fact name and value spans, deterministic companion ID where applicable, and literal continuation when supported. `held-match.json` carries original row indices and the two same-identity mapped spans in assertion order together with eligibility and failure reasons. `*-bounds.json` carries only ordinal half-open question ranges. `*-blind.json` carries only untreated text and prefix IDs. `*-census.json` is a separate audit tape and never enters an inference invocation.
