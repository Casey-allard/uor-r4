# [codex] Equal-byte count comparison on Wick

**Outcome: descriptive configuration negative.** With a 128 KiB count model per arm, the two-frame transport used 4.606925 bits per byte on the held-out documents. An ordered one-token context used 3.844426. The two-frame transport also missed the registered 1% gain over each of the other two controls. Only 61 odd records were available against the minimum of 200 for a positive decision. P1(a,b) and the full P2 S3/output-expert experiment remain open. **Paired difference in all-target BPB, transport minus control, by whole held-out record.** Against the one-token control: +0.762498 [0.700148, 0.833649]. Against the re-seeded group: −0.002568 [−0.009771, +0.003856]. Against SplitMix: +0.047415 [+0.007325, +0.094760]. Lower BPB is better. Corpus positions inside one record share a resampling unit. Secondary response-novel BPB reverses the ranking against SplitMix; the registered primary remains all targets.

**Data and storage.** The run hashed the full canonical c420 TRAIN, DEV-tune, response-mask and ID-byte files against their receipts, selected the longest complete-record prefixes under the sheet limits, and trained on 483 records (1,047,021 tokens; 1,046,538 non-BOS targets). Of 523,023 DEV-tune tokens across 123 records, even records selected k; odd records supplied the measurement. Primary: 265,125 targets / 539,966 bytes. Novel: 243,576 / 496,749. Response novel: 227,288 / 456,629. Novelty was recomputed from this exact TRAIN slice; only within-record preceding windows of 13 count. No DEV-test record participated. Every arm freezes exactly 131,072 bytes, including its direct-address index. Each pays 32 bytes of header and 16,384 bytes of unigram counts. The two transport arms pay another 8,224 bytes for 4,096 packed token-root pairs, 4,096 multiplication-table bytes, and 32 step actions. The controls invest those bytes in 257 extra 32-byte rows.

**Interpretation.** Both transport arms hit fewer rows, and four retained successors cover substantially fewer TRAIN events. The geometric arm and the re-seeded arm saw almost identical row coverage and had overlapping paired all-target performance. Either limited state discrimination or heterogeneous next-token distributions inside those rows could contribute. This comparison does not isolate these causes. A P2 diagnosis can measure target dispersion per S3 bucket at fixed bytes, compare state-only versus the planned (state, last-token) back-off, and preserve the output-expert ablation. This pilot exercised two native group frames from twelve prefix positions. Full E8 snapping, neighbour miss reads, learned transport updates, and the S3 output expert were outside its scope. The BPBs here use a tiny TRAIN prefix and the pilot's bounded top-four head. Comparing them directly to full-TRAIN modified KN on sealed DEV-test would mix models, streams and denominators.

**Checks and costs.** Wick, RTX 4090 / sm_89, ahead-of-time compiled integer CUDA. Five finite arms reproduced every byte of their independent CPU oracle table and all 1,344 target masses per arm. A reversed-order input moved the finite geometric address. The complete-support normalization fixture on held and empty rows had Q32 shortfalls of 127 and 207 units, inside the 8,192-unit rounding bound. All emitted-token masses were positive; unscored BOS contributed its analytic floor when summing the vocabulary. The initial smoke ran before taking the private lock. The same fixture reran under the lock with an identical transcript before either empirical run. The input-denominator and within-record novelty unit tests passed. The original sweep took 63.93 s, the reporting replay 61.63 s. Peak host RSS (871,064 and 875,976 KiB) exceeded the 512 MiB planning estimate. No rental was used. The existing KN CLI stays the default binary of its standalone manifest.

**Reproduction.** Build the standalone KN instrument on Wick with `UOR_NVCC_ARCH=compute_89 cargo build --locked --features cuda --manifest-path docs/labs/kn-reference/instrument/Cargo.toml --bin equal-count`. Run `equal-count fixture` under the project lock, then `equal-count INPUTS_C420 SEED1_D11 NEW_OUTPUT_JSON`. A fresh output path is required. The executable refuses another model hash, another corpus, a changed response mask, or a changed token-byte table. The host release was the pre-outcome FIT and D67 record. A second executable added per-record tallies and occupancy only. Removing those fields and their schema from the replay with jq produced byte-identical sorted JSON to the first sweep, including per-arm frozen image hashes, every target mass digest and every interval. Records carry sufficient statistics only. [Finite result](count/fixture.log) · [Sweep timing](count/sweep.time) · [Replay timing](count/replay.time)
