# [codex] P1 component registration. Count capacity across suffix depths

**Decision.** Determine if spending an unchanged physical D11 byte budget on longer ordered contexts saves held bits compared with retaining every exact order-one row. This is the codex-12 component gate. It precedes the PLAN P1(b) comparison with sealed R* and does not release P2.

**Frozen rows.** Use the existing order-0 through order-4 CUDA exact counter and ordered `PrimeRouteKey` capacity. Same D87 v1 source and corpus record-ordinal seed as codex-11. Remove TRAIN fit records (ordinal 1 modulo 1,000) from counting, including on the 100% counting sweep. Count record ordinals 0 modulo 100 at 1%, 0 modulo 10 at 10%, and the complement of the fit partition at 100%. Keep all scored targets in an admitted document, with BOS as oldest-only context and EOS as a target. Use no token-ID remapping. Bind TRAIN stream, fitting stream, tokenizer, transcript, fixed mask, device and artifact hashes.

**Controls.** Unpruned order-one rows define the row budget B at each corpus size. Compare exact counts in intentionally different row allocations across depth 1/2/3/4, `[100,0,0,0]`, `[75,25,0,0]`, `[50,35,15,0]`, `[40,30,20,10]` percent of B, integer division first and remainder to depth 1. Fixed twelve-byte slots in every arm, no empty padding counted as retained capacity. Rank candidates at each depth by descending exact TRAIN counts, then by ascending canonical `(context,target)` key; store in ascending key order. Use exactly the same D11 trunk and exact unigram in all arms. Report an additional unpruned depth-2 comparator at 1% if its distinct rows fit the registered capacity guard, with its larger true byte cost shown. Report legacy exact bigram as a separately identified sanity check. No selection based on blind DEV-test.

**Native operator.** Persistent count word `u64` stores order in the top nibble, four latest-first 12-bit ordered slots and a 12-bit original target; `u32` stores the exact count. A loaded row keeps its Q24 mass and the original key, and count bytes round-trip exactly. Context lookup uses the final admitted suffix; each missing expert reuses the shorter expert. Weight 8/256 is reserved exclusively for the full-support Q24 unigram. Remaining weight 248/256 is split among currently configured depths; a deterministic four-pass responsibility fit uses only TRAIN-fit records and the final integer weight vector is serialized with the counts. No gradient or float master. Each fitted weight remains an integer and every mix conserves exactly 2^32. CUDA reconstructs the same normalized masses independently from closed/reloaded state bytes. Replays compare all target Q32 masses and Q12 bit totals against the Rust reader, plus exact greedy IDs at registered readback probes. Finite fixtures exercise identical last ID with distinct earlier context, missing-row backoff, exact conservation, full support, deterministic ties and corruption rejection.

**Decision rule and evidence.** Score all 2,670 D87 DEV-tune documents and the pinned historical novel mask, including EOS and excluding BOS, on Wick. Compare paired document bit totals over identical decoded-byte denominators. First test at 1%, requiring a 1% relative overall *and novel* bits reduction versus the strongest matched-budget order-one arm and a paired document bootstrap interval excluding zero before interpreting a quality win. Print every arm even if it loses, exact numerator/denominator, matched file bytes, frontier against unpruned depth-2, number of fallback events, normalized support/conservation, greedy parity and counts of used rows. If all allocations lose, keep the result and compare the larger unpruned depth-2 dose to distinguish an allocation cost from lack of depth information. Require a cold rerun from a fresh root to retain the same artifact, weight and device tapes. Historical exact bigram score was 2.835339 overall / 2.949505 novel at 1%, with weight 242/256; this new floor differs.

**Launch and limits.** Use Wick RTX 4090, ahead-of-time nvcc and the shared `wick-codex-gpu.lock` under `20261118-diagnostics`. Stay under P1's one GPU-day total. Before 1%, confirm ≥2 GiB device free, ≥12 GiB host available, ≥12 GiB free disk, all pinned inputs and exact executable/source hashes, a successful finite device/loader fixture and non-author FIT against the implemented operator. Escalate to 10% and 100% only after observed resources are priced and reviewed. At 1%, compare the canonical GPU and independent CPU triple-stream SHA at each depth before choosing rows. Larger trials stream counted partitions and bound retained rows by physical budget; report any resulting scale blocker as an instrument/resource outcome.
