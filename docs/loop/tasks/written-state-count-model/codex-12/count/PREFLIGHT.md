# [codex] Standalone input validation and unchanged CUDA replay

The exact-head preflight found that the standalone CUDA scorer trusted the on-disk token range and normalized partially checked sparse count words. The ft/dev launcher checked the headered token file while the GPU consumed a separate raw copy. The scorer now checks every token ID, weight, unigram and ordered count row on the host before creating device allocations. It validates the signed-off bounds for the Q8 weights and per-context count totals. The launcher checks the SHA-256 of the raw input and requires it to equal the exact token-file payload after the 64-byte header. It verifies both D11 and native state hashes for each arm before launch. [Repaired CUDA source](../../../../../labs/kn-reference/instrument/src/bin/context-score.cu) · [ft/dev launcher](../ft-dev/run-wick.sh)

On Wick, independent finite plants for an out-of-range token, discontinuous and non-conserving weights, invalid unigram, zero count, noncanonical context key, overflowing row total, duplicate row and absent configured order all refused before output. CUDA devices were hidden for the refusal cases. The actual ft/dev launcher refused an altered raw tape at its checksum. The fixture driver then ran the rebuilt AOT scorer under the shared GPU lock. All 20 generated finite files matched the original bytes, covering D11 artifacts, fit word tapes, reload streams and score tapes. The rebuilt and historical binaries generated the identical full-minus-fit depth-four ft/dev tape with stride one, also matching the original captured tape. The rebuilt scorer repeated the same arm on all D87 DEV-tune rows, and the complete device tape matched the original.
