On the historical mixed panel the repaired nominee pointed to the requested queried word on all 96 positive and absent items. The 24 earlier false vetoes on “Regarding [person], what did the entry name?” disappeared; the previous action nominated token 1412 for “name” on all 24, and the new nominee did so on zero. The combined arm issued zero reads on 48 absent and 50 ordinary prompts, but all 48 ambiguous questions received a source. Questions such as “Between Ben and Sue, what did the unspecified person hold?” require an explicit null or ambiguous requested role. A predictor required to nominate a word can invent a referent even with exact occurrence verification.

On the new crossed 288, old→new nomination accuracy rose 96→192. Of the 192 unsupported questions, old action, nominee-only, support-only and both issued 88, 120, 64 and 64 sources respectively. The combined arm's 64 failures all chose the excluded word, 16 each on conflicting, negated, removed and third-person conditions. Correctly nominated negation rows had no eligible earlier fact. The TRAIN-learned delimiters were token IDs 16 and 28; a negation prefix prevented the negated subject from following either. There is no general learned proof of negation scope. The 32 correctly nominated duplicates had two eligible earlier facts and were all rejected. The 16 remaining duplicate queries chose the other subject and copied its value. The query oracle found both actual occurrences across all 48 duplicates and all 48 conflicts, and zero earlier admissible occurrences on the 144 negated/removed/third rows. It still chose the wrong value on seven of the 48 singletons. On transfer, the oracle nominated the correct word in all 1,728 and left 114 downstream source errors. On the earlier unseen panel it recovered every address. These are distinct requests for work on query role and value-span boundaries.

**What was fit.** The two-pass GPU extractor wrote the token preceding an annotated affirmative fact then the eight-word requested/other descriptors. Both seeds yielded three distinct positive and 308 negative descriptors. The positive sites were all initially uppercase. Each descriptor contains packed-root neighbors, case and a bit indicating a preceding TRAIN fact delimiter. The nearest-class signed distance selects among all alphabetic whole words without a name list. The case signal, positional context and learned delimiters were introduced jointly; this run does not isolate their contributions or establish lowercase-name transfer. No new trainable dictionary or gate threshold was fitted on held. Nominee-only holds the previous role-selected candidate and original permission prototypes fixed and replaces their unrestricted nominee. The exact-one arm independently elects an earlier fact from the nominee and sends it through the same frozen value/continuation operators. For this reason an old-action→exact-one difference includes both binding and permission. The contrasts within either permission rule isolate nomination.

The device runs ahead-of-time CUDA and compares every extraction, role decision, support count and action word against the host instantiation of the same typed operators. Each state is persisted as exact native integer words. Primary and repeat execute TRAIN and all held splits in distinct directories. Rust checks model/tokenizer/span/bank digests and every handoff-prefix digest. The frozen continuation separately checks its device/host words. The first launch rejected a stale directory reference and an incorrect copied tokenizer digest during preflight. The first historical mixed grade-only query projection assumed all new names comprised one BPE token and rejected a multi-piece name. The sealed blind outputs remain in the instrument archive. The corrected post-blind projection compares complete word spellings in the reference tokenizer; it never enters a blind process.
