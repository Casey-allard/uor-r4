# [codex] Whole-context retention under a physical byte cap

The live P1(b) gate requires a frozen model of at most four decimal GB that meets the paired DEV-test bar. P2 later requires a common deployed budget across four address arms. The present unit qualifies the retention and readback instrument with no DEV, prompt, or quality-driven threshold selection. Its physical size is necessary for those later comparisons.

**Retention.** Preserve every group at orders 0–3. For each higher order define support as the exact u64 sum of its raw follower counts. Retain the whole group when support is at least T, with the original canonical order, raw counts and adjusted counts. Recompute stored discount spectra from retained follower words per codec. Choose the smallest positive T whose complete serialized count file fits the specified cap. If no high-order group fits, permit an empty high-order section when the native codec admits it. If the mandatory low-order floor exceeds the cap or the codec cannot represent the result, stop with a specific reason and retain any unique diagnostic. Do not split tied-support groups to force an exact size. Charge actual bytes and report slack. Equality of thresholds or count files across unequal budgets supplies no equal-byte P2 evidence.

**Finite and archive controls.** Start from the exact archived GPU C128 UORKNC02 with 111,671 tokens and C1 with 20,754,301 tokens. Require complete byte identity on the C128 all-retained setting, a pruned run at 8,388,608 bytes, a second cap that forces a distinct threshold (derive from the observed support-size steps only), a deliberately impossible floor, and a no-clobber retry. If the 8 MiB cap falls in a codec gap, preserve it and use the next representable support step as a labelled control. At C1 use a 256 MiB compact budget for a genuine constrained reconstruction. A verifier implemented separately decodes all groups, independently prices T and T−1, checks counts, spectra and cold lookup from original token IDs, exercises ID/context back-off, and rejects a changed follower plus a valid but wrongly omitted group. Report elapsed time and peak memory by program. These operations serialize or verify prior GPU count state. They do not fit or evaluate a new language predictor.

**Full dose.** Before GPU dispatch require an exact C stream and independent census, projected on-disk spool and bounded host/device memory, a named non-author FIT, finite GPU agreement and matching source/binary hashes, a private output root and a live lease or bare-metal Wick lock. Never allocate the approximately 148 GB unpruned stream in RAM. The proposed full-dose compact cap is 3,912,936,331 bytes. It reserves 86,536,132 bytes for the frozen trunk, 265,393 for the tokenizer and 262,144 for the fit, metadata and envelopes, totaling 4,000,000,000 bytes. This last charge is an engineering reserve. Once R is fitted, measure each actual component and the final physical D11. Full counts require confirmation of canonical raw and adjusted spectra, group cardinalities and per-order full hashes, with the documented historical highest-order alias handled by an explicit identity check. A semantic or resource mismatch stops advancement; passing the count unit admits the separate R-only fit with lookup from the actual deployed pruned state. A small fixture, a historical measurement, a reserve or a file size alone cannot qualify P1(b).
