## Plain summary

- **What this task tested**: In `#2831`, training the discrete geometric model one coordinate at a time (`K = 1`) with 64-batch admission-preserving rollback lifted `FrozenZero` accuracy on the 14,287-row development panel (`DEV`) from `133` to `871` top-1 correct predictions at batch `4,096` (`Q1`), then stopped because single-coordinate greedy moves on 64-row batches repeatedly tripped the 64-batch rollback guard. Stage T (`#2836`) tested whether scoring and committing `K = 16` coordinates per batch (`BVG-K`, qualified in `#2835`) overcomes that bottleneck and beats both the unigram count table (`1,226 / 14,287`) and the admission-matched next-word count tables (`W2`, `#2845` / `#3179`) on two independent seeds (`seed 1` and `seed 2`).
- **Four instrument pieces built first**: Before running any GPU training, we built `crates/uor-r4-discrete/src/stage_t.rs` and `stage-t-run`: (1) a straddle-aware D40 controller that tracks `K = 16` blocks across token vectors, `Combine` gates (`0..20`), `Relation` gates (`20..45`), and the straddling read block `16..32`; (2) Seed-1 and Seed-2 configuration manifests; (3) the five mandatory Step 0 GPU controls (`AKd` single-move apply parity, `V1d` `K = 1` transition parity, `KId` block loss/epoch accounting, `V8d` `FrozenZeroV1` zero-trit invariant, and `V9d` checkpoint-resume bitwise parity); and (4) the GPU checkpoint-restricted W2 count-table evaluator (`T_restr(A_W)` and `G_restr(A_W)`, which measure how many DEV tokens an exact integer count table built from the `1,049,856` training rows predicts when restricted to the model's 8 admitted candidate cells $A_W$ on each row).
- **What happened on the GPU**:
  - All five Step 0 GPU controls passed (`5 / 5 PASS`, `0` mismatches, `57,156 context tokens/s`).
  - On `T16_fz` (`FrozenZeroV1`, Seeds 1 and 2), `K = 16` block learning committed `420` updates (`854` coordinate moves, `123` multi-coordinate joint commits), lifting the 3,847-row training admission anchor from `1,211` to a peak of **`1,823`** and expanding DEV cell shortlist admission from `4,244` (`4,292` at `K = 1` Q1) to **`5,009 / 14,287` (`35.06%`, passing `G-Adm >= 4,220`)**. Distinct 16-bit read codes grew from `14,412` (`K = 1` Q4) to **`19,385`**, and the checkpoint-restricted count tables on the `5,009` admitted cells jumped to **`T_restr(A_W) = 2,140 / 14,287`** (`4,006` top-8) and **`G_restr(A_W) = 3,084 / 14,287`** (`4,674` top-8) — beating the unigram bar (`1,226`) and `#3179`'s baseline W2 tables (`1,138` and `1,482`) by `+914` to `+1,858` rows.
  - On `T16_rel` (`LearnV1`, Seeds 1 and 2), `K = 16` ran all `4,096` batches to `Q1` (`678` updates, `1,505` moves including `425` relation gate moves, `27,132` distinct training read codes, `T_restr(A_W) = 1,602`, `G_restr(A_W) = 2,364`), lifting DEV writer `top-1` `2.79x` over `K = 1` `Relation` (`133 -> 371`, with zeroing the learned relation gates dropping `top-1` by `44` rows to `327`).
  - However, the parameterless `OuterL1V1` writer itself scored `455 / 14,287` (`T16_fz`) and `371 / 14,287` (`T16_rel`) `top-1` (`1,484` and `1,124` `top-8`), triggering `DIAGNOSTIC_STOP_CONSECUTIVE_REJECTIONS` below the `1,226` unigram bar. This isolates the remaining M1 bottleneck cleanly: `BVG-K` (`K = 16`) successfully expands shortlist cell admission (`5,009` rows) and read-code capacity (`T_restr(A_W) = 2,140`, `G_restr(A_W) = 3,084`), while selecting the single winning token inside the 8 admitted cells requires either `#2834`'s full-vector metric / wider carrier (`#2847`) or an explicit integer within-cell lookup table rather than shared-table `OuterL1V1` distance alone.
