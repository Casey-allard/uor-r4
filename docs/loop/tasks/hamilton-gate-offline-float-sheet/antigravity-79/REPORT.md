## Plain summary

Inside a neural network or geometric language model, a **gate** controls how features in a hidden layer pass forward to the next stage. Standard transformer models use a **sigmoid** gate (a smooth S-shaped curve that squashes numbers into the range `0` to `1` to dim or shut off signals), which is banned in UOR-R4 (`CHARTER.md` §3.2). The **Hamilton rotation gate** (`Gate::Hamilton`) replaces that squashing curve with 4-dimensional quaternion rotation: it normalizes each block of four numbers into a unit quaternion $q$ and rotates the matching four-number value vector $u$ by $q \otimes u$, without using exponentials or squashing functions. To serve the trained model as an integer-only artifact (`D11`), each continuous quaternion $q$ is snapped to the nearest of **120 unit icosian roots** (the vertices of the regular 600-cell in four dimensions) and the output head is quantized to **Q12 signed integers** (`i32` scaled by `4,096`).

In this unit (`#2824`), we ran the pre-registered 4-arm $\times$ 2-seed $\times$ 256-step offline-float study on an NVIDIA RTX 5090 GPU (replicated across two independent builds) and answered all three questions required by the roadmap item:
1. **Language fit on integer DEV metrics:** Evaluated at `14,206–14,318 tokens/s` across all `14,287` response positions of the DEV benchmark, both learned Hamilton arms (`Hamilton_Active` and `Hamilton_IcosianHard`) beat the fixed-random-rotation null (`RandomGate_Null`, `24–28` top-1 hits) by `+1,010` to `+1,402` rows and beat the training word-frequency count table (`TrainUnigram_CountTable`, `1,226 / 14,287 = 8.581%`) on both seeds in Build A (`1,270` and `1,298` for `Hamilton_Active`; `1,430` and `1,253` for `Hamilton_IcosianHard`), but trailed the un-rotated identity control (`IdentityGate_Control`, `3,041–3,908` hits) at 256 steps because randomly initialized gate rotations start by scrambling the value stream.
2. **Float-to-integer export gap:** Both Hamilton arms passed the export-gap bar ($\le 398$ top-1 rows). Training with the 120-icosian snap in the forward pass (`Hamilton_IcosianHard`) shrank the float-to-integer export gap from `80–312` rows (`17.4%–20.2%` row-by-row agreement) down to just **`2–23` rows (`0.014–0.161` percentage points)** with **`97.6%–97.8%` exact row-by-row prediction agreement**.
3. **Whether the gate suppressed signal:** Across `78,888,960` observed 4-blocks and `986,112` downstream projection rows per evaluation, **zero blocks (`0.0%`)** ever reduced signal amplitude inside the gate ($\min \rho = 0.99999971$, $\max 1/r = 108.94$, never approaching the $10^{-12}$ division-by-zero guard core) and **zero rows (`0.0%`)** reduced signal norm inside the downstream `SpiralcoreFbs` projection ($\gamma_{\text{down}} = 1.000000$). The Hamilton gate operates purely by steering vector directions rather than suppressing amplitude.
