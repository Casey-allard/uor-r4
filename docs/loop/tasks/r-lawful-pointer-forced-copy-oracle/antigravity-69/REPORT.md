## Plain summary

A pointer head is a mechanism that lets a language model answer a memory question (such as a user's stated locker number or role) by copying the exact stored tokens from earlier in the conversation window instead of guessing from general word frequencies. Earlier versions of this pointer relied on banned floating-point exponentials (`softmax`) and dense matrix multiplications (`matmul`), and existed only on the CPU. In this unit, we built the ahead-of-time GPU kernel (`lawful_pointer.cu` -> `lawful_pointer.ptx`) and batch forced-copy oracle evaluator (`lawful-pointer-oracle`) using pure integer arithmetic: slot addresses are represented as products of two prime numbers (one for the entity, one for the attribute), candidate spans are checked by 128-bit integer greatest-common-divisor (`gcd`) divisibility or a canonical token lookup table (`CanonicalFoldTable`), and the winning token is chosen by integer margin comparison. We qualified two independent builds on an RTX 5090 GPU across all `16` finite CUDA controls and all `256` rows (`128` opposite-role pairs, `10,304` decode steps) of the sealed `m2-fresh256` memory panel at `4.35–4.40 million window tokens/s` with `0` GPU-vs-CPU mismatches, registered the 4-branch diagnostic bar (`D68`), and placed the item on `status: held` until the upstream M2 trunk model (`#2844`) is trained.
