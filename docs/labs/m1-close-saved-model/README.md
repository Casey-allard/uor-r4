## 2. Structural diagnosis: why 4-table `UORLUT01` failed Bar (d) and how 19-table `uor-r4.lut-discrete-trunk/1` resolves it

The 4-table Stage 1/2 schema (`discrete.table`, `discrete.cells`, `discrete.routes`, `discrete.gates`) was bounded below `T2 = 6,300` by three exact bottlenecks, all three of which are resolved in `trunk-joint-pointer-v1-d11`:

1. **Bottleneck 1 — Pre-rotation 8-cell shortlist ceiling ($A_W(q_{\text{read}}) = 5,009 < 6,300$):**
   In 4-table `UORLUT01`, the `OuterL1V1` writer admits `kept_cells = 8` cells minimizing `address_distance(q_read(x), cell)` before any trunk rotation, admitting at most `5,009 / 14,287` (`35.06%`) of `ft/dev` targets (`G_restr(A_W) = 3,084 < 6,300`). Rotating $q_{\text{read}}(x) \to q_{\text{trunk}}(x)$ via `DiscreteHamiltonGateV1` *before* cell admission (`A_W(q_trunk)`) lifts `ft/dev` admission to **`9,012` / `9,010`** (`63.08%`) on the exported 19-table `.d11` artifacts.
2. **Bottleneck 2 — Unconditioned 16-bit read-code collision ($T(c_{\text{read}}) = 4,085 < 6,300$):**
   Conditioning on the joint `(query, read)` and `(query, rec)` codes plus the 4-block $\mathcal{O}_{16}^4$ orbit-root causal pointer (`orbit_root_causal_successor`) breaks 16-bit marginal read-code collisions across the `19,385` distinct TRAIN read codes and `55,440` / `54,563` distinct recurrence codes (`796,076` / `795,317` distinct `(read, rec)` pairs).
3. **Bottleneck 3 — `#2844` `Level 3` marginal query weight inversion (`64 * c_q > 32 * c_qr`) and 4-table export omission:**
   Replacing `#2844`'s marginal-first weights with `level3_joint_pointer_score` (`(ptr_match << 8) + (c_qr << 6) + (c_qc << 5) + (c_rr << 3) + (c_r << 1) + c_q`) and exporting all 19 sections (`discrete.table`, `discrete.cells`, `discrete.routes`, `discrete.gates` + 15 `discrete.trunk.*` sections) via `d11-scorer export-trunk` packs the entire scoring path into the self-contained `.d11` artifact (`0` export gap).
