## 2. Structural diagnosis: why 4-table `UORLUT01` (`IntegerDiscreteModel::evaluate_prefix`) cannot clear Bar (d) (`T2 = 6,300 / 14,287`)

The 4-table Stage 1/2 schema (`discrete.table`, `discrete.cells`, `discrete.routes`, `discrete.gates`) is bounded below `T2 = 6,300` by three exact bottlenecks:

1. **Bottleneck 1 — Pre-rotation 8-cell shortlist ceiling ($A_W(q_{\text{read}}) = 5,009 < 6,300$):**
   Every causal prefix $x$ is mapped by the read tree to a $B$-block canonical E8 orbit-root vector $q_{\text{read}}(x) \in \mathcal{O}_{16}^B$ (`16`-bit read code $c_{\text{read}}(x) \in \{0, \dots, 65535\}$ at $B = 4$). The `OuterL1V1` writer admits `kept_cells = 8` cells (`~128` tokens) minimizing `address_distance(q_read(x), cell)`. On `ft/dev` (`14,287` rows), this pre-rotation shortlist $A_W(q_{\text{read}})$ admits at most **`5,009 / 14,287` (`35.06%`)** of true targets (`4,292` on `#2831` `Q1`; `3,426` on `#2833` `Rung-0 Q4`). Even an oracle that knows the exact query token $q(x)$ inside $A_W(q_{\text{read}})$ is bounded by $G_{\text{restr}}(A_W) = 3,084 / 14,287 < 6,300$.
2. **Bottleneck 2 — Unconditioned 16-bit read-code collision ($T(c_{\text{read}}) = 4,085 < 6,300$):**
   Because 4-table `evaluate_prefix` depends on $x$ solely through $q_{\text{read}}(x)$, any deterministic function of $c_{\text{read}}(x)$ alone is bounded on `ft/dev` by the unconstrained read-code table $T(c_{\text{read}})$, which scores **`4,085 / 14,287`** on Stage T `T16_fz` (`3,414` on `Rung-0 Q4`, with projected infinite-data ceiling `3,552` in `#3179` `QB = B2`).
3. **Bottleneck 3 — `#2844` `Level 3` marginal query weight inversion (`64 * c_q > 32 * c_qr`) and pre-rotation `slots` restriction:**
   In `crates/uor-r4-discrete/src/trunk.rs:724-764` (`#2844`), `select_level3_full_trunk` combined counts as `64 * C_query(q_tok, y) + 32 * C_query,read((q_tok, c_read), y) + 16 * C_query,rec((q_tok, c_rec), y) + 4 * C_read(c_read, y) + C_rec(c_rec, y)` and restricted candidates to `&row.slots` ($A_W(q_{\text{read}})$). Because marginal `C_query(q_tok, y)` is counted over all `1,049,856` TRAIN rows whereas `C_query,read` is conditioned on a 16-bit `read_code`, `64 * C_query` dominates `32 * C_query,read` whenever `2 * C_query(y_marginal) > C_query,read(y_joint)`, overriding exact joint `(query, read)` and `(query, rec)` context matches, while `&row.slots` still caps admission at `5,009 < 6,300`.
