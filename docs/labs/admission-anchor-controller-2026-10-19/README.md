## Implemented behavior

`attention_anchor.rs` authenticates original TRAIN row identity and windows. `attention_audit.rs` separates attempted, provisional, committed and rejected updates with an immutable last-passing pin and mandatory durable acknowledgement. `attention_anchor_device.rs` binds a private audit permit to the actual checkpoint, driver cursor, runtime identity, generation and model hash domains before and after GPU evaluation. Shared `snapshot.rs` extracts storage-only types and hashing without a host forward path.

`src/attention_audited.rs` persists each step before lifecycle advancement. A breached interval preserves failed checkpoint, audit and restore intent before physical restoration. It creates a fresh runtime from the last passing model, advances the schedule to the absolute attempted boundary without applying those attempts again, verifies restored storage/epoch/cursor, then persists the observed final record. It does not deserialize the runtime lifecycle or offer resume. Failure custody distinguishes unavailable readback from a coherent checkpoint.

`src/attention_audit_qualification.rs` provides a separately gated finite qualification route, avoiding a cycle in which dose admission would require qualification artifacts that only a dose permit could produce. Its prospective scope includes existing source controls, a bounded synthetic apply/refusal fixture and 384 actual attempts per registered arm with controlled production restoration. Those source bounds are **not permission to execute**. Controlled restoration cannot be labeled a natural admission breach. Strict consumers authenticate actual producer/runtime/source/config, initial checkpoint and baseline, both named sensitivity probes, raw receipts and restoration evidence. Probe snapshots must equal the independently authenticated initial model.

Timing artifacts distinguish samples from projections. The conservative two-arm projection includes 516 audits, 32,808 step bookkeeping operations, 516 ordinary boundaries and 514 physical restoration plus breach-bookkeeping charges. Production and the metadata timing fixture share the actual persistence helpers, including linkage and progress writes/readback; the serialization fixture includes up to16,922 artifact hashes. Deliberate overlapping charges and the absence of a formal runtime upper bound are explicit. A separate dose decision binds the fresh actual resource/rate and planned setup/custody/archive/close costs. A historical qualification budget cannot stand in for that decision or create a healthy-run hard stop. The registered15% readiness rule remains unchanged.
