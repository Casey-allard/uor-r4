## OpenCode launch and safety boundaries

Use the [continuous startup packet](prompts/opencode-continuous-start.md) in the
existing lab. The old local `/proceed-uor-r4` packet explicitly ends after one
milestone and waits for another owner command. The newer owner instruction
supersedes that stopping rule. Do not run the obsolete command to establish
continuous behavior.

At the inspected version the installed native `/goal` feature is disabled.
Source-extracted stub fixtures reproduced an additional defect: with its hook
enabled, an ordinary user follow-up can replace the objective even when
`auto_start:false`. Enabling that feature also requires a new plugin instance;
editing a config file alone does not activate the currently running server.
Leave it disabled until a reviewed correction and bounded live test exist.

The existing todo enforcer is the smaller available mechanism. Use substantive
incomplete mission/child tasks, inspect whether the hook is disabled, and retain
its existing no-progress/failure safeguards. It is not an infinite scheduler or
an offline/quota recovery adapter. Do not create dummy todos or reset its guards
to force liveness. Do not invoke `/stop-continuation` as a gentle pause: at the
inspected version it also cancels descendant background tasks and clears other
continuation state. Preserve existing delegates and jobs during launch.

A live activation receipt must identify the client/version and exact session,
the mechanism/configuration, initial child, completed child, following child and
automatic transition time, along with source/claim and resource validity. Redact
provider credentials and private transcripts. A mock fixture proves only the
extracted path under its declared stubs. It does not certify the desktop client,
provider authentication, hook enablement or future unattended operation.

When useful work is ready, select the next child before ending the current cycle.
When all safe paths are blocked, checkpoint WAITING with the precise wake signal
and a supported delayed wake; back off on unchanged state. Quota exhaustion
requires QUOTA_UNAVAILABLE and a self-contained takeover packet. The mission
remains unresolved. Never imply that a prompt creates tokens or that a sleeping
host continues reasoning.
