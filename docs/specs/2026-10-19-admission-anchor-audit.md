## Recommended integration

Retain the recommended distinct registered mode in the existing attention controller. Reuse PreparedCorpus original-window reconstruction and Device GPU evaluation/aggregation; do not duplicate the training engine or add an asynchronous watcher. Implement deterministic whole-interval rejection as the PM-authorized conservative case. Do not infer an isolation heuristic or selectively retain allegedly safe updates.

The safest first implementation commit consists of host metadata anchor validation, typed audit/rejection receipts, and a pure interval state machine. Follow it with the narrowly scoped GPU evaluator, plan authorization and controller integration in the same complete source PR. Merge the completed unit before a successor. Host tests may use synthetic counts/state identities but cannot claim model admission or CUDA equivalence.

## State transitions and durable evidence

1. **BASELINE:** authenticate exact TRAIN files, manifest and original windows; authorize the new scoped plan; evaluate the fixed anchor on GPU without updates. Persist baseline count, model storage/snapshot hashes, accepted epoch, driver lineage, attempted cursor, per-family counters, anchor/sheet/plan identity. No DEV anchor or generic post-update eval bypass.
2. **BEGIN:** retain a last-passing immutable model checkpoint and committed-state receipt. Open a fresh interval ID with attempted schedule bounds. Permit speculative transitions only inside that interval. Record each transition append-only with an explicit provisional disposition, prior/next epoch and identity, absolute schedule index and family.
3. **BARRIER:** after each 64 completed attempted batches, and after the final 20-batch tail ending16404, finish outstanding GPU work and status readbacks before the audit. No next transition, Q1 evaluation or final decision may cross the barrier. Seal attempted snapshot and raw audit identity before disposition.
4. **PASS:** if the sheet predicate passes, append an interval commit receipt binding all provisional transitions and checkpoint hashes. Commit their accepted updates and promote the last-passing snapshot. Persist the resulting cursor/counter/epoch tuple before opening another interval.
5. **BREACH:** append AUDIT_BREACH and preserve failed snapshot, raw audit, full transition suffix and rejection receipts. Restore the last-passing model and committed accepted counters/epoch. Reject the entire interval, including every provisional accepted update; receipts must also account for transitions that were originally refused/no-change. Advance completed-attempt/schedule cursor to the end of the rejected interval, rather than replaying it. Append a restore receipt binding failed and restored identities and the advanced cursor. Continue only after the restore tuple is validated and durably recorded.
6. **Q1/STOP/FULL:** audit/disposition first. Apply the inherited Q1 gate to the committed post-disposition model at4096. Apply the registered no-op rules, preserving all applicable reasons: strict rejection fraction greater than one half at Q1/full, or three consecutive full-interval rejections. The sheet states checks at Q1/full/stop; a third consecutive rejection must not permit unbounded continuation until Q1. Exact precedence/output representation should be explicit in code and canonical records. A stop is diagnostic, not a mechanism negative. Final audit is mandatory before final evaluation.

## Counters and checkpoint invariants

The attempted schedule is monotone even across rejected intervals. Keep separate authoritative attempted, committed and rejected interval/update counters, including per-family vectors/combine/relation accounting and FrozenZero refusal history. An accepted update means committed only. Provisional applied updates are not accepted until interval commit. For every closed interval, provisional applied updates partition into committed or rejected applied updates; every attempted transition has exactly one interval disposition. Rejected no-change/policy-refused attempts remain attempts, but are not falsely counted as rejected applied updates. Document these separate domains in field names and validators.

Model epoch equals committed accepted updates outside an open interval; inside it the live speculative epoch equals committed accepted plus provisional applied updates. Rollback restores the passing accepted epoch while absolute attempted completed/corpus cursor/next coordinate advance past rejection. Corpus windows and coordinate scheduling derive from attempted completed, not accepted count. The release maximum is attempted work, not a permission to replace rejected attempts. FrozenZero records all scheduled relation policy refusals monotonically and proves zero provisional and zero committed relation applies, including across rejected intervals.

Existing attention_learning::Counters::validate derives attempted family totals from absolute completed and checks accepted/sensitivity ordering. Restoring this entire old struct would erase attempts/refusals and invalidate schedule accounting. New mode needs a new counter/checkpoint schema and validation path; retain legacy schema behavior unchanged. Reuse training::validate_checkpoint only after constructing a coherent driver cursor with advanced attempted completed and restored committed accepted epoch. Last-passing checkpoint identity itself must remain immutable; a separate continuation state binds that passing model to the advanced schedule cursor.

## Rollback identity and ABA safety

Use training::restore / Device::from_snapshot to construct a fresh Device, not an in-place epoch decrement. Current device.rs::make_binding uses checked NEXT_MODEL to allocate Binding.model, and from_snapshot explicitly allocates a fresh process identity for identical reloads. Existing carried batches/proposals reject mismatched binding or epoch. Reuse this protection. Before restore, synchronize work and drop old proposals, carried batches, evaluation objects, per-model Rows/BVG scratch and temporary per-attempt capability/epoch snapshots; rebuild/re-admit these against the new Device binding. Never transplant scratch or an old proposal to a restored model merely because epoch or model bytes match.

Persist a monotonically increasing run-local restoration generation and snapshot identities for evidence; Binding.model is process-local, so it cannot alone authenticate a cross-process receipt chain. Reload must validate registered checkpoint/lineage and create a fresh runtime binding. Do not issue a new owner personal release per interval: the new run's validated release authorizes the registered active controller, and per-interval tokens are rederived narrowly under it. Crashes during an uncommitted interval must fail closed with inspectable evidence; do not infer resume permission or retry a failed attempt from latest pointers.

## Concrete dependencies and authorization boundary

- corpus.rs::PreparedCorpus::batch / eligible_positions / tokens: original single-row windows and deterministic selected-row packing; original corpus is immutable.
- attention_evidence.rs::is_copy_successor and raw admission predicate: shared host classification/recorded-field verification only; no host model/reference.
- device.rs::Device::evaluate / aggregate_evaluations: minimal GPU anchor loop; EvaluationAggregate.target_admitted_rows already supplies the required count. PreparedDriver::load and evaluate_prepared must not be called wholesale by a strict TRAIN-only instrument because they load DEV / compute unrelated reference evaluation.
- training.rs::checkpoint / restore / validate_checkpoint / coordinate_at / validate_cursor: passing-model snapshot, fresh Device restore and attempted-cursor validation. Do not globally relax post-update or held-corpus guards.
- attention_learning.rs::AttentionPlan / validate_plan_header / validate_execution / validate_owner / save / run / Counters: separate registered command/plan/checkpoint/receipt scope; synchronous barrier, speculative commit/reject and no-op/terminal validation.
- controller.rs and main.rs: explicitly named new mode/commands and serialized schema dispatch. Same A8 table hash cannot silently select the old parent sheet/release. Bind new sheet, anchor policy, active whole-interval behavior, source/runtime, inputs, owner review and exact plan identity. Old consumed personal releases are invalid for this successor.

No implementation is numerically qualified by this design. Final registration/FIT, exact implementation source, actual CUDA build, GPU equivalence/rollback/epoch/cursor qualification, measured cost and applicable owner/PM release remain required before a run.
