# Real-text sparse-recall opportunity gate — prospective plan

## Decision and research basis

The [M1 KVAR result](kvar-hard-successor-result-2026-09-24.md) established a synthetic addressed-memory mechanism; the [loaded lexical bridge](addressed-lexical-bridge-result-2026-09-24.md) established only copied output under explicit typed addresses. Neither says how much long-range, selectively addressable information helps real text, or whether a cheap admission decision can avoid harmful reads. Before adding a learned parser or enlarging authored response panels, measure that opportunity on source-separated project Markdown with the retained 4096-token BPE and a count reference. This is a diagnostic, not a new default model.

[Zoology](https://arxiv.org/abs/2312.04927) motivates separating associative recall from average language loss; its reported synthetic/real-text gap warns against promoting KVAR alone. [Large Memory Layers with Product Keys](https://arxiv.org/abs/1907.05242) motivates sparse accessed capacity, but its transformer implementation and floating-point query machinery are not imported. [Titans](https://arxiv.org/abs/2501.00663) motivates separating persistent memory from compressed recurrent state; its dense test-time memory update is not the serving design here. These are research motivations, not evidence that this project's geometry wins.

## Frozen population and arms

- Collect Markdown under this isolated worktree's `docs/` with the existing `realtext_support::reconstruct_corpus` exact-duplicate grouping and source-hash Fit/Tune/Dev split. Bind each document hash and the pinned derived tokenizer SHA-256 `a7ac75b68aa997fe7cc338d25d843157f2dc9d4265fb2f958ee779bb04828d6f`. Deterministically use at most 400,000 Fit tokens, 100,000 Tune tokens and 24 Dev documents up to 4,096 tokens each, in the library's path order. Dev is a retained/exposed project population, so this is a decision diagnostic rather than fresh generalization.
- Static reference **C**: unigram/one-token/two-token counts learned only from Fit, with its two interpolation coefficients selected on Tune by the existing grid. Report its full Dev bits/token and top-one accuracy.
- For each document independently, after target position `t` is observed, write its `(t-2,t-1) → token_t` association to a finite exact map. Before target `t`, query only earlier writes. The candidate is the most recent exact-pair successor; report eligible rate, lag, conflicts, and count-reference correct/wrong intersections for <64, 64–255 and ≥256-token lag. This is **exact-address copy**, not semantic similarity or a learned write policy. Memory resets at document boundaries.
- **G**: on a hit, blend C with a delta on the candidate using an age-bucket dyadic coefficient from `{0,1/4,1/2,3/4}`. Fit each bucket's coefficient on Tune by minimum bits, requiring at least 32 bucket hits; otherwise use zero. Serving-side choice is a bounded integer age compare and table read; scoring probabilities here are offline floats. Dev selection uses the frozen Tune coefficients. On no hit or NoRead, G equals C. Evaluate a same-bucket candidate-rotation null with the same coefficient and hit positions.
- Retain every Dev position's target, C probability/top-one, hit/candidate/lag, G probability/top-one, and bucket, plus per-document summaries and hashes. No model artifact is trained or modified. Do not treat a read-always oracle as deployable learning.

## Decision

Advance this **particular exact-pair sparse cache** to the native language path only if the held Dev result has all of: (1) ≥1% eligible positions at lag ≥64 and ≥0.5% of all targets are rescued from a wrong C top-one by a correct distant candidate; (2) G improves full-population bits/token over C by ≥0.03 with a document-bootstrap 95% interval excluding zero; (3) G beats the rotated-candidate null; and (4) no source-family group worsens by >0.2 bits/token. Otherwise retain the diagnostic and redirect effort to a learned content/role address or richer state objective. Even a pass is a local corpus component, not general prose, semantic memory, geometric advantage, D5 whole-model compliance or energy qualification.

Use one Rust runner, one offline release build and one sealed attempt. Diagnose a genuine instrumentation failure once if needed; do not expand into a suite campaign or tune after Dev exposure. The [shared ledger](resource-ledger-2026-09-19.md) has the complete resource projection before execution.
