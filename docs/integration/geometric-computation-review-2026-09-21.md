## What the diagnostics do and do not prove

A collision-free finite feature set establishes that a sufficiently flexible function can label those observed points. It does not prove either feasibility or infeasibility of a linear or ternary readout. For example, distinct inputs can have linearly separable labels or XOR-like labels. Feature uniqueness alone does not choose between them.

The served predictor also has example-dependent local logits:

`z_i + 2^shift * W * delta_i`, where `delta_i = R(q1_i)-R(q0_i)`.

A majority table on delta alone is a bound for a **direct delta-only decoder**, not generally a bound for that complete residual predictor. Local logits can distinguish two examples with the same delta. A plateau and a superior table therefore leave optimization, coefficient/support constraints and output interface effects unresolved.

A possible targeted certificate would test the actual competitor inequalities

`2^shift * (W[target]-W[other])·delta >= local[other]-local[target]+tie_margin`.

A feasible real-valued solution refutes “no linear map”; verified infeasibility of that relaxation establishes a fixed-feature/interface limit. Ternary feasibility and active saturation need separate treatment. This is an optional discriminator if it changes a decision, not a prerequisite to trying the better decoder interface.

## A structural reason to decode the relative result

For any finite group G, fixed action a, and arbitrary readout F, right multiplication permutes G, hence

`sum_g (F(g*a)-F(g)) = 0`.

Making F nonlinear does not remove this cancellation. A difference-of-potentials readout cannot provide a strictly positive frame-independent target-versus-competitor boost across the entire action orbit. The current partial data do not establish that all conditions of this obstruction occur; it is a conditional architectural restriction, not a new impossibility result for the saved task.

When q0 is a verified nuisance frame, use the actual relative result `s = inverse(q0)*q1` and learn output from s. **A valid identity result s=e is different from NoRead.** Replacing the old residual by `F(s)-F(e)` would still suppress that legitimate result. Keep validity and learned Read/Emit/Stop decisions as explicit state, preserving the local prior for NoRead while allowing `Emit(identity_result)` to produce a learned token. If q0 carries needed query information, preserve that information separately rather than removing it by fiat.

This is a concrete connection to the retained Hopf/frame work: relative observations support frame-independent relations; retained frame/context and action validity preserve information needed for later computation. No continuous rotation, S7 expansion or runtime matrix multiplication is required for the finite implementation.

`r_bind = relation_for_source_compatibility(query, source)`

`o = learned_operation(observed_query)`

`s = shared_ordered_action(o, r_bind, selected_value)`.

Relevance can be invariant across role families while computation distinguishes their requested operations. This factorization preserves useful source learning rather than forcing its descriptor to perform unrelated jobs.

## Research basis and limits

[Sequential Group Composition, February 2026](https://arxiv.org/html/2602.03655v1) motivates recurrent/hierarchical reuse of finite composition. Its real-valued architecture and learning theory do not certify this learner, and an exponentially sized sufficient construction is not a universal lower bound. [Spectral group-composition learning, July 2026 revision](https://arxiv.org/html/2606.02993v2) supports a finite-group feature hypothesis under restrictive population/dynamics assumptions; held-out language transfer is not proved. A compiled real matrix-coefficient table remains a possible later comparison without online matrix products.

[Compositional structure and generalization, ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/572a6f16ec44f794fb3e0f8a310acbc6-Abstract-Conference.html) and [SCAN](https://proceedings.mlr.press/v80/lake18a.html) motivate new combinations of learned components and explicit shortcut checks. [Softmax bottleneck research](https://arxiv.org/abs/1711.03953) establishes particular probability-factorization limits; it does not prove this finite argmax task impossible. A common monotonic score transform would preserve argmax, so it cannot alone repair wrong emitted tokens. No dense mixture/transformer architecture is adopted.
