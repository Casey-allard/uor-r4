## What the contrast resolves

The unchanged job failure receives `Memory: singer.` but answers `You live in
Lisbon.` Changing selected singer→dancer with Lisbon unchanged still answers
Lisbon. Changing only Lisbon→Oslo produces `Your job is singer.`; with both changes
it answers Oslo. All four user-source BPE-length vectors are identical
`[11,7,9,9,9]`. This is content-dependent source-consumption instability after
verified selection and delivery, not erased input from context truncation.

The unchanged hometown failure receives Klotdradburg but answers Klumklid.
Changing the name distractor to Nourkterk makes it answer Klotdradburg; changing
hometown to Brimfold succeeds with either distractor. Those replacements change
BPE lengths, so this is a bundled content/segmentation intervention. The query
and full original histories are preserved within each group. Comparison groups
are different histories, and the hometown comparison has a different write order;
they are not interchangeable order-matched controls.

Every read-on failure names the incorrect distractor, so these four negatives
are not just an omitted valid paraphrase or failed Stop. The finite complete-answer
criterion remains stricter than semantic relevance: five read-off replies mention
the selected value, including correct facts inside acknowledgements that fail
the frozen answer set. Therefore 0/20 does not mean no selected fact appears or
prove the memory channel is always necessary. Read-off changes earlier replies
as well as the final read; this estimates the whole own-history arm, not the
isolated direct effect of only the current suffix.

The evidence does not uniquely prove that omitted relation/view metadata causes
the defect. Query and history still supply those cues; lexical mixtures, recurrent
state and existing pointer policy can all contribute. It does show that correct
exact-store bytes alone do not ensure correct source-conditioned language.

## Implementation decision

Advance a **learned geometric occurrence reader over the predicted selected
record**, preserving exact `(record,commit,token_offset,token_id)` beside geometric
state. Learn which original BPE occurrence to consume and NoRead/Generate/Copy/Stop
behavior from complete response credit. Relation/view/status come from predicted
typed actions/store results. A prime or record identity is not a semantic metric.
Do not force an evaluator-selected source or an authored answer template.

Reuse native q4 context/group state, directed potential and NoRead/normalization
primitives; the retained synthetic V40 weights are not language-trained weights.
Do not splice a width32 residual into the width288 chat model or reconstruct
exact token IDs through lossy K2 values. A first reference can combine exact-frame
copy mass with the entire unchanged pointer-aware parent distribution, retaining
a disabled-consumer identity control. That would be a native geometric consumer
inside a floating language reference, not complete native chat. All floating
trunk/output/pointer work remains to be replaced under D0-b.

Before a fit, implement the connected actual-BPE forward/backward, source-bound
integer export/reload and measured batch cost. Actual D19 vocabulary 4096 fits the
native ceiling, but directly scaling H2/L4 context adds 8,963,136 coefficients
(~4.27 MiB packed/~42.5 MiB expanded tables); integer arithmetic alone is no laptop
cost advantage. Declare the consumer's 128-position frame/query/response admission
separately from the parent's 384-token history; no silent truncation. Compare with
an ordinary consumer at the same information/candidate access and capacity/cost.

Keep Claude's ladder/reload/CUDA work and DeepSeek's distance/surface-form controls
separate. The diagnostic changed only a new example and its evidence documents;
no shared session, training/corpus or peer-worktree edit. A typed session hook
requires coordination on #1552 before touching `stack_grounded_session.rs`.
