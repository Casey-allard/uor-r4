## What the saved result supports

The relative element `inverse(q)*k` is a real finite group operation, common-left invariant. A static learned per-token descriptor of the preceding token changes the relation score. Exact-only is independently refitted with shared explicit observations. The one-step additive-logit loss and its soft expected-cost gradient are mathematically valid. No direct target label is supplied as an inference feature in the inspected selector.

The saved fresh construction has 120 sequences, 1,638 eligible predictions with `i >= 2`, 940 candidate-bearing positions and 233 covered positions. All 120 final queries are covered. Fit has 200 sequences, 2,700 eligible predictions, 1,451 candidate-bearing positions and 358 covered positions. Fit/fresh share the same 10 role pairs and 24 keys; fresh uses a different 12-token payload bank and new draws. Maximum observed candidate count is five. These are held-out payloads and combinations of known roles, not unseen role-family inference or natural language.

## Corrections that materially affect the conclusion

1. **Categorical train/export/evaluation mismatch.** Training uses `(code[q]*7+code[k]) % 120` ([trainer](../../crates/uor-r4-core/src/native_geometric/learner/relational.rs), lines 368–383). Quantization drops mode/code metadata (599–606), and the runner evaluates every selector using H4 `inverse(root[q])*root[k]` (425–445). The categorical table is read at different addresses from training. Its 0.709 score cannot establish that geometry beats categorical relations. Only geometric receives 18,240 descriptor-search evaluations; a frozen random code with no learning is also not a learned-capacity/dose-matched alternative. Preserve its recorded numbers as a mis-evaluated control, not a valid negative for categorical learning.

2. **A source-class shortcut solves the intended pair relation.** In [make_seq](../../crates/uor-r4-core/src/bin/relational-reader.rs), lines 289–333, every geometric answer role belongs to the paired bank, while all distractor/filler roles belong to the disjoint solo bank. A learned source-only paired-bank preference can solve the geometric final queries without matching the query's partner. Both directions of the pair are equally valid, so this panel also does not identify directional/noncommutative benefit. The final answer always shares the exact query key. Add multiple plausible paired-family sources with the same key and query counterfactuals; do not infer general relationships from a vocabulary-class separation.

3. **Static descriptor and slot-index initialization.** `Q(x_prev)` is a learned lexical-context code, not a learned role of an occurrence in broader context. `init_roots = local.a_codes` copies palette-slot labels as group element IDs; the actual S write element is `palette.elements[a_codes[token]]`. It preserves the old equality partition, not the old geometric write states. Name the initialization accurately. Move to a bounded contextual description only when required observations would otherwise collide.

4. **Positive strength is global.** `s(c,a)=v(c)+sb[a]` implies `argmax_a s(c,a)=argmax_a sb[a]` for every candidate and query ([score/choose](../../crates/uor-r4-core/src/native_geometric/learner/relational.rs), 220–242). Saved `sb` chooses 8 nats in all three fitted arms. NoRead is contextual; nonzero strength is not. This is a valid fitted global amplitude, not context-calibrated strength. A small context/action interaction is a justified candidate if needed for natural-text utility.

5. **Coordinate-search objective mismatch.** Affected positions are concatenated once per role occurrence, including query/source duplicates (trainer 541–567), while the declared objective counts each position once. Search therefore optimizes token-multiplicity-weighted loss locally. Starting `best_loss` at infinity also allows equal-loss moves, so 50 moved roots are not 50 demonstrated useful semantic changes. Deduplicate affected positions, start with the current assignment/loss, accept strict improvements with a named tolerance, and test whole-objective nonincrease and tie retention.

6. **Generation uses an earlier reader decision.** `analyse` requires `i+1 < len` and emits only candidate-bearing positions (354–405). Generation requests the final prefix position but uses `ps.last()` (999–1016), which can refer to an older query; if there is no earlier candidate it stops instead of emitting from the local model. Two saved prompt outputs are empty; four contain 48 tokens. Introduce a target-free current-prefix prediction/read function shared by evaluation, generation and timing, then compute supervised losses outside it. Adding a fake future token is not the repair. Retain and resolve the actual source reference; avoid the runner's synthetic candidate-index references at 408–422.

7. **Control claims remain incomplete.** The independent S check adds the identity row; repair it against the declared retained scorer and its absence behavior. Future intervention compares positions strictly before `cut`, omits the prediction at `cut`, and its `decision_changes` count is not part of `instrument_ok` (876–918, 1070–1076). Source-change output `emitted_the_new_payload=185` actually counts selected payloads, not emitted argmaxes (930–980). Compare score/action/reference/payload and actual emitted output with the shared causal function; retain missing-candidate and NoRead cases in denominators.

8. **Cost is not the claimed baseline.** `run_path` constructs and updates a ring even when `use_reader=false` (1265–1312). It predicts 29 positions but divides by 31 (1048–1058). Correcting only that denominator gives 1,351.03/1,347.04 microseconds for the old local/reader measurements; the contaminated baseline and short unpaired timing do not establish incremental overhead. Serialized 8,844 bytes is not resident memory: the shared precomputed row table alone occupies 1,966,080 bytes. Physical energy remains UNAVAILABLE.

9. **Acceptance rule and units.** The 0.15 precision margin was chosen in DeepSeek's prospective design; the previous principal prompt explicitly discouraged arbitrary high-precision requirements. It is reasonable to prefer actual served predictive loss and useful output, but a new rule applied to already inspected panels is retrospective sensitivity analysis, not fresh qualification. Preserve the old `positive=false` and failed controls. The code checks the lower loss CI bound is negative; a wholly negative interval requires the **upper** bound below zero (1068–1080). The current interval happens to satisfy the correct check. Use paired hard-action loss as the primary utility estimate and keep soft expected loss a separate diagnostic; don't call either a calibrated probability without measuring calibration.

10. **Export and preservation scope.** 940/940 parity reconstructs the relational selector by cloning it and replacing JSON fields, rather than using an independent standalone artifact loader (runner 713–739). Its emitted-output check applies the same action twice (753–761). This cannot detect categorical mode loss or establish all-arm trainer/hard/export parity. Trainer checkpoints do exist; exercise actual disk continuation if that fitter is changed or used resumably. Source/data identity must bind the actual code maps, context observations, table, configuration and fitted inputs. `data_id` currently hashes candidate counts and action costs, omitting role/features/payload identity (runner 626–635).

## Mathematical and architectural synthesis

For a single unsaturated boost, `delta(a)=log(1+p(exp(a)-1))-a*I[correct]` is an exact one-step loss difference. For true selection-conditioned correctness `r`, its expected derivative is `p_a-r`, so a finite approximation to `clip(logit(r)-logit(p),0,A)` is a useful offline reference. The served deterministic action and a soft expectation over actions are different quantities. Multiplying all policy scores by a quantization scale preserves an ideal argmax (before rounding) but changes softmax temperature, another reason to compare actual exported decisions and loss.

For group `G`, `q^-1 k` has exact common-left invariance; it ties scores for pair states related by a common frame action. That is an inductive bias, not evidence that a data generator's labels have that symmetry. Gauge-equivariant learning provides the general frame/feature distinction ([Cohen et al., ICML 2019](https://proceedings.mlr.press/v97/cohen19d.html)). The present symmetric fixed-pair task does not establish the required semantic equivariance. Test useful query dependence first and label H4-specific advantage only against a competent learned alternative.

Recent work reinforces measuring separate mechanisms rather than adopting a physics vocabulary as a model. [Echo, May 2026](https://arxiv.org/abs/2605.06997) studies spectral associative retrieval, but its kernel-ridge/spectral operator is not an already compliant replacement for this integer lookup path. [Memoir, July 2026](https://arxiv.org/abs/2607.20792) reports a fixed-budget learning penalty from coupling memory rewrites to pondering in its task, with parity after longer training; it does not prove that writable reasoning memory is generally bad. [Pointer Sentinel](https://arxiv.org/abs/1609.07843) motivates separating copy access from local emission without importing its dense LSTM implementation. These are external results and research leads, not UOR measurements.

The broader roadmap remains: useful query-conditioned access; role/scope persistence; dependent reads and composition; broader language/executed Rust; qualified scale and complete machine cost. Reuse finite H4/Hopf/spin relations now. Preserve the selected directed relation and exact reference for later query updates. Conditional S7/E8 codebooks or harmonic coefficient banks remain available for a witnessed representation/retention limit. The current failure is not evidence that eight-dimensional geometry is too small: the experiment has not yet distinguished a query relationship from source-class membership. Derived output absent from all sources tests computation as well as retrieval; introduce that separately from the first dependent-read scheduler when its benefit can be attributed.
