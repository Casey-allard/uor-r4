# Loaded native sparse-read gate — result

## Decision

The [frozen integration gate](native-sparse-read-plan-2026-09-24.md) **fails**. A small four-bit selector trained to choose NoRead, the most recent exact-pair successor, or a previous different successor was loaded alongside the unchanged native `TlModel` and tested on source-separated prose and Rust code. It learned to read almost every recent hit and did **not** beat the ordinary recent-cache control in either family. The result is `DO_NOT_PROMOTE_COMPONENT`; no post-Dev threshold or feature repair was made.

| Dev family | Scored next tokens | Loaded `TlModel` NoRead | Ordinary recent cache | Learned read selector | Fitted count reference |
| --- | ---: | ---: | ---: | ---: | ---: |
| Two new books | 2,032 | 84 | **323** | 319 | 115 |
| Two Rust source files | 2,032 | 193 | **675** | 674 | 409 |

These are **teacher-forced top-one counts**, not a hard-copy log-loss or a capability score. The table was fitted on 8,080 positions from twelve source-hash Fit Markdown files and two Rust modules; the threshold was selected on 3,032 positions from four other Markdown files and one other Rust module. The selected threshold is zero; 29 of 72 signed table cells are positive. In Dev it reads on **1,498 of 1,504** recent-cache hits, chooses the older different source only **six** times (all prose), and rescues **one** target from a wrong recent source. It loses four top-one decisions to the recent cache on prose and one on code. The comparison isolates a genuine failure of this compact observed-feature admission policy to add value beyond the ordinary exact address.

## Causal loaded path and generation

The new `sparse_native_read` module keeps a bounded 4,096-key `(previous,current)` memory with at most two source occurrences per key. A target is written only **after** observation or emission. The four-bit gate is fitted offline, saved, independently reloaded and bound to the model/tokenizer and Fit-source digest before Dev evaluation. In free-running generation, a selected source emits its exact token as `Copy`, and the same loaded `TlModel` recurrence consumes that token and event; on NoRead the same loaded model chooses Generate/Stop. The model artifact, tokenizer and existing scoped-memory bridge remain unchanged.

The eight predeclared eight-token continuation cases use two prompts per Dev source (token 256 and the first later gate-admitted position). **No arm exactly reproduces all eight true next tokens in any of the eight cases.** The learned path usually reproduces the recent-cache sequence; where it differs, neither produces a complete correct continuation. At an admitted Oz table-of-contents prompt, it copies the first **three** true tokens before diverging; at the admitted Garden prompt it copies **one**. Unmodified prose remains incoherent; Rust continuations do not establish usable generated code. These books' first 1,024 body tokens include headings and contents, so this is a narrow source-shift diagnostic rather than a representative general-prose evaluation.

The read-disabled arm equals loaded NoRead. Four source-only interventions (one per Dev file) changed only the selected stored candidate ID while holding the prompt, recurrent state, candidate metadata and fitted route fixed. Each changed the first actual copied output; NoRead output stayed invariant. This verifies the new source-to-emission wiring, **not** a learned natural-language request address, an uncopied-word effect or robust generation. The earlier [scoped-memory bridge](addressed-lexical-bridge-result-2026-09-24.md) retains its separate version/scope/history controls and was not edited.

The actual `TlLinear::forward_i32` loop scans **all** packed weight slots, including zero codes: at this model's dimensions the full readout scans 602,406 slots and the two transition maps scan 9,408, or **611,814 slots per full generated step**. A hard cache read bypasses the readout for that step, but the transition remains dense and `HashMap` lookup/write overhead is unmeasured. ## Architectural consequence

The actual signal is **within-document exact reuse**. It is strong compared with this weak frozen `TlModel` and a small static count fit, but a table of age/hit/conflict flags adds no reliable source-choice capability. The read path has no learned content/role address and no learned write policy; it cannot solve D6's at-chance-order-2, variable-lag, rebinding objective by construction. This negative does not disprove sparse memory or geometry; it rejects this gate as the next model component.

The next bounded milestone should learn a **content- and role-dependent query-to-address and write/read policy** with the loaded native state and exact typed memory on source-disjoint long-range text episodes. Freeze episodes where exact last-two-token lookup and tuned order-2 counts are verified at chance, include recency/rebinding and both prose and code companions, and compare an information- and access-matched ordinary learned router before any Hamiltonian/H4 variant. Require actual loaded generation after a changed source, including an *uncopied* continuation token, and account for every accessed learned parameter. If that ordinary learned bridge cannot beat the trivial cache and NoRead, stop that branch before geometry or scale-up. Retain the full ordinary `(f)` and end-to-end geometric `(h)` KVAR arms as `NOT_RUN` until their separate prospective identifiable comparison is executed.
