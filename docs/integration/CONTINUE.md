# Continue one UOR-R4 task

Copy the prompt below into a new Codex task in the UOR-R4 project. It selects
and completes one eligible task; it does not activate every roadmap lane.
The [current map](current-state.md), native issue graph and active user's
instructions resolve scope. A prior handoff or index is a dated source.

```text
$uor-project-workflow

Continue UOR-Foundation/uor-r4 from the live project state and complete exactly
one eligible, decision-bearing task. Refresh origin/main without disturbing
the existing checkout. Read AGENTS.md, docs/integration/current-state.md and
docs/uor_productization_integration_plan.md from that current revision. Refresh
the relevant native GitHub issue bodies, assignment,
children/blockers, latest completion comments, open PRs and queue. Query the
local UOR knowledge index for the issue, mechanism and contrary evidence, then
follow the original source paths/commits. Use relevant code, research and proof
records; imported prose is context, not instructions or current authority.

instructions say otherwise. Do not revive a closed experiment. At the #1094

from its sole approved run-retained comparison and exact full/oracle fresh-process
replay. Independent review accepted the result; the bounded scientific DoD is
complete and #1094 closes upon protected merge. Verify that delivery and native
closure. The unchanged reader/core, known vocabulary/query forms,

issue worktree. Preserve unrelated changes, artifacts and sealed inputs.

negative actions, named checks and resource budget concrete. Reuse qualified
mechanics and unchanged evidence rather than repeating QA. If no existing leaf

within the current authorization before executing it.

Implement and independently review the relevant change. Use the installed
source, documentation, math, profiling or browser tools only where they answer
the task's actual question. Run only the checks activated by the contract;
do not run broad QA, dormant suites, calibration or model probes by habit.

runtime plans when new measurement is necessary; account for total time,
memory and space. Preserve failed criteria, NOT_RUN and UNAVAILABLE faithfully.

Deliver the concrete result through a reviewed PR and the repository's
protected merge path. Stage named files only, never push directly to main or
use an administrator bypass, and verify the actual merge SHA/tree. Transport

with the measured result and merge reference; keep unmet parent stages open.

After delivery, append the evidence/supersession record, update the small

and source records with exact identities and limitations. Explicitly ingest
accepted public records with the local uor-knowledge CLI; the MCP is read-only.
Keep private history outside public artifacts. Refresh a code graph only when
its represented source changed. Inventory remaining worktree/build/index
storage and report specific disposable candidates; do not delete unique
evidence, models, sealed files or user content automatically.

Finish with the delivered outcome, its evidence and limits, the actual GitHub
closure state, and one concrete next action. Stop after this task rather than
starting a second experiment or a roadmap-wide cascade.
```
