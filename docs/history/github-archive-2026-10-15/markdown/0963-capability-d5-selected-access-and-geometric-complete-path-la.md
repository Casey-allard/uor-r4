## Preserved execution-policy text before 2026-09-03 amendment

## Outcome

Make least-cost route evaluation, reuse, storage discipline, and verified four-worker execution mandatory before any long compile, replay, or product run. No run may consume hours merely because completion is assumed to be near.

## Runtime design

- Recalculate only the changed node and affected ancestors in the route hierarchy. Never recompute the full conversation or corpus once exact κ-bound inputs and outputs already exist.
- Deduplicate compiled route, lexical, harmonic, trajectory, spin/torsion, and icosian records by canonical identity. Reuse compatible prior work through an explicit cache/provenance contract; never infer compatibility from digest proximity.
- Select the cheapest declared mathematical substrate only when the representations are canonically equivalent or carry an explicit bounded-loss witness. The project adapters are Euclidean `√2`, complex/discrete `2i`, and Riemannian interval `[0,2]`; they are typed coordinate/scale conventions, not literal equalities between domains. #961 serializes the selected adapter. O1 measures its conversion cost, exactness/error bound, direction/orientation preservation, inverse/fidelity witness, and deterministic selection rule.
- Integer/table lookup, exact Z[φ] coefficient updates, phase/cosine tables, typed tangent phase shifts, R4/S3/Hopf transport, and the icosian store must each publish measured cost and fidelity on the deployed path.
- The icosian path is load-bearing: E8 is represented as the Z-module of quaternions over Z[φ], each block is a golden-coupled R4 pair, and `H4 ⊕ φH4` is the fixed folding. Project shorthand **`E8 = H4 × H4`** names that paired mechanism; the executable form is the icosian golden folding, not a literal Cartesian-product identity or `R4 = E8`. Cache keys bind the basis, scale, shell/orientation, coset/profile, and inverse witness.
- Partition deterministic work by κ across exactly four workers on the target M1. Each worker must receive real independent work; reductions are ordered and byte-deterministic. Worker count is a runtime contract, not a flag that leaves the hot loop serial.
- Publish completed units, total units, throughput, remaining-work estimate, cache-hit rate, worker utilization/imbalance, peak memory, projected disk, and checkpoint identity while a run is active.

## Long-run hard gate

Before any expected run over 15 minutes:

1. write the metric, reachability ceiling, smallest cheap instrument, positive/negative decisions, wall-time estimate, disk ceiling, and stop rule;
2. compile/profile the release binary for the target architecture;
3. demonstrate reuse and four-worker activity on the smallest representative slice;
4. prove resumable checkpoints and bounded temporary storage.

A run with predicted wall time over eight hours does not launch. A live run that reaches eight hours stops at a recoverable checkpoint; elapsed time is never evidence that it is almost finished. Re-estimation requires measured remaining units, not intuition.

## Identity and serving boundary

κ is canonical identity and serialization integrity; it is not the tokenizer. The lexical codec owns segmentation. Source weights are offline-teacher-only. Serving has no transformer, MoE, dense-matmul, source-attention, Ollama, cloud-provider, or equivalent fallback.

Routine testing is dormant. O1 authorizes only the smallest decision-bearing performance probe below until the route mechanism is stable.

## Blockers and order

- **Future stage; unassigned.**
- The long-run gate above applies immediately to every programme stage.
- Full O1 implementation is blocked by #955 and #962 so it optimizes the measured final route-native product path rather than a disposable prototype.
- O1 blocks #964 (formal serving contract) and #965 (release QA); references will be updated if GitHub assigns different issue numbers.

## Smallest decision-bearing probe

Use one fixed, representative shard that completes in minutes. Compare one worker with four workers using the same release binary and warm/cold cache cases. Require:

- byte-identical artifacts and κ values;
- nonzero useful work on all four workers;
- measured elapsed/CPU/disk/peak-memory figures;
- cache reuse that skips previously completed route nodes;
- a predeclared speedup floor derived from the measured serial fraction.

If four workers do not clear that floor or outputs drift, profile and redesign; do not launch the full run.

## Definition of done

- The serving and compile hot paths have bounded cost models.
- Node-local invalidation and exact reuse are implemented and traced.
- Four-worker scaling and deterministic reduction are evidenced on the M1.
- Checkpoint/resume preserves canonical output identity.
- A runtime watchdog enforces disk and eight-hour stop policies.
- No claimed optimization is accepted without a matched baseline on the deployed path.
