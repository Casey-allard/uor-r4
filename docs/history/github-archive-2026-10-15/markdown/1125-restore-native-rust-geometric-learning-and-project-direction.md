## Body

The project had drifted toward Python reference fitting, delayed Rust lowering and experiment-specific stage/retry limits. This change restores one native Rust geometric model path and one authoritative development plan, then exercises that path with actual training, decoded output, persistent sessions and recorded negative results.

References #973. Also advances the programme tracked by #820; neither issue is closed by this recovery checkpoint.

## Changes

- Add Rust preparation, count construction, separate learned readout and bounded query-relative memory-read operators, versioned artifacts, resumable training, development evaluation and generation. The CLI, library API and loopback workbench use the same model and session implementation.
- Use prime lexical/ordered-context addresses, fixed zeta channels, ordered H4 state, exact signed Z[phi] paired coefficients and accumulated radial state in the computation. Reuse the existing typed icosian bridge and canonical UOR address APIs. The paired representation remains a reversible view of one H4 carrier, not independent H4 factors or an E8 isometry.
- Fit learned readout/read weights separately from count construction, preserve fixed baseline artifacts, and refuse development IDs or exact text that overlap fitting data. The serving kernel uses bounded integer/table operations; Rust training may use matrix operations.
- Support configurable context and resource windows, checkpointed continuation and explicit resource reports. Exercise load/generate/cancel/export/import/restore, session isolation, bounded output and storage admission. Closed sessions retain their memory reservation until every live reference releases their buffers.
- Reconcile AGENTS, policy, roadmaps, workflow skill and documentation entry points around Rust throughout, all seven primary mechanism roles, and both conversation/memory and coding/reasoning alpha goals. Preserve old evidence and scope its frozen instructions to those experiments.
- Replace policy-only automatic queue acknowledgements with formatting and focused native policy/model/context/allocation/CLI-service checks in the first required status. The other four statuses explicitly remain compatibility acknowledgements. Protected delivery and the manually dispatched legacy release jobs remain intact.

## Evidence and limitations

The recovery record in `docs/native_geometric_recovery_973.md` and its machine-readable evidence identify the actual artifacts, data, controls, resources and executed checks. Focused verification passes 14 native core tests, 12 CLI/service tests, two runtime checks and one existing version-contract test. These cover the tested arithmetic/state, artifact and checkpoint reload, split isolation, interface and kernel boundaries. The learned bounded memory reader is implemented on the same artifact/session path, with deterministic write admission. `docs/integration/current-state.md` and the recovery record retain the exact executed scope; passing focused checks is not broader memory qualification.

The initial matched 32/128/512-token runs show why capacity and useful memory must be measured separately: larger windows retain more supplied values, while the readout-only model fails to change its answer under paired value changes. Larger native training and readout runs complete locally and improve open-development next-piece accuracy, but geometric gates often suppress geometric contributions. Browser output is real and repetitive; tested Rust continuations fail actual compilation. These negatives remain preserved as the learned operator evolves.

The completed exact-cue controlled prose experiment demonstrates query-dependent retained-value reading at its declared window and task scope. Zeta removal can improve that result, so it does not establish blanket geometric advantage. The initial joint prose/Rust fit yields no gain; longer joint fitting improves prose but remains below the coding control. Word-cue equivalence stays an explicit opt-in after regressions and mixed outcomes, preserving the exact-cue default. An aggregate improvement cannot stand in for both conversation/memory and coding/reasoning.

The general-corpus memory head reduces open-development next-piece accuracy from 36.2485% with the reader disabled to 33.2663%. A larger feature-capacity run learns 77,773 features with zero dropped features but still yields 32.7638%. These are preserved model-quality regressions, not a reason to describe capacity or focused tests as useful language competence. Exact artifact, data, fit-dose and control details remain in the recovery record.

This is a native implementation and measured-development checkpoint, **not alpha**. Useful conversation, fact updates, contradiction handling, abstention, multi-step reasoning, workspace-based code repair, learned write behavior, complete typed lineage and broader release qualification remain work under the canonical plan. All seven geometric roles remain primary even where an implemented operator has not yet made them useful. Focused source/allocation checks do not constitute machine-code or whole-executable certification.
